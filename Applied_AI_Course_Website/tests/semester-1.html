Semester 1 examination

Two hours · 100 points · Attempt without notes or an LLM.

Question 1 Attention and architecture 20 points

For B=2,T=128,D=256,H=8 with standard multi-head attention: give Q/K/V, score, per-head output and merged output shapes (8). Calculate explicitly stored float32 score memory across all heads/batches in bytes and MiB (4). Explain the causal perturbation test (4). Explain why improved training loss after removing the mask is not evidence of a better model (4).

Question 2 Training and resources 15 points

For a hypothetical 300-million-parameter model, estimate parameter-state memory under a stated 16-byte/parameter training configuration, excluding activations (5). Contrast with 2-byte inference weights (3). Name four other memory sources/qualifications (4). Explain why accumulation cannot solve all OOMs (3).

Question 3 Retrieval calculations 20 points

Gold evidence is {P,Q}. Lexical ranking is [R,P,S,Q]; dense ranking is [Q,T,P,R]. Compute Recall@3, Hit@3 and reciprocal rank for each (8). With RRF c=0, compute fused scores for P,Q,R and rank those three (6). Explain why c=0 is more top-heavy than c=60 and why these scores are not probabilities (3). Name a fair evaluation control (3).

Question 4 RAG debugging 20 points

An assistant answers a v2 timeout question with a v1 value, cites a real v1 page, and reports valid JSON. The vector database contains both versions. Give four plausible causes at distinct pipeline stages (8), one discriminating check per cause (8), and explain why a stricter JSON schema is insufficient (4).

Question 5 Experimental design 15 points

You have 120 labeled documentation questions and a candidate hybrid retriever. Design train/dev/test use and group handling (5), retrieval/answer/resource metrics (5), and a paired uncertainty/error-analysis procedure (5). Explain how indexed documents may remain available without exposing held-out labels.

Question 6 Delivery judgment 10 points

A candidate improves 5 percentage points overall, introduces wrong-version answers, and has incomplete source hashes. Give a release decision with stated gates (4), minimum repair/evaluation steps (4), and one honest portfolio claim (2).

Q1 (20). Q/K/V=[2,8,128,32]; scores=[2,8,128,128]; per-head output=[2,8,128,32]; merged=[2,128,256] (8). Score elements=262144; float32 bytes=1,048,576=1 MiB (4). Perturb a future input with fixed model/eval mode; earlier outputs must remain equal within tolerance (4). Without masking, a target's future token can leak, making training easier while violating autoregressive conditioning (4).

Q2 (15). 300,000,000×16=4.8 billion bytes=4.8 GB decimal, about 4.47 GiB (5). Inference weights at 2 bytes=600 MB decimal, about .559 GiB (3). Additional memory: activations, temporaries, allocator reserve, KV cache for inference, precision-specific states or implementation differences; four justified items (4). Accumulation lowers microbatch needs, not a single sequence's minimum footprint or all persistent state (3).

Q3 (20). Lexical first three [R,P,S]: recall=.5,hit=1,RR=.5. Dense [Q,T,P]: recall=1,hit=1,RR=1 (8). c=0: P=1/2+1/3=5/6; Q=1/4+1=5/4; R=1+1/4=5/4. Q and R tie, both above P (6). c=0 weights rank one much more strongly; c=60 smooths rank differences. Fusion scores are rank-derived, uncalibrated scores (3). Same documents/chunks/tasks/filters/k and tuning/evaluation protocol; any justified control (3).

Q4 (20). Possible causes: source mislabeled v2; retrieval omitted/misapplied filter; context packer mixed versions; generator ignored correct labels or citation validator checked only existence. Four distinct causes earn 8. Checks: inspect source manifest/text; execute raw filtered search; save exact packed context; inspect generated claims/citations against supplied evidence. One discriminating check each earns 8. JSON ensures structure, not version correctness or semantic support (4).

Q5 (15). One defensible split: 60 dev/tuning, 30 validation/checkpoint, 30 final test with source/task families grouped; if no model training occurs, no artificial training partition is required. If adapting, reserve an actual train subset and separate dev/test. Keep test labels/questions out of tuning; corpus remains the permitted reference knowledge (5). Retrieval recall/RR, answer facts/grounding/refusal, version errors, latency/tokens/failures and slices (5). Save paired per-task outputs, bootstrap paired differences with assumptions and inspect corrected/new errors; recognize small/correlated test limitations (5). Specific split numbers are not required if justified.

Q6 (10). Reject under zero-cross-version and reproducibility gates (4). Fix/filter labels, complete hashes/manifest, rebuild affected artifacts, rerun invariant suite and planned eval without pretending an already-inspected test is untouched (4). Honest claim: independently built and evaluated a documentation RAG prototype, with actual measured numbers only; no invented production usage (2).
