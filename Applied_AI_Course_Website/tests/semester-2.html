Semester 2 examination

Two hours · 100 points · Attempt without notes or an LLM.

Question 1 Adaptation 20 points

For W shaped [2048,4096] and LoRA rank 16, give A/B shapes and parameter counts, dense count and adapter/dense ratio (8). Explain zero-update initialization (4). Contrast LoRA and QLoRA without assuming four-bit activations (4). Name saved dependencies for adapter reproduction (4).

Question 2 Fine-tuning study 15 points

A new adapter improves exact tool JSON from 75% to 95% but increases incorrect tool arguments from 5% to 20%. Design a controlled evaluation and release decision (8), identify two possible dataset causes (4), and explain why training loss alone cannot resolve the question (3).

Question 3 Agent controller 20 points

Write pseudocode for a bounded model/tool loop with typed proposals, schema checks, scope checks, observations and terminal statuses (12). Explain why a step cap is not a call timeout (4). Explain how an invented but valid-looking citation must be handled and what checking its ID cannot establish (4).

Question 4 MLOps and security 20 points

After changing the embedding model, developers reuse the old vectors and omit tenant scope from answer-cache keys. Explain both failures (6), propose manifest/index migration and cache controls (8), and define regression tests and rollback unit (6).

Question 5 Performance and scaling 15 points

Average arrival rate is 1.5 requests/s and average time in system is 4 s. Estimate average work in flight and state assumptions (4). Distinguish TTFT and end-to-end latency (3). Calculate ideal four-way speedup for 80% scalable and 20% serial work (4). Explain why this does not predict production p95 or communication cost (4).

Question 6 Capstone defense 10 points

Your agent is more expensive than the fixed workflow, your adapter shows no reliable improvement, and your retriever measurably improves paraphrase questions. Choose a default release and justify it with the evidence you would present (6). Name two limitations and a focused next experiment (4).

Q1 (20). A=[16,4096], B=[2048,16]. Adapter=16×(4096+2048)=98,304; dense=2048×4096=8,388,608; ratio=.01171875=1.171875% (8). One random factor/one zero factor yields zero initial delta while allowing gradient flow; both zero can block initial factor learning (4). LoRA trains factors on frozen base; QLoRA additionally quantizes frozen base, retaining higher-precision compute/state where required (4). Base/tokenizer revision, adapter config/weights, target modules, environment, training data/config and eval metadata; four distinct dependencies (4).

Q2 (15). Same model/base/context/tasks/decoding/tool validator, separate prompt control, per-task valid JSON and semantic argument correctness, invalid/forbidden actions and budgets; reject if incorrect actions violate gate even though syntax improved (8). Dataset may reward valid format with wrong arguments, omit negative/refusal cases, include wrong-version labels or have leaked paraphrases; two diagnosed causes (4). Loss is fit to labels, and biased/wrong labels can be learned successfully (3).

Q3 (20). Initialize scope/state/budgets; for finite steps call planner with controlled context; parse and validate proposal; final validates citations/contract then terminates; tool action validates name/schema/authority/limits, executes with per-call enforcement, records normalized result; catches typed failures; exhausts explicitly. Six meaningful controls/branches at 2 points each (12). A blocking call can exceed wall time before loop checks; real client timeout/process enforcement needed (4). Reject IDs not authorized/observed; existing IDs still do not prove semantic entailment (4).

Q4 (20). Incompatible coordinate systems make old vectors unsuitable; missing tenant cache scope can expose restricted answers (6). Manifest embeds model/index/source compatibility, rebuild versioned index, benchmark/switch/rollback; scope-aware cache keys, permission enforcement and invalidation (8). Tests deliberately mismatch embedding manifest and cross tenant requests; roll back coherent prompt/model/adapter/index/tool/corpus config, not weights alone (6).

Q5 (15). L=1.5×4=6 average in system, assuming stable averages and correct boundary (4). TTFT until first output token; end-to-end until response finishes including all application stages (3). 1/(.2+.8/4)=2.5 ideal speedup (4). Tail latency depends on variance/load/queueing and distributed work has communication/coordination; no p95 prediction from these means (4).

Q6 (10). Prefer qualifying retriever plus fixed workflow/base generator if agent/adapter add no demonstrated value; retain experimental branches and raw comparisons, report budget/quality/safety and actual negative results (6). Limits could be task-set size, small model capability, lack of real users or untested high concurrency. Next experiment must target an observed failure with a control and metric, e.g. reranking the paraphrase misses under a fixed context budget (4).
