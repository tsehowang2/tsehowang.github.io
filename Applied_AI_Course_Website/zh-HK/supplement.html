詳解補充材料

這些例子深化部分機制，但不增加必修學習時數。可用來代替選讀，或在訂正測驗時參考。所有數字均為示範計算。

手算 Byte pair encoding

由極小 corpus 開始：low、low、lower。先使用 character 和 end-of-word marker：l o w _、l o w _、l o w e r _。統計整個 corpus 的相鄰 pair。(l,o) 和 (o,w) 各出現三次，(w,_) 出現兩次。選定 deterministic tie rule，把 (l,o) merge 成 lo，再重新計數。(lo,w) 出現三次，因此 merge 成 low。所得 vocabulary 現在包含從計數學到的常見片段。真正 byte-level BPE 由 byte vocabulary 開始，並有額外實作細節。

Encode 新字時，套用已學到的 merge rule，而非在該字上重新 fit rule。在某個 corpus 訓練的 tokenizer，可能把不熟悉的 identifier 拆成很多片段。Training 與 serving 的 tokenization 必須相符。改變 merge vocabulary 會改變 model 對 input／output ID 的解讀，而不只是 chunk 長度。

練習： 加入兩次 lowest，重複三個 merge 步驟，並解釋哪些 count 改變了。不要把 merge 的出現頻率當作 semantic importance。

Softmax 穩定性與 cross entropy

對 logit z，先減去 max(z) 才 exponentiate：exp(z_i−m)/sum_j exp(z_j−m)。因為共同 factor 抵消，probability 保持不變，同時降低 overflow 風險。對 logit (1000,999)，直接 exponentiate 可能 overflow；平移後的 logit (0,−1) 得出約 (.7311,.2689)。

Target 為第二類時，cross entropy 是 −log(.2689)≈1.3133 nats。計算 log-softmax 或 fused cross-entropy，一般比先形成很小 probability 再手動取 log 更具 numerical stability。Train data 上接近零的 loss，仍可能反映 memorization 或 leakage。

Residual 與 normalization

Layer normalization 先減去每個 token 的 feature mean，再除以 feature variance 加 epsilon 的平方根，然後套用學到的 affine parameter。RMS normalization 在基本形式中以 root-mean-square 統計量縮放，不會減去 mean。在這個設定下，兩者都是逐 token 的 feature 操作，不會混入未來位置。Residual addition 需要相容 shape。

在 pre-norm block，normalization 發生在 attention／MLP transformation 前，residual stream 仍是一條相加路徑。Post-norm 則是在相加後 normalize。這些是有意義的 architecture 差異；教學實作明確選用其中一種，並不聲稱它是唯一 transformer 設計。

Rotary position 的直覺

對二維 component pair，以 theta 角旋轉，會把 (x1,x2) 映射到 (x1 cos theta−x2 sin theta, x1 sin theta+x2 cos theta)。對 query／key 的 component pair 套用隨位置改變的旋轉，可令 dot product 取決於相對位移。不同 pair 使用不同 frequency。這種構造解釋一種 encode 位置的方法，並不能證明可無限 extrapolate 到 long context。

練習： 把 (1,0) 分別旋轉零度和 pi/2，計算 dot product。再把兩個 vector 同時旋轉相同角度：相對 dot product 不變。把這種 invariance 連結到 relative position。

Query、key 和 value 的 head 數目

標準 multi-head attention 使用相同數目的 query head 和 KV head。Multi-query attention 讓多個 query head 共用一個 KV head；grouped-query attention 使用介乎兩者之間的數目。Cache 儲存量隨 KV head 數目增加，而非只看 query head。因此，model 可以有很多 query head，卻不必為每個 head 分別儲存 cached key／value。

使用 memory formula 前，先核對實際 architecture configuration。Learned projections、head dimensions 和 layer 數量都影響估算。第 22 週的 96 MiB 例子假設指定 KV count、batch、precision 和 context length。

KV-cache 正確性

在 generation step t，可以重用較早位置的 causal key／value state。Cache identity 必須包含實際前置 token 及相關 model configuration。改變 system prompt、model weight 或 token prefix 後仍重用 cache，會算出錯誤結果。Server 上的 prefix caching 需要正確處理 identity 及 authorization，尤其 prompt 可能包含私人內容。

Caching 加快重複計算，但不會改善證據品質。較長 cached context 仍佔用 memory。Batching 和 eviction policy 會改變 throughput 和 tail latency。

Sampling 計算例子

假設 next-token probability 為 (.50,.30,.15,.05)。使用 top-p=.8，並約定保留跨過／達到 threshold 的 token，便保留首兩個 token，再 renormalize 成 (.625,.375)。使用 top-k=3，保留首三個並除以 .95 來 renormalize。不同實作的邊界約定可能不同，請檢查所選 library，不要假設有通用 tie rule。

Sample 多個 candidate 會倍增 generation 工作量。如果五個 candidate 各使用 100 個 output token，則在 judging 或 verification 前，generation budget 已是 500 個 output token。報告時全部都要計算。

把技術文件頁面分 chunk

假設一頁包含 heading、定義 timeout_ms 的段落、code block、例外註解及版本變更表。Fixed-length splitter 可能把例外與規則分開，或把 code block 切成兩半。Structure-aware splitter 先尊重 heading 及 code／table 邊界，再用 source offset 分割過長 section。儲存 parent ID、section path、version、offset 及 content hash。

Overlap 是需要評估的 parameter，不應一味加大。過多 overlap 會重複證據並增加 index 儲存量。把 chunk size 與 embedding tokenizer 的 input limit 和 generator context budget 比較。如果有用文字在 embedding 期間被截斷，evidence recall 的改善可能消失。

逐 claim 審核 citation

答案：「Version 2 defaults to 30000 ms and permits unlimited retries [timeout-v2].」第一個 claim 獲 timeout-v2 支持；第二個沒有支持，並與 retry／config 證據衝突。Source ID 存在、JSON 可以有效、第一句也可以正確，但整個答案仍不值得信賴。

手動審核時，把事實陳述分成 clause，找出支持段落，標記 supported、contradicted 或 not established。另行追蹤不完整答案：即使全部陳述有證據，仍可能漏掉必要 caveat。在專題中，對已審核 subset 逐 claim 評分，並列明 sample size。不要把每個附有貌似合理 citation 的回應都標為「grounded」。

Calibration 與 selective prediction

Cosine score .82 並不等於 82% 正確 probability。要使用 threshold，請在指定 corpus／model distribution 下以 development example 選定。用圖或表呈現「回答更多問題」與「產生更多無證據答案」之間的取捨。保留 held-out check 驗證所選 threshold。

如果已回答的 10 題有 9 題正確，selective accuracy 是 90%。但若 100 個相關 task 只回答了 10 個，coverage 是 10%。兩個數字同樣重要。Abstention policy 亦須分辨真正缺乏資料，還是 retrieval 失敗。

Quantization 與資源估算

理想 four-bit representation 每個 weight 使用 .5 byte，但實際 quantized layer 還需要 scale、metadata 及相容 kernel。部分 tensor 保持較高 precision。Activation memory 和 KV cache 須分開計算。單以 parameter 數乘 .5 看似能放入的 model，仍可能 OOM。

Quantization 可能改變輸出，所以 deployment 前要比較實際 task 行為。若 device 沒有適合該 representation 的高效 kernel，檔案較小不代表 latency 較低。

Tool 結果的 semantics

呼叫 validate_config({timeout_ms:0,retries:3}) 可以是合法的 validator invocation，同時回傳 valid=false。這與 tool-call schema 因含有意料之外的 command field 而無效不同。Error taxonomy 應區分 proposal parsing、argument schema、authorization、tool execution、domain-invalid result 及 final-answer correctness。

同樣，agent 的 completed status 只代表 controller 接受了最終回應。Task checker 仍要核實要求的計算或 validation 確曾發生，而且回應與結果相符。Controller acceptance 和 task success 是不同 metric。

閱讀 paper 的習慣

花十分鐘看問題、task setup 和主要 claim；十分鐘畫出機制並追蹤一條 equation 的 shape；再十分鐘檢查 evaluation control 及一項限制。寫下一個可在較小系統測試的 prediction。若該問題需要，日後才讀完整篇 paper。選讀 Stanford 或 Hung-yi Lee 材料時，用這方法把資料連結到當前 lab，而不是累積沒有觀看的 lecture。
