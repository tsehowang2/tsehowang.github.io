環境設定與運算計劃

先閱讀這部分

網站使用 static HTML、CSS 和 JavaScript。閱讀、slides、搜尋、解答、圖解和進度記錄均不需要安裝 Python 或付費服務。程式碼另外在你的電腦或 Colab 執行。

選擇受支援的 Python environment

建立新的課程 environment 時，先選 Python 3.12 或 3.13，並使用 virtual environment。若某個 dependency 有需要，Python 3.11 仍是受支援的後備選項。Python 3.10 已於 2026 年 10 月 1 日結束支援，因此不再建議用於新安裝 [ Python version status (R31) ]。

現時 PyTorch 安裝文件支援 Python 3.14。選用前，應檢查該 lab 使用的 NumPy、Transformers、Sentence Transformers、PEFT、Qdrant，以及 accelerator packages 是否都有相容版本。Python 3.15 是較新的 Python release，但 language release 本身並不能證明整個 machine-learning environment 已相容 [ Python version status (R31) , PyTorch installation selector (R32) ]。

數值課節需要 NumPy。使用 PyTorch 安裝選擇器，選擇你的 operating system 及 CPU 或 CUDA runtime；安裝後先執行小型 tensor operation，使用 GPU 時亦檢查 torch.cuda.is_available()。成功 import 是第一個 environment check，lab 結果則是另一項檢查。Colab 一般已有 NumPy 和 PyTorch，但仍應記錄該 session 的版本 [ PyTorch installation selector (R32) ]。

先解壓完整課程 ZIP。根目錄包含 coursekit、data、notebooks 和 tests。在根目錄執行 python -m unittest discover -s tests -v。在 Colab 上載 ZIP，解壓至 /content/llm_course，再執行 bootstrap cell；該 cell 亦會尋找已解壓的 llm_course_v2 folder。單獨的 notebook 仍需要相應 support files。

英文與香港中文例子的 models

預設的雙語 retrieval route 使用 intfloat/multilingual-e5-small，輸出 384-dimensional vectors，input limit 是 512 tokens。Retrieval 問題加上「query: 」prefix，passage 加上「passage: 」prefix，中文亦一樣；之後 normalize embeddings，以 cosine 或等價的 dot-product 排名。這些 prefixes 屬於這個 model，並非每個 embedding model 的共同規則。你的 evaluation 應包含英文、繁體中文及跨語言的 question-passage pairs [ Multilingual E5 small model card (R33) ]。

小型 generator route 使用 Qwen/Qwen3-0.6B，以及固定 Transformers4.56.2/PyTorch2.8.0 recipe。一般答案及 JSON-tool exercises，在 apply_chat_template 設 enable_thinking=False。透過公開 API resolve revision，tokenizer 和 weights 使用同一 revision。Run record 記錄 model ID、revision 和 template settings [ Qwen3 0.6B model card (R34) ]。

Model route 用途與限制
intfloat/multilingual-e5-small 雙語 retrieval 預設選項；384 dimensions；最多 512 input tokens；使用 model-specific query 和 passage prefixes。
Qwen/Qwen3-0.6B 小型 generator；一般 tool 和答案 route 明確使用 non-thinking mode。
sentence-transformers/all-MiniLM-L6-v2 舊版 English baseline；384 dimensions；預設會截斷超過 256 word pieces 的 input。
Qwen/Qwen2.5-0.5B-Instruct 保留的舊版小型 generator baseline，用於重現早期課程 runs。

舊 models 仍是有用的對照；年份較早並不會令 baseline 自動失效。這裏明確標示其用途，避免雙語實驗不小心只使用 English embedding model。更換 model 一般需要重新建立 embeddings、相容的 index 及新的 evaluation，並非只替換檔名 [ MiniLM L6 legacy English model card (R22) , Qwen2.5 0.5B Instruct legacy model card (R23) , Multilingual E5 small model card (R33) , Qwen3 0.6B model card (R34) ]。

按可用 hardware 選擇 lab route

手算核對、metric arithmetic、小型 vector search 和 controller tests 都可使用 CPU。Model inference 先用短 input、小型 output limit 和一個 request。約 4 GiB VRAM 的入門 GPU 或可執行短 context 的小型 model inference；VRAM 較多的免費 cloud GPU 則可支援較大的實驗。這些是規劃 route，並非 memory 保證；應量度實際 configuration 使用的 model、cache、activations 及 temporary allocations。

免費 Colab 的 GPU 供應會改變。以 nvidia-smi 檢查分配到的 device 和可用 VRAM，並把 checkpoints 和 reports 另存至 temporary runtime 以外的位置。選擇受支援的 dtype：float32 適合先在 CPU 核對正確性；float16、bfloat16 及 quantized kernels 則視乎 hardware 和 software。第 23 週的 CUDA compilation 需要 nvcc；若沒有，先完成數值及 code-reading 部分，並記錄這項 runtime 限制。

FlashAttention 版本與 generative-model 參考

原始 FlashAttention paper 解釋 IO-aware exact attention。FlashAttention-2 改善 work partitioning 和 parallelism；FlashAttention-3 針對 Hopper execution，包括 asynchronous scheduling 及 low-precision paths。它們是相關的 implementation generations，而不是不同的 probability 定義。考慮安裝前，先讀第 22–23 週的 algorithm 圖解 [ Dao et al. FlashAttention (R26) , Dao FlashAttention-2 (R35) , Shah et al. FlashAttention-3 (R36) ]。

Kernel support 與 hardware 有關。標準 CUDA FlashAttention-2 route 針對 Ampere、Ada 和 Hopper GPUs；FlashAttention-3 則針對 H100/H800 等 Hopper GPUs。官方 implementation 列出現時 requirements 及更新 kernels。本課程不要求安裝 FlashAttention package 才能學習或測試普通 attention；使用 environment 內受支援的 backend 即可 [ Official FlashAttention implementation (R37) ]。

DDPM 是 diffusion 的基礎描述，並非對現時 model 的推薦。第 15 週把它連繫至 learned reverse denoising、latent diffusion 和 flow matching，讓 forward-noising formula 不會被當成完整 generation process [ Ho et al. Denoising Diffusion Probabilistic Models (R21) , Rombach et al. Latent Diffusion Models (R38) , Lipman et al. Flow Matching (R39) ]。

重現實際執行的 environment

Notebook 中的 package ranges 是初始 constraints，並非 lockfiles。尤其 Qwen3 route 需要較新的 Transformers lower bound；要重現舊 run 時，仍可能需要先前儲存的 environment。記錄實際安裝的 Python、torch、transformers、sentence-transformers、PEFT 和 accelerator 版本、model／tokenizer commits、data hashes、seeds 及 configuration。所選 lab 成功執行後，再儲存 lockfile。

課程附帶的 source 和數值檢查，與 model-download、GPU-training 及 kernel checks 是不同的驗證。Model card 或成功的 syntax check，並不代表完整 workload 已在你的 device 執行。每份 report 都應附上 execution status。

輸出

Bootstrap 會建立 runs directory。使用 run IDs 並保留實際 outputs。虛構教學 fixtures 刻意維持小型規模，因此應把它們報告為教學例子，而非 production benchmarks。

按學習階段閱讀

先閱讀課程內的解說和計算例子。概念出現位置的 source links，可讓你查閱原始定義或具體 software behavior。Research papers 和完整外部課程都是參考，並非額外 assignments。

第 1–5 週使用講義及 tokenization／model-card 例子；第 6–11 週把 attention 和 architecture 連繫至原始 transformer 及現代 variants。第 12–16 週連繫 training、chat templates、reasoning 和 generative families。第 17–21 週使用 retrieval、embedding 和 evaluation 文件；第 22–23 週使用 memory、kernels 和 profiling sources；第 24–26 週使用 adaptation 和 preference-learning sources；第 27–32 週使用 tool、protocol、serving、safety 和 lifecycle 文件。按課節指定部分閱讀即可，不需要把所有 sources 全部讀完。

歷史基礎與現時工具

基礎 paper 不會只因出版年份較早而過時。Attention、diffusion 和 low-rank adaptation 保留原始定義；安裝工具時則使用現時 implementation 文件。舊 model 是重現結果的對照；修訂後的 model labs 建議先使用 multilingual embedding 及較新的 small-generator routes。

關於本課程

獨立原創自學材料，與 Stanford 或 NTU 並無隸屬關係，也不提供其證書。教學方法結合直覺講解、機制、實作及受控實驗。導師公開材料的連結屬可選參考，並非複製其 lecture 內容。

驗證與限制

全部32 notebooks 和 companion scripts 通過 syntax checks；28條 CPU-safe paths、第26週 DPO/distillation、第28週 invalid-JSON checks，以及25個 support tests 均通過。Optional model-download blocks 關閉；reference outputs 清楚標示為比較資料。Memory widget 的 batch/token 行為以 DOM test double 驗證；未有 visual browser verification。

本次環境並未執行 model downloads、實際 transformer／adapter training、Qdrant model execution、CUDA compilation／profiling、production serving 或實際 model-agent runs。更新的 recipes 已通過 syntax checks；使用練習 runtime 時，仍需確認 hardware、package 和 model compatibility。Fixture results 和手算會與 trained-model measurements 分開標示。發佈的 notebook outputs 保持空白。
