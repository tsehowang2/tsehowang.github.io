RRF

RRF 是 reciprocal rank fusion：按 reciprocal ranks 合併有序 result lists，而非直接相加不同尺度的 raw scores。

基本 pipeline 讓失敗變得可觀察

假設手冊 assistant 能回答直接問題，卻漏掉 “At what time can pupils board the morning transport?”。Relevant passage 用的是 bus leaves。另一種失敗，是引用了正確時間，卻來自錯誤年份。

這是不同問題。Semantic retrieval 可能有助處理 paraphrase；必需的 version filtering 則處理 scope。再精巧的 prompt，也不能可靠修復一筆標錯資料的 source record。

每次修改都先從已觀察的 error 出發，提出失敗發生在哪個 boundary 的 hypothesis。這能讓改善緊扣任務，而不是追逐流行 component 清單。

結合 lexical 和 dense candidate

Lexical search 擅長處理精確名稱；dense search 可以處理部分 paraphrase。Hybrid retrieval 結合兩者的 candidate。

不同 score 可能採用不同 scale。未經 calibration，就把 BM25 score 直接加到 cosine score，會令意義變得難以預測。Rank fusion 改為結合排序資訊。

Reciprocal rank fusion 把各 candidate list 的 1/(c+rank) 相加。某 item 若不在其中一個 list，該 list 的貢獻就是 0。常數 c 控制最前排名的主導程度。

Fusion 的計算比較

Passage A 在 lexical search 排第 1，在 dense search 排第 10。Passage B 在兩者都排第 2。當 c=60，A 的 score 是 1/61+1/70≈0.030679，B 則是 2/62≈0.032258。

這次比較 B 勝出，因為兩個 list 都一致給它較好排名。這些值是由 rank 推導的 score，並非經 calibration 的正確 probability。

改變 c 會改變 weighting。應比較最後 candidate set 和 downstream task result，而不是只看某個人為設計例子裏，哪段 passage 勝出。

Reranking 對選定 pair 投入更多運算

Cross-encoder 可以同時讀取 question 和每段 candidate passage，估計 relevance。與可 cache 的 bi-encoder vector 不同，這些運算針對每個 query-passage pair 執行。

先對足夠廣的 candidate pool 做 reranking，再選出較小 evidence set。如果必需 evidence 從未進入 pool，reranker 也無法補回來。

Reranking 前量度 candidate recall，之後量度 answer quality。這種分開量度，能告訴你失敗出在找 evidence、排序，還是使用 evidence。

排名之後建立 context

把高度重疊的 chunk 去重、保留 source label，並納入需要的 exception。細小 retrieved chunk 可以指向較大的 parent section，以提供連貫 context。

兩個 version 的比較需要 version diversity；精確的 single-version 問題則需要指定 scope。Selection 取決於任務，並非一律「maximize diversity」。

按實際 token budget packing，並預留 output 空間。記錄 selected source ID 和完整 packed prompt，讓 error 可以重現。

Query rewriting 與多步 retrieval

像 “Does that apply next year?” 這類對話問題，可能需要 reference resolution。Rewrite 可以明確指出目標年份和主題。

Rewriting 也可能引入 unsupported assumption。保留 original question、記錄 transformation，並獨立維持 scope/authorization constraint。

當任務需要時，多個 retrieval step 很有用，但會增加 latency 和 failure path。要在明確 resource budget 下，與 single-step baseline 比較。

一個受控實驗

固定 corpus、chunk、question set、version rule、generator、decoding setting 和 answer rubric。比較 lexical、dense、fusion，以及 reranking 或 selection 改善。

儲存 raw candidate list 和 answer output。按 exact identifier、paraphrase、multi-source question、absence 和 version comparison 分 slice。

如果某方法改善 paraphrase，卻損害 exact name，應研究這個 pattern。只有能定義並測試規則時，才加入 routing；不要用 aggregate average 掩蓋取捨。

實例練習與學習檢查

重現 RRF 計算，然後從兩個 candidate list 都移除一段必需 passage。解釋為甚麼提高 reranker quality，仍不能修復這個特定缺失。

執行一次真實 RAG 比較，並人手 audit claim 和 citation。有效 source ID 只通過 structural check；還要檢查被引用 passage 是否支持 claim。

當你能用量度到的 error reduction，支持加入某個 pipeline component，並說明 quality、complexity 和 latency cost，就已準備好繼續。

參考細節與學習檢查

複習 A：直觀理解

Lexical 和 semantic search 會犯不同錯誤。Hybrid retrieval 結合 candidate list；reranking 則用更多運算判斷最佳 candidate。這是兩種獨立操作。若 relevant document 不在 candidate set，reranking 無法把它找回來。

除非有合理 calibration，否則不要把 BM25 score 直接加到 cosine score：兩者 scale 不同。Reciprocal rank fusion 結合 rank： RRF(d) = sum_lists 1/(c + rank_list(d)) ，rank 從 1 開始。c 控制最高 rank 的主導程度。在 development data 選 setting，並與每個單獨 component 比較。

複習 A：Fusion 計算

當 c=60，passage A 在 lexical 排第 1、semantic 排第 10，其 score 是 1/61 + 1/70 ，約 0.03068。Passage B 在兩者排第 2，其 score 是 2/62 ，約 0.03226。B 勝出，因為兩個 system 都支持它。若 document 不在某個有限 list 中，該 list 的貢獻是 0。Fusion 不代表這些 score 是 probability。

Cross-encoder 同時讀 question 和 candidate，給出 relevance score。先 rerank 足夠廣的 candidate pool，再選小型 evidence set。Diversification 可以減少近乎重複的內容，但過度 diversity 也可能丟掉同一 source 的必需 detail。Parent-child retrieval 可以搜尋小 chunk，再納入較大 parent section，提供連貫 context。

複習 A：Query transformation

Query rewriting 解析對話中的 reference 或擴展 term。Multi-query retrieval 可以擴大 recall。Hypothetical-document 方法會先生成一段像答案的 passage，再對它 embedding。這些方法可能幫助部分 distribution，卻也可能引入 unsupported assumption、額外 latency 和相關的 false evidence。保留 original query，並記錄 transformation。Version 和 access constraint 必須在 rewriting 後仍然成立。

複習 A：實驗

在相同、固定的 development split 上，比較 lexical only、dense only、rank fusion，以及 fusion 加 reranker。Notebook 以簡單 deterministic reranking 示範介面；真正 neural reranker 是選做延伸，並非聲稱已量得的 baseline result。報告 reranking 前的 candidate recall，以及 generation 後的 answer metric，藉此區分 recall problem 和 ordering problem。

如果 hybrid 改善 identifier，卻損害 paraphrase，應檢查 slice result，再考慮 targeted routing。在能解釋 decision boundary 和 evaluation 之前，不要加入 routing。較複雜的 pipeline 有更多 timeout、cache、artifact 和 failure path。
