完整 numeric transformer trace

使用 IDs [0,1]、一個 head、d_model=2。Q/K/V 和 attention output projections 是 identity matrices；兩個 MLP matrices 亦是 identity，中間用 ReLU。每次 normalization 使用 population variance、epsilon=0.00001、scale=1、bias=0。Vocabulary head 在 row-vector convention 下為 [[1,0,-1],[0,1,0]]。固定 weights 示範計算，並非 trained language model。

本學期回到一句話

我們由「I go to school by ___.」開始，現在已能追蹤預測續寫的 causal transformer。本課目標是連接學過的 component，而非介紹 application framework。

使用小型 vocabulary 和兩個 block 的教學 model。在圖中清楚標示 token ID、representation width、head count 和 sequence length。

這個 model 刻意設計得足夠小，方便檢查。architecture 與大型 system 分享重要概念，但 performance 和 resource 仍非常不同。

第一階段：text 變成 representation

將 prefix tokenize 成 [I,go,to,school,by]，再轉成 ID。從 embedding table 為每個 ID 選一個 vector。

為每個位置加上 position vector。若有五個 token，width d_model=8，representation matrix 就是 [5,8]。

ID 本身不編碼順序或 semantic distance。embedding lookup 和 position representation 提供不同資訊，供後續 transformation 使用。

第二階段：每個 block 混合並轉換資訊

normalize 每個 row，形成 Q/K/V，分出合適 head axis，計算 scaled pairwise score，套用 causal visibility，再沿 key 做 softmax。與 value 相乘、合併 head，再 project 回 width 8。

透過 residual path 加入 sublayer output。再次 normalize，套用 position-wise MLP，並進行第二次 residual addition。

在下一個 block 重複。output 仍保留每個 position 的 contextual row。任何 causal query 的計算，都不得使用尚未可得的未來 input。

第三階段：vocabulary prediction

最後 output head 將每個 contextual row 轉成 V 個 vocabulary logit。prefix 最後的 position by，提供用來選下一個 token 的 logit。

假設 bus=2、train=1、bicycle=0，而且在這個小算例排除所有其他 candidate。softmax 約得到 [0.665,0.245,0.090]。

真實 vocabulary 包含很多其他 candidate，所以 denominator 亦要包括它們的 score。必須明說算例限制了範圍；這不是真實 model 的完整 output distribution。

第四階段：training 與 generation 以不同方式使用結果

用完整句子 training 時，預期 target bus 提供 cross-entropy loss。它的 gradient 經過剛才追蹤的計算路徑，改變 parameter。

inference 時，沒有預先給定的 bus target 可以 backpropagate。decoding rule 選下一個 token、附加它、按需要更新或重用 cached state，繼續直至停止條件。

這個分別解釋了同一 network 為何在 training 和使用時都能產生 logit，但周邊程序不同。

在正確邊界診斷錯誤

若 ID decode 成錯字，檢查 tokenizer/vocabulary 配對。若改動未來 input 影響較早 output，檢查 visibility。若 output width 不同於 vocabulary size，檢查 output head。

若 training loss 下降，但 held-out 任務仍弱，先檢查 data、capacity、optimization 和 evaluation，才斷定 block 實作有誤。

有系統的 debug 解釋會指出邊界、具體觀察，以及能區分可能原因的 test。「AI 很混亂」並沒有提供這些資訊。

做好準備後閱讀原版 architecture

打開原版 transformer paper 的 model 圖和 attention equation。辨認哪些 component 已實作，哪些屬於 encoder-decoder 翻譯 architecture，而非我們的 decoder-only 練習。

在一條 equation 旁寫出 tensor shape。找出 residual connection 和 MLP。留意我們的 pre-norm 教學 block，與原版 architecture 的 normalization 排列不同。

現在是適合讀 paper 的時候：你已有 operation 和 example，能用來理解精簡的論文表達。

最後的 shape 紀錄表

若 B=2,T=5,d_model=8,H=2，vocabulary size V=20，token ID shape 是 [2,5]，起始 row 是 [2,5,8]，每個 head 的 query 是 [2,2,5,4]，attention score 是 [2,2,5,5]。合併後的 contextual output 回到 [2,5,8]，vocabulary logit 是 [2,5,20]。

普通續寫時，每個 sequence 最後的 input position 提供一個 twenty-way next-token distribution。training 時，所有有效 position 都可以對 shifted target 貢獻 loss。兩種情況中，causal constraint 都限制每個 query 的可見 key。

寫 reshape 前，先用文字解釋每個 axis。然後建立小 tensor，刻意讓 batch、head、position、feature index 的數值各有分別，錯誤 transpose 就會顯現。這個小實驗讓 shape 紀錄成為實作檢查，而非裝飾性符號。
