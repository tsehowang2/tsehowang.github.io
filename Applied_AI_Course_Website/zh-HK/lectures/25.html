Training 更少 parameters

完整 model 可以包含許多 weight matrices。對每個 entry 進行 fine-tuning，需要為所有 parameters 保留可訓練 state。LoRA 則固定 base matrix，再透過兩個較小 matrices，學習有結構的 update。

先用 column-vector 記法看一層 y=Wx。Base W 仍然處理 input，額外路徑則提供學習得來的變化。

這改變的是 adaptation 的 parameterization 方式。它不會補上缺失的 evidence、審核 training labels，也不保證 application 一定改善。

手算一個 two-by-two update

設 A=[0.1,0.2]，shape 是 [1,2]；B=[[1],[2]]，shape 是 [2,1]。兩者的 product BA 是 [[0.1,0.2],[0.2,0.4]]。

兩個 rows 成比例，因此這個 update 的 rank 最多為一。把 BA 乘以 x=[1,1]，得到 [0.3,0.6]。把這部分加到 base layer 的 Wx output。

這個小例子讓計算看得見，但尚未節省 parameters：A 和 B 共有四個 entries，與 2×2 dense matrix 相同。能否節省，取決於 dimensions，以及 rank 是否足夠小。

一般 shapes 與節省的條件

W 的 shape 是 [d_out,d_in] 時，選擇 A 為 [r,d_in]、B 為 [d_out,r]。Adapter parameters 共 r(d_in+d_out)，而 W 有 d_in×d_out 個 parameters。

當 d_in=d_out=1000、r=4 時，adapter 有 8000 個 parameters；dense matrix 則有一百萬個。Update 受到 low-rank factorization 的限制。

增加 r 會增加 capacity 和可訓練 state，但不保證 held-out quality 一直變好。應在指定 dataset 和 training budget 下比較不同 ranks。

Scaling 與 zero-update initialization

常見的 expression 是 y=Wx+(α/r)BAx。在這個 parameterization 下，α/r 控制 update 的 scale。

常見的 LoRA initialization 把 B 設為 0，並隨機初始化 A，所以起初 BA update 是 0。第一次 backward pass 中，B 可以透過隨機 A 得到非零 gradient，而 A 經過零 B 得到的 initial gradient 則為 0。B 改變後，A 亦可以開始學習。若 A 和 B 都設為 0，兩者的 initial gradient 都會被阻斷。

值得用 code 檢查：在可比較的 modes 下，adapted model 應由接近 base computation 的狀態開始，而可訓練的 adapter parameters 應收到預期 gradients。

哪些東西仍佔用 memory

Frozen base 仍佔 memory，也會參與 forward computation。為了學習 adapters 而保留的 activations，也可能相當大。

LoRA 減少的是 trainable parameters 和 optimizer state 那部分。它不會令大型 model 的 activation footprint 變得極小，也不會移除所有 backward computation。

利用第 22 週的 resource accounting，辨認改變了哪類 state。小型 adapter file 只是完整 model/runtime 需求的一部分。

QLoRA 加入 quantized frozen base

QLoRA 結合 low-rank adaptation 與 quantized base representation。部分 tensors、computations 和 trainable states 仍使用較高 precision。

Four-bit base weights 不代表 activations、gradients、optimizer states 都是 four-bit，也不代表一定更快。Hardware 和 kernel support 很重要，尤其你本機的 GPU 較舊。

必做實驗使用小型普通 LoRA model。若 runtime 支援所選 backend，而實驗亦能在時間內完成，quantized 比較可作選做延伸。

NF4、double quantization 和 paged optimizer 各自做甚麼

QLoRA 把三種 memory 方法與 LoRA 結合。NF4 用一組為 normal distribution 數值設計的 4-bit codebook，儲存已 normalize 的 weight blocks。它的 16 個 code values 並非單純等距的 16 個整數。Block scale 把儲存的 codes 還原為計算時使用的 approximate weights。Frozen base 經過 quantization，而 adapter 和 computation 可以使用較高 precision。

Double quantization 亦會 quantize block-scale information。想像把 weights 放在很多小盒中：先壓縮盒內數值，再壓縮部分數值標籤。這能節省一些 metadata storage，並非把每個 tensor 再減半。Paged optimizer 利用 managed-memory paging，處理暫時的 optimizer-memory 壓力。State 在 host 和 device 之間移動需要時間，因此 paging 主要處理 memory spikes，並不保證 training 更快。

兩種改變不同部分的 LoRA variant

rsLoRA 把 scaling 從 alpha/r 改成 alpha/sqrt(r)，目的是令 rank 增加時的 update 較穩定。若 alpha=16、r=16，兩個 factors 分別是 1 和 4。這是 scaling rule，不是另一種 base quantizer。DoRA 把 weight magnitude 和 direction 分開：學習 magnitude component，並以 low-rank update 調整 direction。因此 DoRA 改變 parameterization，亦增加 state；它並非 QLoRA 的另一個名稱。先理解普通 LoRA path，再辨認每種 variant 改變哪個 component。

儲存與使用 adapter

儲存 adapter weights 和 configuration 時，也要記錄確切 base model 和 tokenizer identities。把 checkpoint 套到不相容 base，可能改變行為或失敗。

部分 adapter updates 可 merge 到相容 base 以作 inference。Quantized merging 和 numerical behavior 需要驗證，不能直接假定可行。

要測試儲存後重新載入的 artifact，而非只測試剛完成 training、仍在 memory 內的 object。下週會完成整個實驗。

實例練習與學習檢查

計算 4096×4096 matrix、rank 8 的 adapter shapes 和數量。結果是 65536 adapter parameters，約為 dense matrix 的 0.390625%。

解釋為何 rank-one update 不能表示所有可能的 2×2 變化。然後說明一項 LoRA 能減少的 memory cost，以及一項仍存在的 cost。

參考細節與學習檢查

複習 A：機制

Dense layer 計算 y = W x 。LoRA 固定 W，並學習 delta_W = (alpha/r) B A ，因此 y = W x + (alpha/r) B A x 。若 W 的 shape 是 [d_out,d_in] ，A 的 shape 是 [r,d_in] ，而 B 是 [d_out,r] 。這一層只會 training r*(d_in+d_out) 個 adapter parameters。選擇哪些 target layers，也是實驗的一部分。

對 4096×4096 matrix、r=8，dense matrix 有 16,777,216 parameters，而 A 和 B 合共 65,536，約 0.39%。這大幅減少可訓練 optimizer state，但不會移除 frozen model storage、activations，或經過 model 的 forward/backward computation。LoRA 可套用於 attention projections 和其他 layers；應檢查實際 module names，不要盲目複製 configuration。

複習 A：Initialization 與 scaling

標準 LoRA 使用隨機 A 和零 B，令 initial update BA=0。第一個 gradient 可以更新 B；當 B 變成非零，A 便可以學習。在相同 mode 下，adapted model 起初執行 base computation。Rank 決定 update space 和 trainable state 的大小，因此比較不同 rank 時，要固定 evaluation 和 training budget。

複習 A：QLoRA

QLoRA 結合 quantized frozen base 與 low-rank trainable adapters [ Dettmers et al. QLoRA (R13) ]。Four-bit base weights 不代表所有 tensor 或 calculation 都是 four-bit。Quantization scales、compute dtype、adapters、gradients、optimizer states 和 activations 仍要考慮。專用 backend support 視乎 hardware 和 software。本課程要求完成一次小型普通 LoRA training；若 runtime 支援，可選做 QLoRA 比較。

複習 A：部署考慮

儲存 adapter 時，記錄 base model/tokenizer identity 和 target modules。若不知道 base revision，單有 adapter checkpoint 並不足夠。把 low-rank weights merge 到相容的 unquantized base，可移除獨立 adapter 路徑；但 numerical behavior 和 quantized merge support 都需要檢查。測試儲存後重新載入的 artifact，而非只測試 memory 中的 training object。

複習 A：實驗

Tutorial 25: 從小型 matrix 理解 LoRA 及 QLoRA 計算 trainable parameter 數目，並檢查 LoRA initialization。 Tutorial 26: Fine-tuning 實驗、preference 與 distillation 建立實際 adapters，確認哪些 parameters 收到 gradients。比較手算與 model 的 parameter count，解釋 biases 或未計入的 modules。載入前先估計 memory，第一次 training step 後再量度。

完成標準： 推導 LoRA shapes，解釋 zero-update initialization，並區分 LoRA 與 QLoRA。 閱讀材料： Hu et al. LoRA (R12) 方法、 Dettmers et al. QLoRA (R13) 概覽、 Hugging Face PEFT LoRA guide (R14) 。 Tutorial： 25.
