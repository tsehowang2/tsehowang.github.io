Word vector 能表達甚麼

練習 03檢查你的理解
課堂投影片 · 第 03 週

一步一步學習。

閱讀每段解說，停下來預測結果，然後繼續。選取簡報後，可用方向鍵操作。完整講義在下方。

由例子開始

兩個字可以有不同標籤，卻是相關的 input

我們的 count model 把「I go to school by」和「I go to work by」視為毫不相關的完整字串。Neural model 則可以在不同例子中重用數值 feature。如果 school 和 work 出現在某些相似的交通 context，學到的 representation 可能會有共同特性，有助預測交通工具字詞。

這不表示兩個字意思完全相同。如果 representation 的 coordinate 能幫助 model 降低某項任務的 error，它就對該任務有用。Model 學到甚麼，取決於資料和 objective。

先從普通的二維 vector 開始，方便畫出來。Vector 有 direction 和 length。這兩個特性對常見 similarity 計算的影響並不相同。

由例子開始

Dot product 是加權比較

對 q=[1,0] 和 a=[0.8,0.6]，dot product 是 1×0.8+0×0.6=0.8。對 b=[4,3]，結果是 4。b 的答案較大，同時反映了 direction 和 magnitude。

Dot product 可以理解為兩種 coordinate pattern 對齊的強度。負與正的 coordinate 可以作出相反方向的貢獻。這是一項數值運算，並不會自動定義 semantic similarity。

之後 attention 會使用學習得到的 query vector 和 key vector 之間的 dot product。我們現在先研究這項運算，避免在介紹 attention equation 時，一次過加入 geometry 和 model architecture。

建立對機制的理解

Cosine 比較 direction

a 的 length 是 sqrt(0.8²+0.6²)=1。b 的 length 是 sqrt(4²+3²)=5。把 dot product 除以兩者 length 的乘積，就得到 cosine similarity。這兩個 vector 與 q 的 cosine 都是 0.8。

從 geometry 看也合理：b 是 a 的五倍，所以指向同一方向。把非零 vector normalize 至 length 為一，就會移除 magnitude。Normalization 之後，它們與 unit q 的 dot product 相等。

沒有哪一種 score 在所有情況下都正確。Model 可能把 magnitude 作為學習計算的一部分。對某項 retrieval 任務，只比較 direction 可能有用。應選擇配合 training objective 和所研究系統的運算。

建立對機制的理解

Embedding table 如何從 prediction error 學習

假設簡單的 model 看到 token school，要預測下一個 token。它選取 school 的 row，作 transformation，然後為 vocabulary 各項產生 score。如果正確 next token 是 by，但 model 給它的 probability 太低，training 就會透過 gradient 改變 parameter。

Embedding coordinate 也是可以改變的 parameter。反覆出現的 context 會促使 model 建立有用的共享結構。我們並不是手動給 school 指定一個「education coordinate」。

不同 random seed 可以得到不同 coordinate 值，卻支援相似的 prediction。如果同時旋轉 representation space，並對後續 transformation 作相容調整，相關行為可以維持不變。因此，不應把個別 coordinate 解讀成固定的人類概念。

建立對機制的理解

起始 vector 與 contextual vector

bus 的起始 vector 來自它的 vocabulary row。在「I go to school by bus」和「The bus broke down」中，lookup 的 row 可以相同。經過 context processing 後，兩個句子中 bus 位置的 representation 就可以不同。

Context 告訴我們，正在討論交通選擇，還是故障。Contextual vector 表示在可用 context 下、某個 position 的 token。之後 causal mask 會決定哪些其他 position 可供使用。

要分清 token embedding、contextual token representation 和整句 sentence embedding。從 lookup table 選出的 vector，並不會自動成為整段文字的良好摘要。

建立對機制的理解

簡單的 sentence representation 及其限制

表示句子的一個簡單方法，是對 token vector 取平均。這會結合資訊，卻失去大部分順序。「The dog chased the boy」和「The boy chased the dog」在簡單 tokenizer 下包含相同單字，因此不考慮順序的平均值可以完全相同。

這個限制說明為何需要 context 和 position processing。取平均仍然可以是有用的 baseline；了解它的 failure mode，能避免把方便的方法誤當完整 language model。

第 17 週會再回到為 search 訓練的 sentence embedding。這個應用需要自己的 objective 和 evaluation。現在的目標，是理解數值 representation 如何共享資訊。

深入學習，檢查理解

一個小型數值實驗

把 q 從 [1,0] 移向 [0,1]。到 [0,1] 時，它與 a 和 b 的 dot product 變成 0.6 和 3，但兩者的 cosine 仍然相等，都是 0.6。Normalize passage vector 會改變原本的 dot-product 比較。

現在試 q=[-1,0]。Dot product 變成 -0.8 和 -4。當 score 可以是負數，similarity 的定義便很重要。最高 score 仍只表示「在此運算下最大」，並不表示「以這個 probability 為真」。

用 geometry 圖解同時檢查 magnitude 和 direction。在依賴圖中顏色之前，先解釋計算。

深入學習，檢查理解

實例練習與學習檢查

計算 [3,4] 的 norm，把它 normalize，再計算它與 [1,0] 的 cosine。答案為 5、[0.6,0.8] 和 0.6。然後比較 [6,8]，解釋甚麼改變了，甚麼維持不變。

解釋為何改動 embedding table，卻不調整已訓練 model 的其餘部分，可能改變行為。再解釋為何兩個分開訓練的 384-dimensional model，不一定使用相容的 coordinate。

現在你應該能跟隨 embedding lookup、dot product、normalization，並分辨 initial representation 和 contextual representation。這些都是學習 attention 之前需要的數值基礎。

深入學習，檢查理解

第二個 representation 例子

假設 toy vocabulary 有 school=[1,0]、work=[0.8,0.2]、bus=[0,1]。「school bus」的 mean representation 是 [0.5,0.5]，「work bus」則是 [0.4,0.6]。它們的 similarity，部分來自共同的 bus 成分。這些 coordinate 是刻意選定的；實際 model 需要 training 和 evaluation。

現在把「school bus」反轉成「bus school」。因為 addition 具有交換律，mean 不變。這是對「取平均永遠保留語言意思」的精確反例。要證明這項特定 invariance，無須大型 benchmark。

下一個問題是如何改善：model 怎樣分辨順序？Position information 可以改變起始 row，contextual processing 則可以用不同方式結合它們。這直接把簡單 vector average 的限制，連結到我們正在建立的 architecture。
