第一學期 / 第 05 週

為甚麼語言需要 context 和次序

練習 05檢查你的理解
課堂投影片 · 第 05 週

一步一步學習。

閱讀每段解說，停下來預測結果，然後繼續。選取簡報後，可用方向鍵操作。完整講義在下方。

由例子開始

同一個字可以出現在不同情況

讀「I go to school by bus」和「The bus is late because it broke down.」。Token bus 參與了不同關係。第二句中，it 指回 bus。若 model 獨立處理每個 token，就無法利用句子解決這個指代關係。

字的順序也很重要。「The boy follows the bus」和「The bus follows the boy」包含相同單字，卻描述不同事件。只根據出現了哪些字建立 representation，會失去這個分別。

我們現在需要一個機制，把起始 token vector 轉成依賴其他 position 的 representation。這就是 attention 要處理的問題。先看看較簡單的 context 提供方法。

由例子開始

固定 window 只看到句子的一部分

Window model 可能只用最後兩個 token 預測下一個 token。對「I go to school by」，它只看到 school by。這可能有用，但較早的資訊一旦落在指定 window 以外，就會消失。

擴大 window 會增加 context，但對某些簡單 architecture，也會改變 input size 和 parameter 數量。若句子的 dependency 距離更遠，仍可能超出 window。

這並不是證明所有 fixed-window model 都表現差，而是指出一項結構選擇及其限制。在討論 benchmark 結果之前，我們想先了解 architecture 能使用哪些資訊。

建立對機制的理解

Recurrent model 會攜帶 state

Recurrent neural network 每次處理一個 token。簡化的 recurrence 是 h_t=f(Wx_t+Uh_(t-1)+b)。新的 state 結合當前 token vector 和上一個 state。

想像依次讀 I、go、to。讀到 to 之後的 state，可以攜帶這三個字的部分資訊。因為下一個 state 依賴前一個 state，sequence 自然有處理順序。

這個 state 的 width 有限，必須在反覆更新中保留有用資訊。學習長距離 dependency 可能困難，而 training 也有跨時間的 sequential dependency。Gated recurrent architecture 能處理部分問題，但不會消除所有取捨。我們介紹它們是為了理解問題，並非聲稱 recurrence 無法做 language modeling。

建立對機制的理解

用簡單 state update 展示資訊流失

考慮 scalar recurrence h_t=0.5h_(t-1)+x_t，由零開始。如果 input 值是 [1,0,0,0]，state 就是 [1,0.5,0.25,0.125]。第一個 input 的影響逐步減弱。

這是刻意設計的算術例子，並不表示訓練好的 RNN 永遠使用 0.5 的衰減。它展示反覆 transformation 如何改變較早資訊的影響。

如果任務要求經過很多步後仍準確記住第一個字，compressed state 就必須保留這項細節。Attention 會提供另一種 access pattern：把當前 representation 直接與可用 position 的 representation 比較。

建立對機制的理解

讀取 source，產生 target

翻譯提供一個具體的 context 問題。「I go to school by bus」可以是 input sequence，而譯文則是另一個 output sequence。Encoder 讀取 source 並建立 representation；decoder 按 generation rule 產生 target。

單一固定 vector 可以概括整個 source，但句子變長時，重要細節可能難以保留。Attention 可以讓每個 target position 查閱不同 source position。

這個 source-target 例子引出 cross-attention。我們先研究的 self-attention，則比較同一 sequence 內的 position。分別在於 vector 從哪裏來，而不是方法是否在「思考自己」。

建立對機制的理解

當前 position 可以看到甚麼

Next-token generation 中，從「I go to school by」作 prediction 時，在生成 bus 之前不能先讀到答案 bus。如果 training 計算意外讀取未來 token，它解決的問題便比 inference 任務容易。

若 sentence encoder 用來表示已完整觀察的 input，讀取某個 position 左右兩邊的字可能合理。任務決定允許使用的資訊，並沒有通則要求所有 language model 使用同一 mask。

我們會把 architecture 與 visibility 分開。Causal decoder 使用從左至右的 visibility pattern；encoder 通常對有效 input position 使用 bidirectional pattern。

深入學習，檢查理解

通往 attention 的橋樑

假設你要填上句子最後一個字。你可能查閱不同的較早線索，而不只依靠一張壓縮筆記。Attention 把這個想法變成從資料學到的 value vector 數值 mixture。

這個次序讓我們在引入最終公式的所有 matrix 之前，先檢查 mixture。初學者應先能計算小型 attention 例子的 output，才去記它的簡潔 equation。

深入學習，檢查理解

把 context access 畫成可測試的圖

把「I go to school by bus」畫成六個方格。對 school 位置的 representation，畫線連到各 model 允許使用的資訊。Two-token window、recurrent state 和完整有效 input attention，提供不同路徑。

若從 school 作 autoregressive prediction，就劃掉 by 和 bus，因為它們是未來 input position。若是完整句子的 encoder，這些字則可以保留。因此，同一句子在不同任務下，可以有不同而合理的計算。

不要只用某個 model「讀得比較好」來解釋分別。圖中會指出實際 dependency。接着可以用 property test 改變不可用 token，確認在禁止存取的位置沒有影響。這把口頭規則變成可量度的 implementation 條件。
