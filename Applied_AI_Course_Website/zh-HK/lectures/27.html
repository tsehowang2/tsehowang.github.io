完整講義

閱讀完整解說

Calculator 是具體而有用的 capability

一張 bus ticket 要 4 dollars，child ticket 要 2 dollars。兩張 adult tickets 加一張 child ticket，合共 2×4+1×2=10 dollars。Deterministic calculator 可檢查 arithmetic。

Model 可以建議 expression，但由 application code 決定可用 operations，並 validation arguments。產生一個 function name，並不代表獲准執行任意 code。

討論 agent framework 前，先由這項狹窄 capability 開始。Tool 是通往指定 operation 的 interface，並有自己的 contract。

Tool call 包含 name、arguments 和 result

Proposal 可以是 name=calculate，arguments={expression:"2*4+1*2"}。Controller validation shape 和 expression，執行有界 arithmetic operation，再回傳 value=10。

之後可利用 observation 組成 response。Final answer 應與 result 一致，並在需要時引用 ticket prices 的 source。

學習這個 control flow 不需要在網站執行 code。Visual lesson 模擬流程，notebook 則執行真正的 bounded reference implementation。

Schemas 讓邊界可檢查

定義 required keys、allowed types、ranges，以及多餘 fields 的處理方式。Integer timeout field 不應因 Python 把 bool 當成 int subclass，就接受 true。

Configuration validator 可以接受格式正確的 invocation，但因建議 timeout 超出 range 而回傳 valid=false。這與拒絕 malformed call 不同。

Error categories 有助 debugging：proposal parsing、schema failure、scope failure、execution failure、domain-invalid result，以及 final-answer error。

固定 workflow

對簡單 ticket task，workflow 可依預定次序 retrieve 現價、calculate total，再 format response。

Model 可以協助抽取 structured request，但 control path 大致固定。這樣可能較易測試，而且已足夠完成 task。

只有當 task 確實能受惠於根據 observations 選擇下一 action，才加入 adaptive planning。

Agent 會適應情況選擇 actions

Troubleshooting 的下一步可能取決於 result：檢查 requested version、retrieve rule、validate configuration，再調查第一項 violation。

Agent 讓 model outputs 影響下一 action。外圍 controller 仍負責 enforce tool contracts、scope、budgets 和 termination。

把系統稱為 agent，不代表有良好 reasoning、可靠 execution，或更廣 authorization。這些都需要另外 implementation 和 evaluation。

有限 execution 與任意 programs

我們的 arithmetic tool 會 parse 受限制的 expression tree。它只允許少量 operators，拒絕 names/function calls，並限制 size 和 numeric magnitude。

它不會把 expression 傳入 Python eval。General code runner 需要比本 tutorial 強得多的 isolation 和 resource controls。

若將來加入 side effects，要仔細定義 authorization、idempotency 和 retries。Lookup page 與 deploying service 的後果不同。

分別測試 capability 與 behavior

先讓 deterministic planner 經 controller 執行。這可在不依賴 model output quality 的情況下，檢查 validation 和 execution。

然後連接真正 model planner，把 malformed proposals 和 wrong choices 保留為 results。Controller 接受 call，不等於 task 成功。

在相同 task set、available tools 和指定 resource budget 下，與固定 workflow 比較。若 agent 沒有可量度價值，可保留為 experimental branch。

Native function calling 與 structured output

很多 model interfaces 接受 tool definitions，並回傳有明確結構的 tool-call field，讓你不必從自由文字抽取 function name。這就是 native function calling。Model 仍然只是提出 call；application 才負責執行。Call 通常有 tool name、arguments 和 identifier，用來把 result 對應到正確 request。不同 model 和 chat template 支援的 schemas、tool formats 會有分別，使用時要核對。

Parsing 檢查收到的文字能否轉為 JSON。Schema validation 在收到資料後檢查 keys、types 和 ranges。Constrained decoding 則在 generation 時限制可選 next tokens，令 output 符合支援的 grammar 或 schema。三者屬於不同階段。有效 JSON 仍可能包含錯誤計算或未獲授權的 action，因此 semantic checks 和 permission checks 仍由 application 負責。

Parallel calls 需要先檢查 dependency

兩個獨立的 reads，例如查詢 adult fare 和 child fare，可以 parallel 執行。計算 2*adult_fare+child_fare 則必須等待兩個 results。為每個 call 設定 ID，分別記錄 result 或 error，並預先定義只有一個成功時如何處理。若 calls 更新同一個 booking，或依賴較早的 observation，就需要明確次序。Model 提出兩個 calls，並不代表它們適合 concurrent 執行。

一個具體的 ReAct 與 environment trace

ReAct 交替進行下一步決策、action，以及回傳的 observation。對 fare 問題，可觀察的 trace 是：retrieve prices → 觀察 adult=4、child=2 → 以 2*4+1*2 呼叫 calculate → 觀察 10 → 回答 10 dollars，並引用 fare source。簡潔記錄選擇的 action 和原因即可。成功條件是能獨立核對的結果，而不是很長、看似內部思考的 rationale。

Coding agent 在 repository 中查看 files、提出 edits 和執行 tests；computer-use agent 則透過 observations、clicks 和 typing 操作畫面。兩者都需要 initial environment、allowed actions，以及 final state 的檢查。小型 coding exercise 可以提供一個獨立 fare function 和 failing test，允許 patch，再檢查 target test 及原有行為。這示範 SWE-bench 所用的 issue-to-patch-and-tests 評估方式，不要求執行完整 benchmark。對畫面操作任務，應驗證實際儲存的 booking state，而不是接受最後一句「done」。

寫出 ticket tool contract、valid call、unknown-tool call、extra-argument call 和 division-by-zero case。執行前預測每項結果。

參考細節與學習檢查

複習 A：直觀理解

Model 可以建議呼叫 calculator、lookup document，或檢查 configuration。單憑說出 function 名稱，不會獲得 authority。Tool interface 指定有哪些 operations、哪些 arguments 有效，以及如何回傳 results。Application code 負責 enforce 這些規則。

定義 tool 時，列出 name、input schema、output schema、authorization requirements、failure states 和 side effects。把 read-only tools 與改變 external state 的 actions 分開。本課程可執行 tools 是 bounded arithmetic calculator 和固定 configuration validator。兩者都不提供任意 Python evaluation、shell commands、network requests 或 file writes。

複習 A：Validation 層次

Parse model response；validate shape；檢查 tool name；validate argument keys/types/ranges；enforce authorization；在 time/resource limits 下 execute；normalize observation；log outcome。不要對 model-generated expressions 使用 eval 。附帶 calculator 會 parse arithmetic AST，只接受狹窄 operator set，並限制 length、tree size 和 numerical magnitude。這些 checks 用作教學，不是任意 code 的 general sandbox。

複習 A：Contract 實例

validate_config 只接受 timeout_ms 為指定 range 內的 integer，以及 retries 為指定 range 內的 integer。若 input 多了 command field，便會拒絕。Integer field 不應默默接受 Python boolean subtype。Observation 回傳 valid 以及明確 errors；不會向 model 回傳未整理的 exception traceback。

對 side effects，idempotency 很重要。Retry document lookup 通常無害；retry deployment 卻可能建立多個 releases。真正帶 side effects 的 tool，需要 idempotency key、authorization 和明確 retry semantics。我們會學習這些 contracts，但 starter 不提供 deployment tools。

複習 A：實驗

Tutorial 27: Tool、function、workflow 與 agent 練習 valid calls、unknown tools、missing arguments、oversized expressions、division by zero、extra fields 和 invalid value ranges。先預測每項應在 execution 前被拒絕，還是回報為 tool failure。建立小表格，列出可觀察 outcomes 和 expected traces。

Documentation assistant 有用的 executable behavior 很狹窄：根據 retrieved rules 計算 retry delay，或按 selected version validation 建議 configuration。Generic shell access 會把 risk 和 evaluation scope 擴大至遠超 task。只有實際 user task 需要時，才加入 capabilities。

完成標準： 畫出 model proposed call 與 authorized execution 的邊界，並在 prompt 以外實作 validation。 閱讀材料： Yao et al. ReAct (R11) actions/observations； Hung-yi Lee Introduction to GenAI and ML 2025 (R03) agent/context 主題。 Tutorial： 27.
