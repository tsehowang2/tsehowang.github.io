完成文字與遵從要求

pretrained language model 從 prediction 任務學習模式。「Complete this sentence with one transport word」這類要求，指定了一種特定行為方式。

model 可能在 pretraining 已獲得部分有用行為，但 supervised example 可令期望的格式和 response 更一致。我們區分一般 prediction training 與之後的 adaptation。

繼續用簡單任務。給定「I go to school by ___,」，一個期望 response 是 bus。給定「Name two possible completions,」，期望 response 可以是 bus 和 train。task instruction 改變了甚麼才算滿意的 response。

pretraining 從廣泛文字學習

next-token pretraining 利用文字建立大量 shifted prediction target。data 和 objective 並不保證每個生成主張都正確。

model 學習 parameter，以支持 training distribution 內的 prediction。它不是把每句話當作普通可搜尋的 row 儲存，雖然 memorization 確實可能發生。

embedding table、attention projection、MLP weight 和 output head，都參與這個 parameterized 計算。前面 lecture 學過的完整路徑，在 training 後依然存在。

supervised fine-tuning 提供期望 response

一個 SFT example 配對 input 和 target output。單輪教學例子中，input 可以包含 instruction 和句子 prefix，target 則是期望的 completion。

training 可能只對 assistant-response token 計算 loss，同時保留 prompt token 作 context。這是 loss masking，與 causal attention masking 不同。

本週先建立概念。學過 evaluation 和 compute resource 後，week 24–26 才會建立 dataset、adapter 和受控制的 fine-tuning 實驗。

preference 比較 candidate response

一個 preference example 包含 prompt 和兩個可能 response，按明確 rubric 偏好其中一個。正確而簡潔的 completion，可以比無關答案更受偏好。

RLHF 通常在 reinforcement-learning 程序使用由 preference 得到的 reward 資訊。DPO 則使用相對 reference model 的 direct preference objective。細節稍後再學；兩者都需要深思熟慮的 data 和 evaluation。

preference 是對受評行為的 signal。只獎勵討好的措辭，可能偏好流暢卻錯誤的 response。rubric 與 algorithm 名稱同樣重要。

作為中間計算的 reasoning

考慮「A bus ticket costs 4 dollars. I buy three tickets. What is the total?」。可核實的結果是 12 dollars。response 可以展示簡潔計算 3×4=12。

chain-of-thought prompting 用中間步驟或例子，幫助部分 model 處理部分任務。但生成 rationale 仍可伴隨錯誤 final answer，亦不保證揭示 model 真正內部的 causal process。

reasoning-trained model 可能使用額外 inference 計算。我們應評估最終正確性和 resource use，而非按顯示出來的解釋長度判斷能力。

Multi-step 答案可以在特定 boundary 出錯

使用這條問題：「A school buys 8 adult tickets at 6 dollars and 12 student tickets at 4 dollars. A 25% discount applies only to the student tickets. What is the total?」Adult subtotal 是 8×6=48；student subtotal 是 12×4=48，discount 後是 36，正確 total 是 84。看似流暢的錯誤解法，可能把整張 96-dollar bill 都 discount，得到 72。失敗點是「only」的 scope，而非 multiplication。

比較直接作答，與要求 adult subtotal、合資格 student subtotal、discount 和 final total 的 prompt。記錄最終答案是否正確，以及 discount 有否套用到正確 group。在多條獨立核對答案的 problems 上完成相同比較前，不要聲稱該 prompt 有幫助。展示 steps 可以令讀者更容易檢查錯誤，但不代表這些 steps 忠實描述所有 internal computation。

Test-time compute 在 training 後增加運算

同一個固定 model，可以透過較長的 intermediate computation、抽樣多個 candidates、搜尋 alternatives，或使用 verifier，增加 inference work。對 ticket problem，可抽樣三個 candidates，檢查兩個 subtotals 和 discount scope。報告所有 generated tokens 和 verification calls，包括被拒絕的 candidates。增加 test-time compute 提供更多尋找或檢查 solution 的機會；selection rule 決定這些機會能否改善最終答案。

PPO、GRPO、RLVR 和 constitutional feedback

在 reinforcement-learning post-training 中，language model 是為 response tokens 分配 probabilities 的 policy，而 reward 為抽樣得到的 response 評分。PPO 比較新舊 policy probabilities，並在 training objective 中使用 clipping，抑制過大的 updates；常見 RLHF 設定亦會控制相對 reference model 的 drift。Value estimator 協助估計 response 比預期好多少。這是 parameter training，與要求固定 model 展示 steps 不同。

GRPO 對同一 problem 抽樣一組 responses，再比較 group 內的 rewards。典型形式會減去 group mean，再除以加上穩定項的 group standard deviation，形成 relative advantages；在該設定下可避免另一個 learned value model。若所有 candidates 都得到相同 reward，group 便幾乎或完全沒有 relative learning signal。不同實作的 normalization、clipping 和 reference-policy penalties 可以不同，因此應指出實際使用的 objective。

RLVR 即 reinforcement learning with verifiable rewards。Checker 可以核對 ticket total、執行 unit test，或驗證 mathematical result。這比「聽起來有說服力」更直接可檢查，但薄弱的 checker 仍可能獎勵 shortcuts。只檢查 final string 是否為「84」，並不能證明所有展示的 steps 都正確。

Constitutional methods 使用書面 principles 指導 critique、revision 或 preference judgments。例如按「claims 需要 evidence」的 principle，要求 model 批評並修改答案；AI feedback 亦可以協助建立 training preferences。Principles 和 reviewer 成為 learning process 的一部分，需要評估 bias 和 errors。Constitutional feedback、human preferences、verifiable rewards 和 SFT labels 是不同的 supervision sources，而一個 training recipe 可以把它們結合。

公平的小型 reasoning 實驗

準備有獨立答案的 arithmetic example。在適用情況下，用相同 model、task set 和 decoding setting，比較 direct response 與簡潔的 step-based prompt。

計入所有生成 candidate 和 verification call。若某方法先 sample 五個答案才選一個，成本就包括全部五個。

簡單 sentence completion 可能不需要額外 reasoning。arithmetic 可用 calculator 提供獨立核實結果。只有先理解底層 model，並釐清之後的應用任務，才會引入 executable tool。

in-context learning 與 weight 改動

在 prompt 提供 example，可以影響當前 output，而不改變 model weight。fine-tuning 則用 optimizer 改變 trainable parameter。

假設 prompt 提供兩個只用一個字回答的 example，這是 contextual instruction 或 demonstration。gradient update 後儲存 adapter，則是另一種 intervention。

日後診斷失敗需要更好 prompt、更好證據，還是學到的改動時，這個區分很重要。目前先辨認哪些資訊在 input，哪些在 parameter。

實例練習與學習檢查

為 sentence completion 寫兩個 SFT example，另寫一組 preference pair，讓 preferred output 遵從 one-word instruction。指出計 loss 所用的 prompt token 和 answer token。

為 ticket 問題寫出正確答案，以及一段好看但錯誤的解釋。解釋為何只評 explanation 的流暢程度會失敗。

當 pretraining、SFT、preference、in-context example 和 reasoning prompt 在你的解釋中有不同意義，就準備好了。semester two 會回到它們更深入的 objective 和實驗。

response 可以遵從格式，卻仍然錯誤

instruction 要求用一個字完成「I go to school by ___.」。target bus 同時教授格式和關聯。若每個 example 都不顧證據而堅持 bus，model 可能學到狹窄模式，在 context 說明講者步行時失敗。

用對比例子：「The bus service is closed today. I go to school by ___.」。期望 completion 可能取決於額外資訊，而且仍有多個合理答案。假裝永遠只有唯一正確答案的 dataset，可能編入沒有根據的確定性。

instruction-following evaluation 要分開評估有否遵從「one word」，以及內容是否符合提供的事實。reasoning 則要分開看 final amount 是否正確，以及計算看起來是否可信。這些區分會引導之後的 adaptation 實驗，避免將較低 loss 自動視為更好行為。
