一個普通句子，缺了一個字

先看「I go to school by ___.」。在考慮 neural network 之前，先寫出三個可能的填空答案。Bus、train 和 bicycle 都合理。在某些奇怪的虛構故事中，把 Banana 放在「by」後面，文法上或許說得通；但對這個普通句子來說，這並不是常見的接續。這項任務是利用已有的文字，為接下來可能出現的文字分配不同的 probability。

現在把 prompt 縮短為「I go to ___.」。School 仍然可能，但 work、sleep 和 the park 也變得合理。合理的下一個字會改變，是因為可用的 context 改變了。Context 指 prediction 所依據的文字。本課程前半部分的 context，就是普通句子的 prefix。

model 不需要知道你實際如何上學，也可以給 bus 很高的 probability。它可能學到，人們經常用這種方式描述上學交通。這個分別很重要：一段很可能出現的接續，聽起來合理，但對某個人而言可能並非事實。Prediction 是起點；要如實回答問題，還需要額外的判斷，我們稍後才會研究。

一個可以逐項檢查的小型資料集

想像有五個 training sentences：「I go to school by bus」出現三次、「I go to school by train」出現一次，「I go to school by bicycle」出現一次。在 prefix 完全是「I go to school by」的例子中，觀察到的下一個字比例為 3/5、1/5 和 1/5。因此，我們第一個 language model 可以預測 bus 的 probability 是 0.6，train 是 0.2，bicycle 是 0.2。

這些數字描述的是這個小型資料集，並不代表現實世界的交通情況。資料集一改，估計值就會改。如果資料集中沒有關於 boats 的句子，這個 count-based model 對該 prefix 後面的 boat 就沒有直接證據。之後的 neural model 可以在相關 context 之間共享資訊，但它仍然是從我們提供的例子和 objective 學習。

我們已經找出 learning problem 的基本要素：例子、input、可能的 output、prediction，以及評價 prediction 的方法。我們會逐步加入數值 representation 和可訓練的 function，而不是一次過引入完整 transformer。

從一次 prediction 到一個 sequence

假設 model 選擇 bus。現在已有的文字是「I go to school by bus.」。要繼續，它會用這個更長的 prefix 再做一次 next-token prediction。它可能選擇句號。如果之後出現結束標記，generation 就停止。生成一段文字，就是重複這個操作很多次。

這就是 autoregressive generation：每次新的 prediction 都依賴 sequence 中較早的元素。model 不需要在一次決定中選好整段文字。在 generation 過程中，一個錯誤會成為之後 prediction 的 prefix 一部分，這有助解釋為何接續內容會逐漸偏離。只要選過一次不太可能的字，就會改變 model 下一次看到的情況。

暫時先把 token 想成單字。第 2 週會撤去這個簡化假設，仔細介紹 token ID、標點和 subword。初步解釋可以採用簡化假設，前提是清楚說明，並在之後修正。

用熟悉的符號表示 conditional probability

寫下 p(bus | I go to school by)。直線讀作「given」，意思是在已知該 prefix 的情況下，bus 的 probability 是多少。所有允許的 next token 的 probability 加起來等於一。language model 是一個 function，為每個 prefix 產生這樣的 distribution。

整個 sequence 的 probability 可以寫成一連串 conditional probability 的乘積。例如，p(I, go, home) 等於 p(I) 乘 p(go | I)，再乘 p(home | I go)。這個 chain-rule decomposition 是 probability 的恆等關係；具體的 language model 會提供各項的估計值。

如果這三個 probability 分別是 0.5、0.4 和 0.25，sequence probability 就是 0.05。較長的 sequence 會累積更多相乘項，因此比較不同長度句子的原始 probability 時，要特別小心。之後我們會在 prediction positions 上取 negative log probability 的平均值。

Training 和使用 model 是兩回事

Training 時，我們用例子調整 model。Inference 時，我們用已訓練好的 model 做 prediction。這個 count-based model 靠點算次數來「訓練」。neural language model 則改變數值 parameter，令 training examples 中合適的 next token 得到更高 probability。

句子「I go to school by bus」可以提供多個 training situations：「I」預測 go；「I go」預測 to；「I go to」預測 school。我們不需要找人逐項標註，因為下一個 token 已經出現在文字中。這就是 next-token training 背後最基本的 self-supervised signal。

不要把 training example 當成對 model 發出的指令。句子是資料，我們從中建立 prediction tasks。理解底層 prediction model 如何運作之後，才會介紹 instruction following。

小型 model 也很適合幫助理解

只有五句的資料集無法支援通用 assistant。它的價值是每個 probability 都能解釋。如果之後的程式給 bus 的 probability 是 0.2，而不是 0.6，我們可以檢查次數並找出錯誤。

較大的 model 會引入學習得到的 vector 和 nonlinear function，但核心問題仍然相似：它收到甚麼 input？我們期望哪個 output？它分配了多少 probability？學習過程中改變了甚麼？當 equation 變得複雜時，記得回到這些問題。

第一學期會逐步建立 transformer，作為表示及結合 context 的方法。等你熟悉 model 本身之後，才會進入 vector database、RAG、agent framework 和 deployment。

實例練習與學習檢查

再加入兩次「I go to school by train」。現在共有七個符合的例子：bus 三次、train 三次、bicycle 一次。Probability 變成 3/7、3/7 和 1/7。在這個 count model 中，Bus 和 train 並列。並列不代表任務出錯，只表示觀察到的資料無法區分兩者。

解釋為何「I go to work by」可能需要另一個 distribution。然後解釋，簡單的 exact-prefix count model 無法在 school 和 work 之間共享哪些資訊。這個限制會引出學習 representation 的需要。

繼續之前，你應該能分辨 example、prefix、next-token distribution、生成的 token、training 和 inference。你亦應該能解釋，為何高 probability 的句子未必是關於使用者的真實陳述。Tutorial 會在不用 neural-network library 的情況下，建立這個小型 count model。
