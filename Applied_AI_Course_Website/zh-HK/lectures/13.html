第一學期 / 第 13 週

Generation、decoding 與 KV cache

練習 13檢查你的理解
課堂投影片 · 第 13 週

一步一步學習。

閱讀每段解說，停下來預測結果，然後繼續。選取簡報後，可用方向鍵操作。完整講義在下方。

由例子開始

model 先提供選項，才產生句子

回到「I go to school by.」。訓練好的 model 為每個 vocabulary token 產生 score，再由 decoding rule 將 score 轉成下一個選定的 token。

greedy decoding 取最高 score；sampling 則按一個 distribution 選擇，這個 distribution 可能經 temperature 或 filtering 修改。同一 model 因而可以產生不同續寫。

這裏的 decoder 是針對 prediction 的決策程序，不會核實所選句子是否真實描述某人的上學路線。

由例子開始

簡單的 sampling distribution

假設 bus、train、bicycle、boat 的 probability 是 [0.5,0.3,0.15,0.05]。greedy 選 bus。理想的重複獨立抽樣下，sampling 可能選到全部四個，出現頻率逐漸接近這些 probability。

若 top-k=2，保留 bus 和 train，再 normalize 成 [0.625,0.375]。若 top-p=0.8，並採用包括剛好達到 threshold 那個 token 的慣例，留下的也是這兩個 token。

邊界和 tie 的慣例取決於實作。比較手算與 library 結果時，先說清楚慣例。

建立對機制的理解

generation 改變下一次 input

選 bus 後，下一個 prefix 包含 bus；model 可能預測句號。選 train 後，後續的詞可能不同。

所以 generation 不是一連串獨立 classification。較早選擇會改變後來的條件。局部 probability 最高的 token，不一定構成整體 probability 最高的完整 sequence。

beam search 按 scoring rule 保留數個未完成 sequence，但是否有用取決於任務和 decoding objective。它不是 open-ended generation 中 sampling 的通用替代品。

建立對機制的理解

重用 key 和 value

causal transformer 較早的 position 不依賴未來 token。附加新 token 時，可以保留較早已計算的 key/value state。

沒有 caching，naive generation loop 每次都重新處理整個 prefix。有 KV cache 時，新 token 可 query 已 cache 的 key/value 及自己的新 state，實際方式取決於 model architecture。

cache 儲存 intermediate representation，不是答案清單。它加快重複計算，但不改善底層證據或事實可靠性。

建立對機制的理解

追蹤三個 token 的 cache

想像 prefix 是 I go to。每一 layer 都已有這三個 position 的 cached key 和 value。附加 school 時，計算新 position 的 representation，讓其 query attend 到四個可用 key position。

舊 cached tensor 對應的是完全相同的舊 prefix。若把 I 改為 You、更改 model weight，或更改較早的 role token，一般便不能正確地重用舊 cache。

week 22 會計算 cache memory。目前最重要的是理解容許重用的有效條件。

建立對機制的理解

text model 與 chat formatting

對話 model 接收的仍是 serialized token sequence。tokenizer 可能包含 chat template，用來標記 role 和 message 邊界。

寫出可見文字「system:」，不會自動等同 template 的 special token。先檢查一個簡短 render 例子，並用真正 tokenizer 計 token。

我們在基本 generation loop 之後介紹這個 interface，讓你也能解釋 role formatting 是一種 input 構造選擇。它不應遮蓋底層的 next-token mechanism。

深入學習，檢查理解

停止及評估續寫

generation 需要停止條件：end token、指定的新 token 數上限，或其他明確規則。maximum length 防止無限續寫，但也可能截斷 response。

decode output tensor 時，分清 input token 和新生成 token。若把完整 prompt 當作生成文字傳回，evaluation 便會誤導。

對簡單例子，檢查續寫是否合乎文法、是否與提供的 context 一致。後面的任務還需要獨立核實事實和任務要求。

深入學習，檢查理解

實例練習與學習檢查

對 [0.5,0.3,0.15,0.05] 套用 top-k=3，再除以 0.95 進行 normalize。然後解釋 temperature 調整與刪除 top-k 以外 candidate 的分別。

畫出附加一個 token 前後的 cache 內容。解釋為何即使長度不變，改動較早 token 仍會令重用失效。

當你能從 prefix ID、logit、token selection、append、cache update，一直追蹤到 termination 的完整 generation step，就準備好了。

深入學習，檢查理解

cached 計算與改變的 prefix

考慮在「I go.」後生成文字。cached key 和 value 代表所選 model 下這兩個特定 input position。對 causal model，附加 to 時可以重用較早 state，因為未來 input 不會改變過去的計算。

把 prefix 換成「You go.」。長度仍是二，但第一個 token embedding 和所有依賴它的較早 state 都可能不同。只按 prefix 長度索引的 cache，會傳回錯誤計算。

現在保持可見 user sentence 不變，卻修改 chat prompt 的 system instruction。完整 token prefix 又變了。cache identity 必須反映真正先前的 token 和相關 model configuration，不能只看人眼見到的最後一條問題。

這個例子將數值 optimization 與正確性連起來。只有重用的 state 屬於你真正想執行的計算，節省計算才有意義。
