完整講義

閱讀完整解說

測驗需要評分規則

向手冊 assistant 提出十條問題。執行之前，先決定每個 answer 需要哪些 fact 和 source。否則看到流暢答案之後，很容易才說它「好」。

分開 retrieval evidence、answer correctness、completeness、citation support，以及適當指出資料不足的行為。同時記錄 failure 和 resource use。

Benchmark 是一份小型 behavior specification。它可能不完整或帶有 bias，因此設計時應像 model configuration 一樣認真。

Recall、hit rate 和 reciprocal rank

設必需 evidence 為 {H2,H3}，retrieved result 為 [H1,H2,H4]。因為找到一段 relevant passage，Hit@3=1；因為只找到一半必需 evidence，Recall@3=1/2；第一個 relevant item 排第 2，所以 reciprocal rank 是 1/2。

對沒有 relevant passage 的 unsupported question，一般 recall 分母是 0。標記為不適用，並另外評估 answer/refusal behavior。

當可能需要多個 source 時，不要把 hit rate 改名為 recall。這會掩蓋較難任務中缺少 evidence 的問題。

Answer 可以有支持，卻不完整

如果問題問 time 和 fare，“The bus leaves at 07:30 [H2]” 有支持但不完整；“The bus leaves at 07:30 and costs 2 dollars [H2]” 則加入了 unsupported fare。

Rubric 應指出必需 fact，以及 unsupported 或 contradicted claim。Exact substring matching 可以作有用的 smoke test，但會漏掉 paraphrase、contradiction 和錯誤對應關係。

在有量度的 subset 上，human review 仍然有用。報告 sample size 和 disagreement，而不要把人手判斷當成永遠正確。

Coverage 和 selective accuracy

假設 assistant 回答了 20 條問題中的 15 條，其中 12 條答對。已回答問題的 accuracy 是 80%，coverage 是 75%。

Overall correctness 也取決於其餘五次 refusal 是否適當。全部拒答可以減少 unsupported assertion，卻令產品毫無用處。

按預期 task distribution 評估這個平衡。Similarity threshold 是在 development data 上選出的值，並非 probability guarantee。

Training、development 與 held-out evaluation

Training data 改變學到的 parameter；development example 指導 prompt、threshold、chunking 和其他 setting；held-out example 則估計作出這些選擇後的 performance。

在生成近乎重複的 question 或重疊 chunk 之前，先按有意義的 group 劃分。對 RAG，inference 時仍可讀 indexed reference document；leakage 指的是用 held-out question 或 label 來選擇 system。

如果看過 final test error 後再 tuning，後續分析應標示為 exploratory，並為下一次 final claim 保留全新、未接觸的 case。

在相同任務上比較兩個 system

如果 A 解決 32/40，而 B 解決 34/40，觀察差距是五個 percentage point。檢查 paired result：B 修好了哪些 error，又製造了哪些新 error？

Paired bootstrap 重抽 task index，並用配對 output 計算差距。Question family 之間的 correlation，可能令天真的 individual-task resampling 過分樂觀。

面對 interval 和小 sample，應審慎陳述 uncertainty。「平均值較大」本身不足以證明可靠改善。

用計算例子理解 nDCG 的 graded relevance

若不同 evidence 的用處有高低之分，先為它們標示 relevance grades。使用 gain=2^grade−1 和 discount=log2(rank+1)。若回傳 grades 是 [0,2,1]，DCG@3 = 0/1 + 3/log2(3) + 1/2 = 2.39279。理想排序 [2,1,0] 的 IDCG@3 = 3 + 1/log2(3) = 3.63093。兩者相除，nDCG@3 約為 0.65900。報告應列明這個 gain convention；另一 convention 會得到不同數字。若全部 grades 都是零，要說明如何處理 ideal denominator 為零的情況。

分清 context precision、faithfulness 和 correctness

簡單的 binary context precision，是 relevant retrieved chunks 數目除以所有 retrieved chunks。若 [H2,H1,H3] 包含所需 H2 和 H3，precision 就是 2/3。部分 evaluation frameworks 使用 rank-weighted average precision 或 judge-based 定義；應記錄確切 formula，而非直接比較名稱相同的 scores。

在明確的 faithfulness rubric 下，把 answer 分成可核對 claims，再數出 supplied evidence 支持多少項。「The bus leaves at 07:30, costs 4 dollars, and has Wi-Fi」有三項 claims。若只有首兩項獲支持，這個 rubric 下的 claim faithfulness 就是 2/3。Faithful answer 亦可能重複過時 source，因此 factual correctness、source version、completeness 和 citation support 仍需分開檢查。

Paired test 檢查哪些答案真正改變

McNemar’s test 在同一組 tasks 上使用 paired binary success。假設 B 修正 A 的 8 個錯誤，而 A 在 B 失敗的 2 個 tasks 成功；兩者一致的 30 個 tasks 並不決定這個 test。若 success rates 相同，10 個 discordant outcomes 應有相同機會偏向任何一方。Exact two-sided binomial 計算得到 p≈0.1094，因此這個小例子對可靠差異的證據有限。除 p-value 外，亦應報告 effect size 和 paired counts。

Paired bootstrap 可估計 continuous scores 和 binary scores 差異的不確定性；McNemar 則專門處理 paired binary outcomes。兩者都需要合適的 independent units。相關 paraphrases 應分組，而非當作很多 independent tasks。若 test questions 或 answers 進入 training、prompt tuning 或 selection，就出現 benchmark contamination；pretraining overlap 亦可能推高 public benchmark 成績。應保留 provenance、檢查 near-duplicates，並加入全新 held-out tasks。

Model judge 與 operational metric

LLM judge 可以大規模套用 rubric，但可能偏好某些措辭、長度或熟悉的 model style。用已 review 的 example calibration，並檢查 disagreement。為 judge 和 prompt 記錄 version。

記錄 parse error、timeout 和 budget failure。它們必須保留在分母內，或放入明確指定的 outcome category。

除了 quality，也記錄 latency 和 token。某方法用了五倍 inference budget，多解決兩個 task，仍可能有用，但應明確說明取捨。

實例練習與學習檢查

對 gold {A,B} 和 ranking [C,A,D] 計算三種 retrieval metric。然後標示一個有支持但不完整的 answer，以及一個看似完整卻沒有支持的 answer。

準備固定的小型 development evaluation，加入 adversarial case，並產生 per-example record。撰寫同時包含 evidence 和 limitation 的 release recommendation。

當 evaluation 能解釋 system 在哪裏成功、哪裏失敗，而不只給一個 judge score 或漂亮示範，就已準備好繼續。

參考細節與學習檢查

複習 A：直觀理解

你的 benchmark 是一份小型、不完美的預期 behavior specification。它應包含具代表性的成功、困難 case，以及明確沒有答案的情況。單一平均 judge score 難以支持 release decision。要儲存底層 example、judgment 和 slice。

按用途劃分：training/adaptation、development/tuning，以及 final held-out evaluation。如果近乎相同的 page family 或生成 paraphrase 會洩漏答案，就避免它們跨越邊界。Retrieval 在 evaluation time 可以閱讀 indexed reference document；leakage 的問題是用 held-out question、label 或 near-duplicate 去 tune system。必須準確分清兩者。

複習 A：每個 boundary 的 metric

以 labeled evidence 評估 retrieval；按 required fact 評估 answer correctness；在 structural 和 semantic 層面評估 citation validity；也評估 unsupported claim、適當 refusal、task completion、latency、token 和 failure。之後學 agent 時，還要評估 tool correctness、forbidden action 和 budget exhaustion。明確列出分母，包括 timeout 和 parse error。

LLM judge 可以提供可擴展、按 rubric 評分的協助，但會受措辭、answer length 和自身 model family 影響。用 human-labeled example calibration；pairwise comparison 時隨機排列 answer；檢查 disagreement；保留 judge prompt/model version。不要把同一 model 的 self-confidence，當作 correctness 的唯一 evidence。

複習 A：Uncertainty 例子

如果 system A 答對 32/40，B 答對 34/40，觀察差距是 5 個 percentage point。這不會自動成為有意義的改善。檢查 paired difference：可能 B 修好 A 的四個 error，卻新增兩個。Paired bootstrap 重抽 task index，保持 pairing，再計算差距。Sample 很小或有 correlation 時，uncertainty 仍大；應報告 interval 和 assumption，而不是因多答對兩題就宣稱較優。

複習 A：實驗

Tutorial 21: 評估 retrieval、答案與 uncertainty 實作 retrieval metric、paired resampling 和 JSON evaluation record。至少加入五個 adversarial case，包括 version mismatch、無關但 high-overlap 的 evidence、missing answer、page 內的 fake instruction，以及 multi-source question。用 development data 選 threshold；held-out set 只在計劃好的 checkpoint 執行。

Starter 的 structural test 建立 software behavior 和 metric arithmetic 的正確性，但不能證明 natural-language grounding。你的 manual scoring rubric 必須為每個 task 指出 required fact 和 unsupported statement。保留簡短 error notebook，包含 original question、expected evidence、actual output、diagnosis 和下一個 hypothesis。

完成標準： 以 per-example evidence 和 uncertainty 支持 release recommendation。 閱讀材料： Hung-yi Lee Introduction to GenAI and ML 2025 (R03) 的 evaluation 主題； Stanford CS336 Language Modeling from Scratch (R01) 的 evaluation lecture heading。 Tutorial： 21.
