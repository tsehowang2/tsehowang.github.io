完整講義

閱讀完整解說

一本簡單的學校手冊

想像手冊有三段內容。H1 寫着 “School opens at 08:00.”，H2 寫着 “The school bus leaves at 07:30.”，H3 寫着 “A ticket for the school bus costs 4 dollars.”。一名學生問：“When does school start?”

Search 的任務，是為這條問題選出有用的段落。問題用了 start，H1 卻用了 opens。完全相同的字詞比對可以找到 school，但也可能找到關於 bus 的段落。好的 representation 應有助分辨真正有用的 evidence 和只是相關的文字。

我們刻意先學 representation 和 transformer，才開始這個應用。現在，“embed the question” 指的是一種具體的數值運算，而不是未加解釋、像魔法一樣的 API。

先建立 lexical baseline

Lexical retriever 比較字詞或 term。Inverted index 把一個 term 對應到包含它的段落。Term weighting 可以減低常見字詞的影響，並強調更有辨識力的 term。

對於 school 何時開始這條問題，簡單的 overlap 方法可能同時給 H1 和 H2 分數。這種失敗不難理解：方法沒有學過 start 與 opens 的關係，也可能無法清楚分辨主要主題。

BM25 是常用的 lexical scoring 方法系列，包含 term-frequency saturation 和 length normalization。我們會把它與 semantic 方法比較，而不會假設 neural vector 對所有 query 都更好。遇到精確的 API 名稱和 error code 時，準確的 lexical matching 往往很有幫助。

Sentence embedding 為特定任務表示輸入

Transformer encoder 可以產生帶有 context 的 token vector。Pooling 或其他 representation 程序會建立 passage 或 sentence vector。之後，training 會鼓勵這些 vector 形成適合目標比較任務的 geometry。

為 retrieval 訓練的 embedding model，目標是讓相關的 question-passage pair 在選定的 similarity function 下取得好分數。隨意平均 token row 是另一種方法，有不同的限制。

在 bi-encoder 中，question 和 passage 可以獨立 encode。Passage vector 只需儲存一次，之後可重複用於很多問題。這種重用解釋了為甚麼 dense retrieval 能擴展，而不必對每條 query 都重新與每個 passage 一起處理。

一個小型數值排名例子

使用設計出來的 unit question vector q=[1,0]。設 H1=[0.9,√0.19]、H2=[0.6,0.8]、H3=[0,1]。三個 passage vectors 的長度都等於一。它們與 q 的 dot product 分別正好是 0.9、0.6 和 0。H1 的第二個 coordinate 約為 0.43589。

H1 排第一。這些座標是為了方便計算而設計，並非真實 embedding model 的量測輸出。給定 vector 後，排名運算是確定的；但 vector 是否表達了正確的 relevance，仍需要實驗驗證。

在 tutorial 中，以真實 model embedding 取代人為座標。固定 question set 和 evidence label，讓實驗測試 representation 本身，而不是一個精心挑選的示範。

Retrieval embedding 可以怎樣訓練

Positive pair 由一條 question 和一段能支持答案的 passage 組成；negative pair 則不能支持答案。Contrastive objective 可以提高 positive score 相對於其他競爭分數的值。

Hard negative 與問題相似，但答案不對。對 “When does school open?” 而言，bus 的 departure time 就是有用的干擾項。另一個例子，是描述不同年份 school opening time 的段落。

如果被標為 negative 的 passage 其實提供有用 evidence，就出現 false negative。因此 dataset 的建立方式很重要。Embedding space 反映 objective 和 label，並不是客觀、通用的「意思量尺」。

三個問題的 contrastive training 例子

回到 school handbook。Q1 是「When does school start?」，Q2 是「When does the school bus leave?」，Q3 是「How much does a ticket for the school bus cost?」。相應的支持 passage 分別是 H1、H2 和 H3。我們先標示這些 positive pairs，然後才 training。在這個小例子中，其他 passages 並不能回答該問題。

bi-encoder 分別 encode 每個問題和 passage。下表使用設計出來的 training logits，視作已完成 similarity scaling，方便計算 objective。這些並非原始 cosine similarities：cosine 不可能等於 2。較大的 logit 會令配對相對其他 candidates 得到較高 probability。

問題 H1 H2 H3
Q1 2 1 0
Q2 0 2 1
Q3 1 0 2

Q1 的 positive passage 是 H1。對 row [2,1,0] 使用第 4 週學過的 softmax。這次計算的 temperature 設為 1，normalize 後的 candidate probabilities 約為 [0.66524,0.24473,0.09003]。這些 probability 描述 training 時在三個 candidates 之間的選擇，並非 passage 真實或足夠的 calibrated probability。

Q1 的 loss 是 H1 probability 的 negative natural logarithm：−ln(0.66524)，約為 0.40761。Q2 和 Q3 的 score pattern 相同，只是 positive 位於不同 column，因此三個 rows 的 mean loss 亦約為 0.40761。我們希望 positive 相對其他 passages 得到較高 score，而非單純令所有 similarity scores 一起上升。

要看清學習方向，在 temperature 為 1 時，這個 row loss 對三個 scores 的 derivative 約為 [−0.33476,0.24473,0.09003]。因此，gradient descent 在目前位置會把 positive score 向上推，把其他 scores 向下推。真實 model 的 backpropagation 會沿著 score，經過 question 和 passage encoders，更新可訓練 parameters。我們並不是把這個小型 score table 當成 model 儲存。

Temperature 把 cosine similarity 連接到 training logits

之前的 [2,1,0] row 是 temperature 為 1 的教學例子。常見的 retrieval setup 會先 normalize embeddings、計算 cosine similarities，再除以 temperature τ：logits = cosine/τ；等同乘以 scale=1/τ。合適的 scale 由 model 和 objective 決定；training library 可以固定或學習它。

假設 cosines 是 [0.8,0.6,0.2]，τ=0.05，則 logits 為 [16,12,4]。Stable softmax 給 positive candidate 的 probability 約為 0.982008，positive loss 約為 0.018156。同樣的 cosines 在 τ=1 時，probability 約為 0.422379，loss 約為 0.861852。Temperature 會改變 distribution 的尖銳程度和 gradient scale，因此之前例子的 loss 約 0.41 並非通用的實際訓練目標。

false negative 會改變 model 學到甚麼

現在把 H2 換成「Classes at this school begin at 08:00.」。對 Q1 而言，這亦是有用答案，並非 negative。若只把 H1 標為 positive，model 成功配對 H2 反而會被懲罰。假如 Q1 scores 從 [2,1,0] 變成 [2,2,0]，single-positive loss 會升至約 0.75862，儘管第二個支持 passage 的 score 已改善。問題在於 label 假設。把同一 batch 的其他項目當成 negatives 前，先檢查 duplicates 及多個有效答案的情況。

bi-encoder retrieval 與 cross-encoder reranking

bi-encoder 預先儲存 passage vectors，再用新問題與它們比較。cross-encoder 則把問題和一個 candidate passage 一起讀入，產生 pair score。它能直接查看兩者的 token interactions，但每個選定 pair 都需要經過 model 處理。常見做法是先用 bi-encoder retrieve 少量 candidates，再用 cross-encoder rerank [ Sentence Transformers retrieve and rerank (R28) ]。若支持 passage 根本沒有進入 candidate set，reranker 亦無法把它找回來。

檢查理解：指出 table 每個 row 的 positive column；重算 Q1 的 softmax 和 loss；解釋為何另一段正確的 school-opening passage 不應自動成為 negative。這是一種常見的 contrastive setup [ Sentence Transformers contrastive losses (R27) ]，並非 training embedding model 的唯一方法。

按 model 要求準備 query 和 passage

embedding checkpoint 亦包含 input recipe。有些 retrieval models 以 prefix 區分輸入，例如「query: When does school start?」和「passage: School opens at 08:00.」。其他 models 可能使用 instruction template，或不需要 prefix。應依照該 model card 和 query/document encoding methods，包括 pooling、normalization、maximum length 和 truncation。對所有 models 隨意加入 prefix 並不會自動改善結果。

一個 vector、多個 vectors，或 sparse term weights

Matryoshka-trained embedding 把有用資訊放進 vector 的不同長度 prefixes。若 model 曾針對 64、128 和 256 dimensions training，你可選擇支援的 prefix 長度，按需要重新 normalize，再比較 quality/storage tradeoff。普通 embeddings 沒有這個特性；把任意 256-dimensional vector 切成首 64 個數值，可能丟失重要資訊。

ColBERT 保留 passage 的多個 contextual token vectors，而非全部 pooling 成一個 vector。其 late-interaction score 讓每個 query token 找出最高的 passage-token similarity，再把這些 maxima 加起來。對 query tokens「bus fare」，假設兩個 passages 的 maximum similarities 分別是 [0.9,0.2] 和 [0.7,0.8]，示範 scores 就是 1.1 和 1.5；第二段涵蓋兩個概念較好。Passage representations 可預先計算，但儲存多個 token vectors 通常需要更多 index 空間。

SPLADE 採用另一條路：neural encoder 產生 vocabulary terms 上的 sparse vector，並學習 term expansion。輸入「bus fare」的 query，即使沒有打出「ticket」，亦可能給該 term 權重。Inverted index 可以比較 nonzero term weights。這與 BM25 的人工設計 term weighting，以及 compact dense vector 都不同。各方法針對不同 matching 和 storage 要求，應以相同問題評估。

Relevance 需要 label 和明確定義

對原本的問題，H1 是 relevant。對 “How much does the school bus cost and when does it leave?”，H2 和 H3 都是必需的。只有一段相關 passage，未必足以完成整個任務。

Hit@k 問的是前 k 個結果中，是否至少有一段 relevant passage。Recall@k 問的是所有必需的 relevant passage 中，有多少比例被找出。我們會在第 21 週仔細計算兩者。

對於 “What color is the headteacher's car?” 這類沒有支持資料的問題，這本小手冊沒有對應 passage。Retriever 仍可以回傳最近的 vector；但「最近」不代表「足夠」。

逐步轉向 technical documentation

當 passage 描述 API parameter 而非學校時間表時，結構一樣適用。精確名稱、version constraint 和 code block 會變得重要。容易理解的手冊例子先教機制，documentation corpus 再提供較難的情境。

選定一個固定的 corpus revision，保留 passage ID 和 source provenance。Question label 要與 training 或 configuration tuning 分開。不要在看到新 retriever 擅長哪些問題之後，才挑選 evaluation question。

為 “When does the bus leave and what does a ticket cost?” 標示必需的 evidence。解釋為甚麼只找出 H2 時，Hit@1=1，但 Recall@1=1/2。

分別以 lexical search 和真正的 dense search，比較一條 paraphrase question 及一條 exact identifier question。儲存原始排名，並為每種方法記錄一個失敗例子。

參考細節與學習檢查

複習 A：直觀理解

Retriever 必須把有用 evidence 排在前面，而不只是找出相關文字。精確的 API 名稱和 error code 較適合 lexical matching；改寫過的意圖可能較適合 semantic matching。先準備這兩類問題和簡單 baseline。選擇 scoring 方法，是因為它針對已觀察到的失敗，而不是因為名字有 “vector”。

Inverted index 把 term 對應到符合的 document。TF-IDF 會提高「在 document 中常見、在 corpus 中罕見」的 term 的權重。BM25 再加入 term-frequency saturation 和 document-length normalization。Dense retrieval 把 query 和 passage encode 到共同的 vector space，再作比較。Lexical baseline 為 dense retrieval 提供重要對照，尤其適用於 technical symbol。

複習 A：Relevance 與 metric

設 G 為 relevant evidence ID 的集合，Rk 為首 k 個回傳 ID。Recall@k 為 |G intersection Rk| / |G| 。只要有任何 relevant item，Hit@k 就是 1。Reciprocal rank 為 1/r ，其中 r 是第一個 relevant 結果的排名；若沒有則為 0。當 relevant passage 不只一段時，Hit@k 和 Recall@k 回答的是不同問題。只要定義好 relevance label 和 normalization，NDCG 可以表示不同程度的 relevance 及位置折扣。

複習 A：計算例子

假設 G={A,B}，首三個結果是 C,A,D，則 Hit@3=1、Recall@3=1/2、reciprocal rank=1/2。報告如果把 Hit@3 稱為 “recall”，就會掩蓋缺少第二段 evidence 的問題。若比較任務需要兩個 version，缺少這段 evidence 可能令問題根本無法作答。

對沒有 relevant evidence、無法回答的問題，一般 recall 的分母是 0。不要默默當作 perfect recall。應以 refusal、false-positive retrieval 或 unsupported-answer measure，另外評估這類問題。Starter 把它們的 retrieval metric 標為不適用。

複習 A：實驗

Tutorial 18: 從一列 vector 建立 vector database 比較內附 lexical retriever 和真正的 sentence-transformer embedding。固定 document chunk、question、version filtering 和 k。加入 exact identifier、paraphrase 和 wrong-version distractor。先儲存每條 query 的排名，再計算平均值；平均數可能掩蓋某一整類系統性失敗。

分清 model failure 和 ingestion failure。檢查預期 passage 是否真的在 index 裏、truncation 有沒有刪去關鍵句，以及 metadata filter 是否排除了它。真正的 capstone 要標示足夠多類問題，避免單一例子主導某個 slice。小型 teaching fixture 用來協助檢查 software correctness，並不足以充當 research dataset。
