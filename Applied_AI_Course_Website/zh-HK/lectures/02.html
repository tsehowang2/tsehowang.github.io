由例子開始

為何 model 需要 representation

我們看得懂「I go to school by bus」，但數值 model 需要一套可重現的方法來表示它。先用一個簡單規則：「遇到空格就分開」。句子變成六個 token：I、go、to、school、by、bus。Vocabulary 列出 model 認識的 token 類型。

分配 ID：I=0、go=1、to=2、school=3、by=4、bus=5。句子就變成 [0,1,2,3,4,5]。ID 是標籤。School 的 ID 比 go 大，不代表 school 更有意義。如果我們一致地調換 ID 和相應 model tables 的排列，標籤本身不會改變任務。

要分清三樣東西：原始文字、token sequence 和 ID sequence。Tokenizer 決定轉換方法；vocabulary 決定哪些 ID 對應哪些 token 字串；model 透過 representation layer 使用這些 ID。

由例子開始

標點暴露出按單字分割的弱點

比較「bus」和「bus.」。單純按空格分割，會把它們視為不同字串。那麼「school-bus」、「school bus」或拼字錯誤又如何處理？把每個可能的字形都當成獨立 vocabulary 項目，會產生大量罕見項目，也難以處理未見過的字。

Character tokenizer 則把 b、u、s 和標點分開表示。它的基本項目較少，但 sequence 會較長。Subword tokenizer 使用介乎完整單字與 character 之間、可重用的片段。常見字可能只用一個 token，較罕見的字則拆成數個片段。

沒有任何規則規定一個 token 等於一個單字。使用真正 model 時，必須檢查它實際採用的 tokenizer。按單字分割仍適合教學，因為我們可以逐個 ID 手算追蹤。

建立對機制的理解

Vocabulary 必須先學好或選好，才投入使用

假設 vocabulary 包含完整 token school 和 schools，卻沒有 schoolyard。Word-level 系統需要 unknown-token policy。Subword 系統可能用 school 和 yard 編碼 schoolyard，也可能按學到的 vocabulary 使用其他片段。

Tokenization 必須與訓練好的 model 相容。如果 training 時 ID 5 代表 bus，inference 時卻代表 train，即使兩者都是有效整數，model 收到的 representation 仍然錯了。因此，model checkpoint 和它的 tokenizer 必須配套使用。

Special token 可以標示 sequence 的開始或結束、padding，或對話邊界。確切意思取決於 model。我們稍後才會介紹 conversation template，不會假設「assistant」這類看得見的字，自動就是特殊角色標記。

建立對機制的理解

用小例子理解 byte pair encoding

考慮 low、low 和 lower。由 character 和結束標記開始：l o w _、l o w _、l o w e r _。點算相鄰 pair。l,o 出現三次，o,w 也出現三次。採用固定的同分處理規則，把 l,o 合併成 lo。重新點算；lo,w 現在出現三次，於是合併成 low。

這個 algorithm 從常見的相鄰模式建立可重用片段。實際 tokenizer 還有更多細節，包括初始 alphabet 和文字 preprocessing。我們的例子只是解釋 merge 的概念，並非聲稱重現某個正式使用的 tokenizer。

編碼新文字時，要套用已儲存的 merge rules，不要為每個句子各自重新訓練 tokenizer。否則，model 學好的 parameter 所依賴的 input vocabulary 會不斷改變。

建立對機制的理解

透過 lookup table，把 ID 變成 vector

Embedding table 為每個 vocabulary 項目儲存一個學習得到的 vector。如果 table 有六行，而每個 vector 有三個 coordinate，它的 shape 就是 [6,3]。查找 bus，即 ID 5，就會選出 row 5。

為方便說明，假設 bus 的 vector 是 [0.2,0.8,0.1]，school 是 [0.9,0.1,0.4]。這些數字只是為了追蹤計算而虛構，並不表示第一個 coordinate 真的代表教育，或第二個代表交通。

這個六個 token 的句子，現在變成六行三列的 matrix。每行對應 sequence 中的一個 position。第 3 週會研究 vector geometry；之後 attention 會結合這些 row 之間的資訊。

深入學習，檢查理解

One-hot encoding 與 lookup 選取的是同一行

ID 5 的 one-hot vector 有六個 coordinate，除了 index 5 是一，其餘全是零。把這個 row vector 乘上 [6,3] embedding table，會選出與 lookup 相同的 row。這個等價關係從數學上解釋了此操作。

實作通常採用有效率的 indexing operation，而不是實際建立龐大的 one-hot matrix。兩者的分別，在於同一選取操作的數學描述，以及有效率的程式實作。

此時 bus 的 vector 還不取決於所在句子。不論 bus 出現在哪裏，lookup 都產生相同的起始 row。之後的 contextual processing 才會利用周圍 token 改變 representation。

深入學習，檢查理解

長度與 decoding

如果 word tokenizer 產生六個 token，而 character tokenizer 產生二十一個，同一段文字就會讓 model 處理不同長度的 sequence。長度會影響後續步驟所需的計算量和 memory。

Decoding 按 tokenizer 的規則，把 ID 轉回文字。空白與 special token 要特別留意；把 token 字串用空格接起來，並不是通用的 decoding algorithm。檢查 round-trip 行為時，要保留原始字串。

Tutorial 會比較簡單的 word tokenizer 和 UTF-8 bytes。Byte count 有助檢查 encoding，但不能代替 pretrained model 的 token count。

深入學習，檢查理解

實例練習與學習檢查

為「I go to school by bus」和「You go to work by train」建立 vocabulary。決定如何表示句號和結束標記。編碼這兩個句子，再 decode 回文字。然後在 vocabulary 沒有 bicycle 的情況下，編碼「I go to school by bicycle」。

說明你的 unknown-token policy，並解釋為何另一個 tokenizer 可以透過較小片段避開這個特定 unknown。若 vocabulary 有 100 項、vector width 是 16，計算出 embedding parameters 有 1600 個。若句子有七個 token，寫出它的 representation shape 為 [7,16]。

當你能解釋 ID 為何只是標籤、tokenizer 為何必須配合 model，以及 ID 如何選取 vector，就準備好繼續。理解這一層，不需要 sentence similarity 服務或 database。
