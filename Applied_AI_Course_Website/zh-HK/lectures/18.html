由例子開始

當清單改變時，persistence 就派上用場

上週，我們可以把三個手冊 vector 放在 memory 中直接比較。現在想像有數千個 passage、每學期都有更新，而且重新啟動程式之後仍有人提出問題。

Vector database 協助在這些操作之間維持 vector 及其相關資料。先從一個 point 開始：它包含 ID、vector、source text reference 和 metadata。Database 負責按其支援的行為儲存和搜尋這些 point。

Embedding model 建立 vector；similarity metric 定義比較方法；index 組織 search；database 則加入管理和操作能力。這些 component 互相關聯，但各有不同職責。

由例子開始

一筆可直接檢查的 record

把 H2 表示為 ID=bus-2026、vector=[...]、version=2026、source=handbook transport section，以及 content hash。如果規則曾改變，關於 2025 的問題不應默默採用 2026 規則。

Metadata filter 限制哪些 passage 可以成為候選。更新期間，text、vector 和 version 必須一直保持對應。即使 nearest-neighbor algorithm 正確，也無法修復 ingestion 時標錯 version 的 record。

Stable ID 有助更新現有 passage，避免不斷累積 duplicate。確切的 update semantics 視乎 database API，並需要 save/reload test 驗證。

建立對機制的理解

以 exact search 作參考

Exact search 把 query 與每個符合條件的 stored vector 比較，再按 metric 選出最佳結果。對小型 collection 而言，它可能已完全足夠。

隨着 collection 增大，approximate nearest-neighbor 方法可以用額外結構和資源，換取較少的 search 工作。這裏的 approximation 針對選定的 vector metric；如果 embedding 質素差，即使 exact vector neighbor 也可能在語意上無關。

要分開這兩種 error source：approximation 可能漏掉 exact neighbor，而 representation quality 則可能令 exact neighbor 對問題沒有幫助。

建立對機制的理解

用 graph 理解 HNSW

Approximate graph index 把 point 連接起來，讓 search 沿着有希望的 neighbor 前進，而不必檢查每個 point。HNSW 使用多層、可導航的 graph hierarchy。

可以直觀地想像成沿着越來越局部的連接在地圖上尋路，但真正的結構是 vector-space point 和 algorithmic rule。Search breadth 和 construction setting 會影響 recall、latency 和 storage。

用同一批 query vector 和相同 metadata constraint，比較 approximate result 與 exact result。Local mode 的九個 teaching point，不能證明 production HNSW 的效能。

建立對機制的理解

在選 candidate 之前還是之後 filtering

假設未 filtering 的前三個結果全屬於 2026，但問題問的是 2025。先取三個結果再刪去錯誤年份，可能甚麼都不剩，儘管 relevant 的 2025 evidence 其實存在於未 filtering 排名更後的位置。

透過 search mechanism 套用必需 constraint，並評估 filtered 行為。在 private system 中，authorization 必須由 application/database control 強制執行，而不能依靠 model 生成的建議。

在公開的 teaching corpus 中，version filtering 是 scope constraint。不應把它說成完整 authentication 或 multi-tenant security。

建立對機制的理解

Storage 計算與 compatibility

一百萬個 384-dimensional float32 vector，原始 vector 大小是 1,536,000,000 bytes。這還未包括 graph link、ID、payload、text、replica 和 allocation overhead。

兩個輸出 dimension 同為 384 的 embedding model，不一定共享 coordinate system。即使 database 接受相同 vector length，更換 model 通常仍需要重新 embedding，並建立 compatible index。

記錄實際 model/tokenizer revision 和 source manifest。Dimension checking 可以找出一類 mismatch；identity checking 則找出另一類。

建立對機制的理解

Update、deletion 與 migration

如果手冊修改了 bus departure time，就要更新 source record 及依賴它的 vector/index state。如果某 passage 被移除，要確保其 index entry 和任何 cached answer 都獲處理。

進行 model migration 時，先建立另一個 compatible collection，驗證 point count 和 ID，benchmark retrieval；只有通過所選 gate 後，才切換 active collection。保留較早 collection，才能一致地 rollback。

這正是 data engineering 的嚴謹做法直接發揮作用的地方。即使 vector representation 是學出來的，它仍需要 lineage、schema check 和 lifecycle。

建立對機制的理解

實例練習與學習檢查

把 local collection 儲存、關閉，再重新開啟，重複一次 filtered query。用同一 ID 更新一個 point，確認內容已改變。刪除另一個 point，再確認它已不存在。

解釋失敗的 query 是由 ingestion、filter、embedding representation 還是 approximation 引起。設計一個 test，區分其中兩種原因。

當你理解 “vector DB” 是一個持續維護的 collection 和 search service，並有明確 compatibility 與 update 行為，而不是 embedding model 的同義詞，就已準備好繼續。

選讀：深入學習

深入研習 12：直觀理解

一串 vector 和 cosine score 可以示範 semantic search。Vector database 再加入 persistent collection、metadata、update、filtering 和 operational behavior。這些能力很重要，因為 documentation 會改變，而使用者仍持續 query。Index 是有 lifecycle 的 artifact，並非一次性的 preprocessing 步驟。

每個 point 應儲存 stable ID、embedding、source reference、version、content hash 和 payload。在 collection manifest 記錄 embedding model 和 tokenizer revision。兩個 model 即使都輸出 384 個數字，也可能產生不相容的 geometry。Model migration 通常需要重新 embedding，並建立或重建 index；不要只因 dimension 一樣就混用 vector。

選讀：深入學習

深入研習 12：Exact 與 approximate search

Exact nearest-neighbor search 評估所有 candidate，提供有用參考。Approximate nearest-neighbor search 在工作量、storage 和 retrieval quality 之間取捨。HNSW 建立可導航的 graph；search breadth 會影響速度與 recall。Index setting 必須在真實 metadata filter 下與 exact result 比較，而不能只用未 filtering 的隨機 benchmark。

當只有少部分 document 符合條件時，filtered search 的行為可能不同。先取一小串 top-k 再套 version filter，即使 relevant document 存在，也可能沒有有效 candidate。透過 retrieval mechanism 套用 constraint，並量度結果。與 security 有關的 authorization filter 不可交由 language model 執行。

選讀：深入學習

深入研習 12：Migration 例子

假設 index A 包含 model M1 的 vector 和 10,000 個 source chunk。使用 M2 和相同 source manifest 建立 index B。檢查 row count、missing ID、embedding dimension 及 development retrieval benchmark。先把有限 evaluation workload 導向 B，只有通過 gate 後才切換 active index。保留 A 作 rollback。如果 document 同時改變，也要把這點記錄為獨立 experimental variable。

Deletion 同樣重要。從 object storage 移除 document，不會自動刪掉它的 chunk、cached answer 或 replicated index entry。要定義 tombstone/update policy 和 completion check。

深入研習 12：實驗

Notebook 18 建立 local Qdrant collection、upsert vector、按 version filtering、儲存後重新開啟，再次 query。直接檢查 payload。以相同 ID 加入一次 update，然後刪除一個 point，確認它不再出現。Local mode 教的是 client 和 lifecycle；不能證明 distributed durability 或 production throughput。
