Prediction 只能使用可用資訊

Training 時，我們有完整句子「I go to school by bus.」。在 by 後面的位置，model 必須只用 prefix 預測 bus，即使 training tensor 右邊已經包含答案。

Causal mask 防止 query position attend 到未來 position。若 index 從零開始，query i 只可使用 j≤i 的 key。Diagonal 保持可見，因為當前 input token 本來就是用來預測 next token 的 prefix 一部分。

這是 information-access rule，與是否把某個 position 計入 loss 是兩回事。Padding mask、causal mask 和 loss mask 各有用途。

簡潔的 attention equation

標準 single-head 表達式是 softmax(QKᵀ/√d_head + mask)V。要把它讀成一連串操作：比較 query 與 key、scale score、移除禁止 position、normalize 每個 query row，再混合 value。

對 T 個 position，Q/K 的 shape 是 [T,d_head]，score 和 weight 是 [T,T]，V 是 [T,d_value]。Output 是 [T,d_value]。

不要把整個表達式當成不可拆開的符號去背。如果 implementation 出錯，要逐個檢查 intermediate tensor。小型 input 比大型 model 的最終 loss，更容易揭示錯誤。

Scaling 的完整計算例子

取 q=[1,0]，key 為 [1,0] 和 [0,1]，value 為 [2,0] 和 [0,4]。這裏 d_head=2，所以 score 是 [1/√2,0]，約為 [0.7071,0]。

Softmax 約得到 [0.6698,0.3302]。混合 output 是 [1.3395,1.3210]。兩個 position 都有貢獻。

現在假設第二個 key 位於未來。在 softmax 前，把它的 score 設為負無限。Weight 變成 [1,0]，output 變成 [2,0]。Masking 不只移除禁止項的貢獻，也會改變 normalization。

為何把 probability 乘零並不一樣

假設先計算未 masking 的 weight [0.6698,0.3302]，然後把第二個 weight 乘零。結果是 [0.6698,0]，總和不是一。Output 變成 [1.3395,0]，與正確 masking 的結果不同。

你可以重新 normalize 剩下的 probability，但在 softmax 前 mask logit，是直接而標準的實作。重點是理解自己想執行甚麼計算。

如果某行的所有 key 都被禁止，softmax 就沒有有效 normalization。設計 padding 和 batching 時，應確保每個受評估 query 都有適當的可見 key，或明確處理無效 row。

為何要除以 square root

在簡化假設下，query/key coordinate 互相獨立、zero-mean、unit-variance，它們的 dot product variance 會隨 d_head 增長。很大的 score magnitude 可以令 softmax 極度集中。

基於這個直覺，除以 √d_head 可以較好控制 scale。這不保證學習得到的 score 永遠服從特定 distribution，只是解釋 scaling term 的動機。

試用有很多 random coordinate 的 vector，比較 scaling 前後的 score spread。要檢查統計數字，不要直接斷言較尖銳的 attention map 就比較好。

Padding 帶來另一項 visibility 條件

一個 batch 可以包含不同長度的句子。我們可以把較短句子 pad 到共同長度，但 padding position 不應像有意義的 source word 一樣參與。

允許使用的 key position 必須同時符合 causal rule 和 sequence 的 validity rule。未來 token 即使是真字，仍然被禁止。Padding token 即使位於左邊，也不會因此成為有用 context。

Loss masking 再決定哪些 target prediction 計入 objective。即使 attention masking 正確，如果拿 padding label 來 training，loss 仍然可以出錯。

用 invariant 找出 future leakage

固定 model parameter，並關掉 dropout 等 randomness。先跑一次 sequence，再只改變最後一個 token。較早的 causal output 應在指定 numerical tolerance 內維持不變。

這項 property 檢查實際行為，而不是只看 matrix 是否呈三角形。在合適例子中，移除 mask 應令同一 property 失敗。這個失敗證明測試能偵測目標 bug。

移除 mask 後 training loss 降低，可能是 answer leakage。在 tutorial 08，實作 attention 計算，執行 invariance check，再移除 mask，令 check 失敗。一個 [T,T] score matrix 每個 head 儲存 T² 個數值；未計 batching 或多個 heads，T 加倍已令這部分 storage 變成四倍。
