Application 複習

Sentence embeddings 在學得的 geometry 下支援 retrieval comparison。Vector database 維護相容 points、metadata 和 updates。

RAG 選 evidence，並以它 conditioning generation；answer checks 區分 support、completeness、absence 和 scope。Fine-tuning 以經審核 targets 和可量度 objective，改變 learned behavior。

Tools 提供狹窄 capabilities。Execution harness 控制 actions 和 budgets；evaluation harness 檢查 tasks 和 outcomes。

Operations 複習

Manifest 識別 model、prompt、tokenizer、index、source、adapter、tool、environment 和 evaluation dependencies。Service enforce contracts 和 resource behavior。

Monitoring 和 traces 支持 diagnosis。Authorization 要放在不可信 model/document text 以外。Release decision 依據事先公布 gates 和一致 rollback plan。

區分真正 public deployment、local deployment 和 proposed architecture。三者都可提供有用 evidence，但 claims 不同。

答辯應展示甚麼

展示一個清晰 problem、task set、baseline、一項 controlled improvement、raw examples、limitations 和可重現 run。

面對 “Why an agent?”，展示需要 adaptive decision 的 task，以及與 fixed workflow 的比較。面對 “Why fine-tune?”，展示重複 error、training intervention 和獨立 outcome。

若實驗未能改善 baseline，解釋發現，並 release 較好 system。不要把 negative result 改寫成虛構成功。

Terminology error 可用精確 definition 和 example 訂正。Mechanism error 需要 numerical trace 或 property test。Evaluation error 需要更好的 task 或 denominator。

這個訂正過程，會把 grade 轉成具體下一步 learning action。

聚焦的下一步

根據已觀察 weakness 選下個 experiment：retrieval misses、long-context reasoning、training-data quality、tool planning、multimodal extraction，或 serving efficiency。

避免同時向所有方向擴展。一項狹窄、經量度 improvement，可能比另一個未測試的廣泛 prototype，更能證明 delivery 能力。

持續閱讀 primary papers 和 official documentation，心中帶着 mechanism、shape trace 和可測試 question。你現在已有足夠結構，能更有效理解精簡解說。

實例練習與最終反思

記錄三項有 evidence 支持的 decisions、兩項未解決 limitations，以及一項聚焦的下個 experiment。包括 source/model provenance 和協助披露。

把工作描述為獨立 personal project，列出你實際產生的 dataset、model、implementation 和 measurements。只有真的發生過，才可稱 workplace 或 paid-client experience。

當另一人能運行 release、檢查 evaluation，並聽你從日常例子到較難 mechanisms 作清晰解說，就算完成課程。

深入學習 32：直觀理解

可信 delivery evidence 包括他人可運行的 artifact、可檢查的 evaluations，以及你能解釋支持的 reasoning。漂亮 demo 若同時展示 failure behavior、release constraints 和 claims 限制，就更有說服力。

Final project 是懂得區分 versions 的 documentation assistant，包含 semantic retrieval、source citations 和狹窄 executable tools。它包括已比較的 lexical baseline、bounded workflow 或 agent controller、經量度 adaptation experiment、API 和 operations evidence。若 fine-tuning 沒幫助，default deployed branch 可用 base model；經量度的 negative experiment 仍能展示良好 engineering。

選讀：深入學習

深入學習 32：最終審核

從乾淨 directory 開始，照 README 操作。驗證 source ingestion、artifact compatibility、index loading、inference（或明確記錄的 offline fallback）、test execution 和 example requests。記錄 environment details 和 dependency downloads。另一 reader 應能區分哪些可 offline 運行，哪些需要 model downloads 或 GPU access。

寫結論前，先凍結 raw final evaluation outputs。包含 task slices、適當 paired comparisons、quality 和 latency、tool safety、uncertainty 和 limitations。若 exploratory analyses 使用了 held-out results，要標示。絕不能把 template 的假設 metrics 當成 claimed measurements。

選讀：深入學習

深入學習 32：答辯實例

問題：“Why did you add an agent?” 有理據的 answer 會指出需要 conditional inspection 的 task、與 fixed workflow 比較，並展示 trace-level success/cost。“Agents are more advanced” 不足以支持選擇。問題：“Why fine-tune?” 有理據的 answer 會把可重複 error pattern 與 targeted objective 連起來，並報告 controlled comparison，包括 regressions。

選讀：深入學習

深入學習 32：提交要求

展示五分鐘 demo：一個 supported lookup、一個 cross-version comparison、一個 tool task、一個 unsupported question 和一個 controlled failure。包括 final report、reproducibility manifest、architecture description、evaluation harness、test data 和 licenses/provenance。必要時，把 checkpoints 或 model-download instructions 與 source code 分開。遵照 capstone rubric，記錄你自己的 contributions 和所獲協助。
