完整講義

閱讀完整解說

用具體決定檢視 release

用同一份 evidence table 做 release review，無需新增 module。每次 release 記錄：data 和 model license、誰可存取 source 和 logs、English/Chinese task slices 的錯誤、附 hardware/workload 的實測 resource use，以及 deployment 尚需的 legal review。缺少 license permission 或 source 未獲授權，都會阻止 release。細小 quality 差距要檢查 cases 和 uncertainty。Energy 估算必須清楚界定 measurement boundary；單靠 parameter count 不足。

Scaling 和 multimodal extensions 保留為 optional second-pass notes。本週 required work 是 integration：固定 component versions、重跑相同 checked tasks、檢查 failures，並按結果選擇 release。

Project 現在有已理解的 components

你先學會 model，才把它用於 retrieval 和 tool systems。Project 結合聚焦的 public documentation corpus、semantic search、附 source labels 的 answers、有界 executable tools、evaluation，以及可重現的 API release。

整合先由 user tasks 開始。Exact lookup、paraphrase、version comparison、troubleshooting、calculation 和 insufficient-evidence requests，各需要不同 success checks。

Architecture 應展示 evidence 和 action boundaries，而非把所有 components 藏在一次 framework invocation 後。

由頭到尾處理 documentation question

User 問兩個 versions 的 retry waiting 有何改變。保留 comparison scope、retrieve 兩邊相關 rules、選 coherent context、需要時用 validated tool 計算，再形成有 source 支持的 answer。

若缺一條 rule，完整 comparison 就仍未解決。若 model 提出 invalid call，controller 會拒絕。若 generation 加入 unsupported caveat，answer rubric 會捕捉另一類 failure。

這條 trace 把日常 school examples，連接到更難但結構相似的 technical task。

Baselines 讓整合 claims 有理據

比較 lexical 和 dense retrieval、basic 和 improved context pipeline、狹窄 task 的 base 和 adapted models，以及 fixed workflow 和 adaptive planning。

保持相關 controls 固定，報告所有 calls、failures 和 costs。若 agent 或 adapter 都沒有實際改善，default release 可以不包含它們。

只要有 data、configuration、raw outputs 和 limitations，negative experiment 同樣能展示良好 reasoning。

Data 與 final evaluation

使用經審核 task records，包含 expected sources、required facts、allowed tools、group labels 和 success predicates。Final evaluation 要與 adaptation 和 configuration choices 分開。

目標應是可管理、聚焦的 collection，而非無差別 crawl。保留 source revisions 和 redistribution terms。

報告 task slices、counts、uncertainty、新 failures 和 resource measurements。小型 project 不足以支持涵蓋所有 documentation domains 或大規模 production usage 的 claims。

Tables、images 與遺失 structure

Technical pages 包含 tables、diagrams、code 和 screenshots。Text parser 可能保留 values，卻失去 row/column association。

若 table 的 product-tier labels 消失，retrieval 可找到正確 page，但 answer 把數字配到錯 tier。應把 extraction 與基於 extracted evidence 的 reasoning 分開 evaluation。

Multimodal extension 應保留 coordinates/provenance，並用獨立小型 test set。加入 vision model，不會自動還原每個 detail。

Scaling 是選做 engineering decision

若有真正 bottleneck，選 parallelism 前先識別 resource。Data parallelism 把 model 複製到不同 batches。Tensor parallelism 分割 layer computation。Pipeline parallelism 分割 layers，再排程 microbatches。

State sharding 可減少重複 optimizer/gradient/parameter state，但增加 communication costs。Activation checkpointing 處理的是另一 memory component。

假設 70% work 完美 scalable、30% serial，理想 four-way speedup 為 1/(0.3+0.7/4)≈2.11，尚未計 communication。沒有實測多 GPUs 時，可以提交清楚標示的 theoretical memo。

Release 前的 ethics 與 governance 檢查

答案看似正確的 assistant，仍可能對不同 groups 提供不平均的服務。比較 English 和香港中文 questions、不同 phrasing、missing answers 和 accessibility needs 的表現，並報告 slice sizes 和 errors。Bilingual interface 本身並不證明 answer quality 相同。讓使用者知道答案由 model 生成，提供質疑重要錯誤的途徑，並清楚界定涉及個人的決定由誰負責。

分別記錄 model weights、source code、training data、retrieved documents 和 redistributed outputs 的 licenses。「Open weights」並不代表所有用途都無限制。網頁公開可讀，本身並不能證明可重新發布全文，或可用於任何 training context。核對 license terms、permitted use、attribution 和適用的 copyright rules；若 permission 不清楚，就記錄疑問，不要自行假設存在一概適用的 research 或 AI exception。

Energy 亦是可以量度的 resource。假設一部 device 平均使用 100 watts，執行 2 hours，其 device energy 就是 0.2 kWh。計算時要交代 CPU、GPU、utilization、duration 和 system boundary；carbon emissions 還取決於 electricity carbon intensity 等假設。重用相容的 cached computation，並停止沒有幫助的 experiments。把估算標為估算，不要當成 universal emissions-per-token 數值。

Regulation 取決於地點、活動和 organization 的角色。香港 personal-data obligations、model 和 data licenses、面向消費者的陳述，以及目的地市場的規則，可以分別適用於同一 system 的不同部分。例如 EU AI Act 區分 roles 和 risk categories，亦有分階段實施的 obligations。使用官方 regulator guidance，保留註明日期的 applicability record。這裏的目標是辨認哪些問題需要審視，而不是背誦全球法律 checklist。

Final release 前，回答五個具體問題：測試過哪些 user groups；哪些 personal data 是必要的；哪些 licenses 允許預期用途；由誰負責 incident response；以及記錄了哪些 resource 和 regulatory assumptions。把答案附在原有 release checklist，令 ethics 成為 delivery 的一部分。

Final release candidate

識別所有 artifacts、跑 invariant 和 integration checks、執行計劃 task evaluation，並檢查有代表性 traces。決定前記錄 quality 和 latency gates。

使用已記錄 downloads 和 environment，在乾淨 directory 重現。Notebook cached variables 不應成為未記錄 dependency。

準備 demo，包含正確 lookup、comparison、tool task、真正 absence 和 controlled failure。

只有針對已觀察到的需要，才寫 capacity/extension memo。區分實際 implementation、measured results 和 future proposals。

選讀：第二次閱讀的延伸內容

參考細節與學習檢查

複習 A：Integration contracts

一起固定 corpus、chunking、embedding、index、tokenizer、generator、adapter、prompt 和 tool versions。追蹤同一 request 經 retrieval、context packing、generation、tool execution 和 claim checks 的流程，在每個 boundary 記錄 source 和 configuration。

複習 A：Release decision 例子

假設 hybrid retrieval 改善 checked paraphrase tasks，但 adapter 和 agent 增加成本、沒有可靠提升，就以 hybrid retrieval 配合合格 base model 和 fixed workflow 為 default。保留 adapter/agent outputs，作為負面 experimental results。以下 Amdahl 例子是 optional capacity note。

複習 A：Reproduction check

由 clean directory 開始，核對 component identities，重跑 checked questions 而不以它們 tuning，儲存 raw per-task outputs，並與上一 release 比較 failures。單靠 manifest 不能證明 answer support 或 permission correctness。

複習 B：直觀理解

Technical documentation 包含 tables、diagrams、screenshots 和 code。Text-only parser 可能丟棄 answer 所需資訊。Multimodal support 應由保留 evidence 和 evaluation extraction 開始，而非只換成 vision-language model。

OCR 從 images 抽取 text，但可能誤讀 symbols、units 和 indentation。Table extraction 必須保留 row/column relationships。Vision-language model 可結合 visual 和 textual inputs，但細小 screenshots 或密集 diagrams 仍可能困難。儲存 page/image coordinates 和 source references，令 citations 指向正確區域。把 extraction 和基於 extracted material 的 reasoning 分開 evaluation。

複習 B：重溫 generative model 類別

對 diffusion，一個 forward step 可寫成 xt = sqrt(alpha_bar_t)*x0 + sqrt(1-alpha_bar_t)*epsilon 其中 epsilon 為 standard Gaussian。Training 通常教 network 預測 noise 或相關 target；sampling 按 schedule 從 noise 重複 denoise。這與 next-token autoregression 不同，但真正 systems 可能結合不同 architectures 和 representations。

VAE 學習 latent variable model，使用 reconstruction/regularization objective。GANs 使用 adversarial learning。Flow matching 學習連接 distributions 的 vector field。這些概覽概念有助閱讀 image/audio generation documentation；實作高品質 image generator 不在核心 capstone 範圍。

複習 B：其他相關主題

Mixture-of-experts architectures 把 tokens route 到 expert networks 的 subsets，影響 active compute、total parameters 和 communication。Longer-context models 可接受更多 evidence，但仍需 retrieval selection、latency control 和 evaluation。Model-context 和 agent communication protocols 標準化 interfaces；它們不會自動提供 authorization、正確 tool semantics 或可靠 planning。把新 frameworks 當成你已理解 contracts 的可替換 implementations。

複習 B：Evidence 問題實例

Screenshot table 按 product tier 列出 timeout defaults。Flattened OCR 回傳數字，卻遺失 tier labels。Retrieval 找到 page，但 generator 把錯誤數字配到 requested tier。Error 在 language generation 前的 extraction/structure。Page-level citation 不能修復錯誤關聯。

複習 B：實驗

Tutorial 32: 溫習、答辯與持續學習計劃 包含 reproducibility audit；可重看 tutorial 15 的 numerical noising illustration。Project 選一個 extension：保留並 evaluation 一個 documentation table、retrieve 帶 coordinates 的 diagram，或加入經審核 multilingual subset。定義小型獨立 test set，與 text-only baseline 比較。Extension 要放在本週原有時間內。

完成標準： 解釋 diffusion 與 autoregression 的差別，並診斷一次 multimodal evidence-loss failure。 閱讀材料： Ho et al. Denoising Diffusion Probabilistic Models (R21) 概覽； Hung-yi Lee Introduction to GenAI and ML 2025 (R03) image/audio generation 主題。 Tutorial： 31.
