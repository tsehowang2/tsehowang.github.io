由例子開始

一個反覆出現的 behavior 問題

假設 assistant 知道提供的 school fact，卻經常忽略 “Answer with one transport word.”。它回傳一段 paragraph，而不是 bus。

修改 prompt 和加入 output constraint，是成本較低的第一步。如果仍有可重現的 behavior gap，supervised fine-tuning 可能是合理實驗。

如果問題是 bus timetable 根本沒有進入 prompt，調整 weight 可能是錯誤介入。選 training method 之前，先診斷 failure。

由例子開始

Input 與理想 output

SFT example 包含 instruction/context 和 target response。簡單 record 可以問 “Complete: I go to school by ___; answer with one word”，target 是 bus。

另一筆可以問手冊裏沒有支持 fact 的問題，target 是指出資料不足的 response。加入這類 example，避免 dataset 暗示每條問題都應收到自信的 factual answer。

Target 必須符合實際提供的 evidence 和要求 format。流暢的 synthetic target 也可能錯。

建立對機制的理解

建立 model sequence

使用 model 的 chat template，serialize prompt 和 assistant response。Answer-only training 期間，prompt token 仍作 context，但其 loss label 設為 ignored。

檢查實際 token boundary。String length 不等於 token length。如果對 prefix 的假設不符合 template，就可能 mask 錯誤位置。

如果 truncation 移除了所有 answer token，這筆 record 就沒有預期的 supervised target。Training 前先偵測，不要把其後的 failure 當作 tuning problem。

建立對機制的理解

Label mask 的計算例子

對 toy ID sequence，prompt 是 [10,11,12]，answer 是 [20,21]，完整 input 為 [10,11,12,20,21]。Answer-only label 可以把 prompt position 標為 ignored，把 answer position 按 model 的 shifted-loss convention 標為 supervised。

要明確指出哪個 library 會在內部執行 next-token shift。不要手動 shift 兩次。

本 tutorial 檢查 prepared record；之後的 training notebook 使用所選 model 的 convention。印出的 token ID 和 label，是有用的 debugging artifact。

建立對機制的理解

先 split data，再做 paraphrase

如果同一問題的十個改寫版本跨越 train 和 test，表面 generalization 可能主要來自重複 task structure。生成 paraphrase 之前，先按有意義的 question/source family split。

Final evaluation record 要與 adaptation 和 configuration selection 分開。如果可行，真正 project 的 train set 可由 100–300 個經 review 的 narrow example 組成；較小 pilot 必須作更有限的 claim。

Manual review 和 executable check 互補。Validator 可以檢查 citation ID 或 calculation，reviewer 則檢查 target 是否真正回答 question。

建立對機制的理解

選擇 adaptation objective

SFT 教 model 模仿 target。Continued pretraining 在額外 text 上使用 language-model objective。Preference training 比較 alternative。這些 objective 並不解決完全相同的問題。

對狹窄的 output-format behavior，label 做得好的 SFT 可以合適。對經常改變的 factual information，透過 retrieval 保持 evidence 更新，可能更易維護。

方法可以結合，但實驗必須隔離改變了甚麼。同時改善 prompt、retrieval 和 weight，便無法對 adapter 作乾淨的結論。

建立對機制的理解

Training 前先寫實驗提案

寫出 failure distribution、計劃 dataset、baseline、expected improvement 和 possible regression。例如：改善有效 tool-call format，同時監察 argument correctness 和不適當作答。

在 independent example 上選 metric，並在看到 result 前定義 release gate。Training loss 是診斷指標，不是最後 application criterion。

實例練習與學習檢查

提出 grouped split，並 audit 十筆 record。指出一種 SFT 不太可能修復的 failure，原因是缺少 relevant evidence。

選讀：深入學習

深入研習 17：直觀理解

Assistant 失敗時，改變 model weight 只是其中一種介入。缺少 source material，指向 ingestion 問題；缺少 relevant passage，指向 retrieval；answer 忽略現有 evidence，可能涉及 context、prompting 或 model capability。持續出錯的 output format，才可能適合 supervised fine-tuning。付出 training cost 前，先診斷失敗的 boundary。

Prompting 在 inference time 改變 instruction 和 demonstration。RAG 改變提供的 information。Supervised fine-tuning 改變 parameter，以模仿理想 output。Continued pretraining 在新 text 上，透過 language-model objective 改變 parameter。Preference optimization 改變可能 response 之間的相對 preference。方法可以共存，但它們處理不同的直接問題，也有不同 update cost。

選讀：深入學習

深入研習 17：SFT dataset 設計

SFT example 包含 input 和 target response。對本 assistant，可以教狹窄 behavior，例如選擇有效 tool，或產生引用 evidence 的 JSON answer。加入 answerable task、資料不足 case、version-specific evidence 和 tool failure。如果每個 example 都可作答，model 可能學到「給答案永遠有獎勵」。

Target 在提供的 context 下必須正確。Synthetic generator 可以產生合理卻錯誤的 example；要人手 audit sample，並盡可能使用 executable 或 source check。儲存 provenance 和 generation setting。製作 paraphrase 之前，按 task family 或 documentation group split，否則風格上近乎重複的內容可能洩漏至 evaluation。

選讀：深入學習

深入研習 17：選擇介入的例子

想像有 50 個 development failure：25 個缺少 evidence，10 個有正確 evidence 但 JSON 無效，10 個需要尚未提供的 calculation tool，5 個本身有歧義。拿全部 50 個來 training，會混合四種原因。先修 ingestion/retrieval，加入 typed calculation interface，並釐清歧義任務。只有 prompt/schema constraint 之後仍有量度到的 gap，才 fine-tune format adherence。

對 answer-only loss，用 ignored label mask prompt token，並 supervise answer token。Input 要保留 evidence。不要用 final held-out label training，也不要用 hidden test set 選 epoch 數。記錄 truncation rate；target 被切掉的 example，不提供預期 supervision。

選讀：深入學習

深入研習 17：實驗

Notebook 24 建立 training record、檢查 source ID，並 split grouped task。小型 synthetic example 教的是 data pipeline，不是有用的 production behavior。為真正 project 建立更大、經 review 的 development dataset。Training 前先預測：哪個 metric 應改善，哪個可能 regression？保留 frozen RAG baseline 作比較。

完成標準： 用 error taxonomy 說明為甚麼選 SFT，並建立有考慮 leakage 的 dataset。 閱讀材料： R01 的 post-training 主題；R14 的 configuration overview。 Tutorial： 24.
