Training 後的 artifact 需要比較

School 例子的一字 completion task 提供簡單 format target。Documentation project 之後加入有 citations 的 answers 或 typed tool proposals。Fine-tuning run 應檢驗清楚說明的 behavior gap，而非只產生 checkpoint。

令 base model、inputs、context、decoding 和 evaluator 保持可比較。如果同時改善 prompt，亦要加入 prompt-only control。

實驗可以得出 adapter 沒有幫助的結論。只要誠實記錄 data、training 和 evaluation，這種發現同樣有用。

最基本的 training 與 reload 流程

檢查準備好的 examples，以及非空的 answer masks。確認 loss 為 finite、trainable factors 有非零 gradients，而 frozen base parameters 沒有 gradients。

先跑短 pilot，儲存 adapter 和 tokenizer/config metadata；若 memory 有限，釋放 training instance，再對應 pinned base 重新載入。

在獨立 task cases 上產生 outputs。Reload 後 loss 為 finite 只是 smoke check，不能證明 response behavior 改善了。

一個隱藏 regression 的結果

假設 valid JSON 由 80% 升至 96%，但 correct arguments 仍弱，unsupported answers 則由 5% 升至 15%。Model 學會了一種行為，同時令另一種行為變差。

檢查 targets 是否獎勵自信作答、漏掉 absence cases，或把正確 formatting 與錯誤 facts 配對。更多 valid JSON 並不足以支持 release。

比較各項 task outcomes，保留新 errors。選擇較強、符合要求的 system，而非自動部署最新 artifact。

Preferences 由 rubric 開始

對 ticket question，應偏好 “3×4=12 dollars”，而非自信的 10-dollar answer。Preference 反映 task correctness，不是 response length。

按照明確 rubric 收集 preferred/rejected pairs，涵蓋 evidence、completeness、valid actions 和有用解釋。審核互相矛盾及不確定的 labels。

LLM teacher 可以產生 candidate pairs，但它的 errors 可能變成 training targets。可行時，human 或 executable checks 仍很重要。

以小計算理解 DPO margin

DPO 比較 learned policy 相對 reference，如何改變 preferred response 與 rejected response 的 relative likelihood。

如果 preferred response 相對 reference 改善 0.4 natural-log units，而 rejected response 改善 0.1，relative margin 就是 0.3。使用 beta=0.1 時，sigmoid input 是 0.03，loss 為 −ln(sigmoid(0.03))≈0.67826。Zero-margin loss 是 ln(2)≈0.69315，因此這個 positive margin 令 loss 稍微下降。beta 是 tuning parameter：0.1 是常見的 implementation default，並非 universal best value，亦不是每種 setup 都必須使用 0.1–0.5 的規則。

這項計算解釋 objective 的方向。它沒有執行 preference training，也不保證 labels 代表我們真正想要的行為。

Reinforcement learning 與 verifiable rewards

RLHF 可包含 learned reward model，以及帶 reference-policy constraint 的 reinforcement-learning optimization。Verifiable-reward 方法則使用可檢查 outcomes，例如正確 arithmetic 或 executable result。

Checker 仍可能不完整，或被鑽漏洞。Reward 改善衡量的是對該 reward procedure 的成功，不是普遍可靠性。

Reasoning prompts、reasoning training、preference optimization 和 executable verification 是不同 interventions。要說明實驗實際用了哪一種。

Distillation 與 forgetting

Distillation 利用 teacher 的 outputs、probabilities 或 demonstrations 教 student。它可傳遞有用行為，亦可傳遞 teacher errors 和表面 style。

對狹窄 task 進行 fine-tuning，可能削弱其他原本有用的行為。除 target task 外，也要加入 general formatting、refusal 和基本 instruction-following checks。

儲存 raw examples、measured results、environment 和 model revisions。這些記錄讓負面或混合結果可理解，而非只有一句無法解釋的 “fine-tuning failed.”

實例練習與學習檢查

執行真正的小型 model LoRA tutorial，並進行 controlled base comparison。報告 task quality、invalid outputs、unsupported behavior、memory 和 elapsed time。

建立 20 組經審核的 preference pairs，解釋一個模糊 preference，並重現 DPO scalar loss。清楚區分這項 objective 練習與真正 SFT training。

當你能根據 application outcomes 支持 release decision，並討論 preference/distillation 方法而不聲稱做過未做的實驗，就已準備好。

參考細節與學習檢查

複習 A：直觀理解

Training loss 回答 model 是否正在擬合 supervised targets。Application 要問的是：儲存後的 adapter，能否在沒有不可接受 regressions 的情況下改善 target task。完整實驗包括 baseline、controlled training run、held-out comparison 和可重現 checkpoint。

Base 和 adapted models 應使用相同 base revision、task contexts、decoding settings 和 evaluation parser。若加入 adapter 時亦改善 prompt，另外跑 prompt-only control。最基本 comparison matrix 可以是 base prompt、improved prompt、improved prompt plus RAG，以及 RAG plus adapter，並按 task 設定 constraints。若某些組合無法回答 research question，就不必強求每個組合。

複習 A：Training 機制

使用小 batch、短 sequence length、gradient accumulation 和 checkpoints。先跑少量 batches，確認 valid-token counts、非零 gradients 和 finite loss。若所選 setup 需要，則 clip gradients。若 model 要求，training 時關閉 inference-only caches。Preparation 和 evaluation 都要一致使用實際 chat template。

Prompt loss masking 必須配合 serialization。Tutorial 使用單一 user message 和 assistant response；tokenize prefix 和完整 conversation 時，不重複加入 special tokens，並檢查 prefix IDs 與完整 sequence 的 prefix 相同。若假設不成立，就拒絕或重新設計 examples。更複雜的 multi-turn data，需要正確 assistant-token mask，不能靠 string length 猜測。

複習 A：結果解讀實例

假設 JSON validity 由 80% 升至 96%，factual completeness 仍是 70%，而對 unsupported questions 的不當回答由 5% 升至 15%。Adapter 學會了 formatting，但 release 並非明顯更好。較低 loss 或更多 valid JSON，不能抵銷 refusal regression。檢查哪些 training examples 獎勵了過度自信作答。

複習 A：實驗

Tutorial 26: Fine-tuning 實驗、preference 與 distillation 執行短時間小型 model LoRA adaptation，並儲存 adapter、tokenizer 和 training metadata。附帶 task 刻意設計得很小、很狹窄，不能據此推論 generalization。必交 project report 要使用經審核 training data 和獨立 development cases；若 resources/data 不足，就清楚標示為小型 pilot。

量度 runtime、peak GPU memory、trainable parameter count、task correctness、format validity 和 unsupported-answer behavior。在乾淨 session 重新載入儲存的 adapter，再 evaluation 一組 smoke set。若 quality 沒改善，記錄 negative result，最終 release 保留較強 baseline。

完成標準： 重現一次真正的小型 training run，並解釋該 artifact 是否應部署。 閱讀材料： Hugging Face PEFT LoRA guide (R14) adapter save/load； PyTorch automatic mixed precision recipe (R18) precision。 Tutorial： 26.

複習 B：直觀理解

SFT 表示 “imitate this answer.” Preference data 表示 “prefer this answer to that answer for this prompt.” 這些 signals 並不直接編碼普遍真相。Rater 可能偏好討好但錯誤的 answer，而 teacher model 可能產生系統性 errors。

RLHF 通常包含由 preferences 得來的 reward model，以及以它作目標的 reinforcement learning。Reference-policy constraint 有助限制不受控 policy drift。RL with verifiable rewards 使用可檢查 outcomes，例如正確 executable result；但 checker 本身仍可能不完整或被鑽漏洞。在狹窄 checker 上取得高 reward，不等於證明廣泛可靠性。

複習 B：DPO 機制

DPO 直接利用 preferred 和 rejected responses，相對 reference model 進行 training。其中一種形式是最小化 -log sigmoid(beta * [(log pi(y+|x)-log pi_ref(y+|x)) - (log pi(y-|x)-log pi_ref(y-|x))]) 。括號比較 relative policy changes，而非只比較 raw sequence likelihoods。beta 是控制這種關係的 tuning parameter；實際效果取決於 setup。

若 preferred response 相對 rejected response 改善，loss 便下降。但錯標 preference pairs 可能 optimization 出錯誤行為。應 deduplicate pairs、審核矛盾 labels，並確保 answers 依相同 context 和 task 判斷。

複習 B：Distillation 與 forgetting

Distillation 利用 teacher outputs、probabilities 或 demonstrations training student。它可較節省地傳遞行為，但 student 可能繼承 teacher errors，或只學到表面 formatting。記錄 provenance，驗證 teacher-generated data。Fine-tuning 亦可能削弱原有有用行為；除狹窄 task 外，也 evaluation general-format、refusal 和基本 instruction-following cases。

複習 B：比較實例

Teacher 產生長解釋，但 API name 錯誤；較短 response 引用正確 source，並承認 version difference 尚未解決。若 preference label 獎勵 length，system 可能 optimization verbosity，而非 correctness。收集 labels 前，先寫涵蓋 factuality、evidence、completeness 和 action validity 的 rubric。

複習 B：實驗

Tutorial 26: Fine-tuning 實驗、preference 與 distillation 包含 numerical DPO loss calculation，並非完整 RLHF training pipeline。從 development failures 建立 20 preference pairs，用明確 rubric 標記，並以小型 blinded re-labeling 檢查 agreement。找一個 binary preference 掩蓋重要 tradeoff 的 case。完整 DPO/RL training 為選做延伸；若選擇它，便取代另一實驗。

完成標準： 區分 SFT、reward-model RLHF、DPO、verifiable rewards 和 distillation，並解釋 optimization proxy 的風險。 閱讀材料： Rafailov et al. Direct Preference Optimization (R15) objective； Hung-yi Lee Introduction to GenAI and ML 2025 (R03) post-training 主題。 Tutorial： 26.
