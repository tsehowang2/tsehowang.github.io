第一學期 / 第 11 週

Encoder、decoder 與完整 model architecture

練習 11檢查你的理解
課堂投影片 · 第 11 週

一步一步學習。

閱讀每段解說，停下來預測結果，然後繼續。選取簡報後，可用方向鍵操作。完整講義在下方。

由例子開始

block 成為特定任務設計的一部分

transformer 是由相關 component 組成的一系列 architecture。encoder、causal decoder、encoder-decoder 的可見範圍和資訊流各有不同。

用三個日常任務來看：表示完整句子「I go to school by bus.」；續寫 prefix「I go to school by.」；將完整 source sentence 翻譯成另一種語言。這些任務可用的 input 和所需 output 都不同。

decoder 不只是指「把 ID 轉回 string 的東西」。在 model architecture 中，它是一種 neural sequence-processing 設計。tokenizer decoding 是另一個 operation。

由例子開始

encoder 讀取完整 input

encoder 表示一個完整可見的句子時，有效 position 通常可以 attend 到前後其他有效 position。school 的 representation 可以使用右邊的 bus。

這有助 token labeling 或比較完整 input 等任務。masked-language objective 可以隱藏某個 token，要求 model 用周圍可見的文字預測它。

若在「I go to school by [MASK],」隱藏 bus，model input 便包含一種特殊的 masking 情況。這裏的 training objective 和 input 構造，與普通由左到右續寫不同。

建立對機制的理解

causal decoder 預測續寫內容

decoder-only language model 對 input prefix 使用 causal self-attention。在 training 的某個 position，它可以讀取當前和較早的 input token，但不能讀取未來的 target token。

對「I go to school by,」，最後的 representation 為下一個 token 產生 vocabulary logit。選定 bus 後，model 將它附加到序列，再繼續。

許多熟悉的文字生成 LLM 都使用這種排列。architecture 解釋 next-token 計算；之後的 post-training 則塑造對話行為。

建立對機制的理解

encoder-decoder 連接兩個 sequence

encoder-decoder system 先表示 source sequence。decoder 再一邊參考 target prefix 和 source representation，一邊產生 target sequence。

decoder 的 self-attention 對 target prefix 採用 causal 方式。cross-attention 的 query 來自 decoder，key/value 來自 encoder output。source position 不需要遵從 target 由左到右的順序。

若 source 有七個 token，而 target 暫時有四個 position，cross-attention score 的 shape 可以是 [4,7]。這個長方形 matrix，就是 week 7 提過的 shape 分別。

建立對機制的理解

用可見範圍表釐清分別

對四個 token 的完整 input，encoder self-attention 可讓每個有效 query row 使用全部四個 key position。causal decoder 則讓 row 0 只見到 0，row 1 見到 0 和 1，如此類推。

cross-attention 的可見範圍還取決於有效 source position 和任務限制。padding 仍須處理。「encoder 看見所有東西」只是指獲准使用的有效 input position，並不代表可以忽略其他限制。

畫出這三種情況，不要只背 model 名稱清單。圖示說明某個 position 可用甚麼資訊，往往比知道一個宣傳標籤更有用。

建立對機制的理解

training 時的平行計算並不會移除 causality

training 時，完整 target sequence 已作為資料提供。masked transformer 能平行計算很多 position 的 representation，因為 mask 限制了它們的 dependency。

普通 autoregressive generation 中，下一個生成 token 會改變下一次的 prefix。所以各次 output-token 決策依次發生，即使每次 forward pass 內部使用平行數值計算。

這區分了已知 sequence 內的平行計算，以及新生成 token 之間的依次 dependency。兩者可以同時成立。

深入學習，檢查理解

為學習練習選擇 architecture

我們的 tiny model 是 causal decoder，包含 learned absolute position、兩個 block 和 vocabulary output head。這使整條路徑貼近起初的 sentence-completion 任務。

我們並不是說只有這種 architecture 有用。選它是因為 label、mask 和 output selection 都能由頭到尾檢查。

日後載入 pretrained model 時，先辨認 architecture 和 tokenizer，才套用教學 model 的假設。normalization、attention-head sharing、position 方法和 training objective 的不同，都可能改變重要細節。

深入學習，檢查理解

實例練習與學習檢查

為每項任務辨認 model 排列和允許的 context：填補完整句子中隱藏的字、續寫未完成的句子，以及根據完整 source 產生翻譯。

解釋 causal decoder 為何不能在 training 的 by position 使用答案 bus。再解釋完整 input 的 encoder，為何可以合理地使用 school 右方的詞。

當你在解釋中，能以 encoder、decoder、self-attention、cross-attention、training parallelism 和 autoregressive generation 分別指向不同 operation 與限制，就準備好了。

深入學習，檢查理解

使用相同詞語的三個任務

任務 A 提供完整句子，問哪個詞代表交通工具。完整 input 的 representation 可以使用某 position 兩邊的資訊。任務 B 提供「I go to school by」，要求續寫；它不能讀取尚未生成的答案。任務 C 提供 source sentence，要求 target-language sentence，因此需要建立兩個 sequence 之間的關係。

為以上情況分別寫出 mask 和 tensor shape。若任務 C 有六個 source token 和八個 target position，cross-attention score 的 shape 是 [8,6]，causal target self-attention 則是 [8,8]。兩個 matrix 回答不同的資訊流問題。

這個練習避免 architecture 名稱變成脫離內容的標籤。知道可用 input、output 任務和 attention source 後，你就能解釋為何某種排列合適，以及 leakage 會在哪裏發生。
