CPU、GPU、memory 與 model 資源計算

課堂投影片 · 第 22 週

由例子開始

數值運算是在實體 hardware 上執行

Transformer 包含 matrix multiplication、elementwise operation 和 memory access。CPU 可以執行小 model；GPU 可以平行執行大量合適 operation，但 performance 亦取決於 data movement 和 memory capacity。

分清 host RAM 和 GPU VRAM。Model 下載到 disk，不代表一定能放進任何一種 memory。Tensor 在 CPU 和 GPU 之間複製，會帶來 movement 和 coordination。

現在你已能指出 hardware 儲存甚麼 tensor、執行甚麼 operation，所以我們開始學 hardware。

由例子開始

Parameter 只是第一項 memory 開支

如果 model 有 P 個 parameter，每個用 b bytes 儲存，weight memory 就是 P×b。五億個 parameter、每個兩 bytes，合共十億 bytes，約 0.93 GiB。

Training 期間，gradient、optimizer moment、可能存在的 master weight、activation 和 temporary buffer 都增加 memory。Generation 期間，KV cache 也可以很大。

所以 inference weight estimate，不能回答 model 能否 training，或能否處理很長、帶 batch 的 context。

建立對機制的理解

Training state 的估算例子

一個示範用 mixed-precision Adam 配置，每個 parameter 使用 2 bytes weight、2 bytes gradient、4 bytes master weight，以及兩個 optimizer moment 共 8 bytes。未計 activation 和 overhead 已合共 16 bytes。

五億個 parameter 的已計 state 是八十億 bytes，約 7.45 GiB。不同 implementation 和 precision 選擇，會改變計算。

互動 worksheet 明確標示這只是 partial estimate。Worksheet 的數值低於 VRAM 線，不代表真實 runtime 一定放得下。

建立對機制的理解

KV cache 的計算

Cache bytes 約等於 2×layers×batch×tokens×KVheads×head_dimension×bytes。前面的 2 代表 key 和 value。

設 24 layers、batch 1、2048 tokens、8 個 KV head、dimension 64、每個 value 兩 bytes，結果是 100663296 bytes，即 96 MiB。

更長 context 和更大 batch 會成倍增加這個量。Grouped-query attention 的 KV head 比 query head 少；應檢查 architecture，而不是自動代入 query-head count。

建立對機制的理解

Memory hierarchy 和 movement

GPU execution 使用 register、block 內的 shared memory、cache 和 device DRAM，實際安排視乎 hardware。大型 tensor 放在 device memory；搬移及重讀它們，可能主導 operation 的時間。

宣傳中的高 arithmetic rate，不保證 application 一定快。Low-arithmetic-intensity operation 可能把大部分時間花在搬移 value。

下週會用 vector addition kernel 讓這點變得可見。Operation 足夠簡單，所以 indexing 和 transfer boundary 可獨立檢查。

建立對機制的理解

較小 microbatch 和 checkpointing

Gradient accumulation 讓幾個小 microbatch 一起形成一次 effective update。它可以減低 activation memory 中與 batch 有關的部分，但 persistent model/optimizer state 仍然存在。

如果單一 sequence 已造成 OOM，單靠 accumulation 不能縮小該 sequence 的 footprint。較短 context、activation checkpointing、較小 model 或 state sharding，分別處理不同 component。

Activation checkpointing 透過在 backward 重新計算，節省部分 intermediate storage。代價是額外 computation，而不是免費移除 memory 開支。

建立對機制的理解

選 precision，量度實況

Float32、float16、bfloat16 和 quantized representation 的 numerical range、memory cost 和支援程度都不同。不要假設你的 GTX 1650 Super 支援每種 optimized dtype 或 kernel。

使用實際 device property 和 compatible software。免費 Colab session 可能提供不同 GPU，甚至沒有 GPU，所以要儲存 checkpoint 和量測 metadata。

在明確 workload 下記錄 allocated 和 peak memory。Allocator reservation 和 warmup 可能令過度簡化的讀數產生誤導。

選讀：深入學習

深入研習 9：直觀理解

GPU 加速很多相似 arithmetic operation，但 model 同時要搬移 data，並把 working state 放進 memory。單憑「更多 FLOPs」，無法預測實驗能否執行、會否快。分清 CPU RAM、GPU VRAM、device memory bandwidth、host-to-device transfer 和 compute throughput。

CPU 負責安排工作並 launch kernel。GPU execution 把 thread 分組，在 streaming multiprocessor 上執行。Register 靠近個別 execution context，shared memory 在 block 內可見，cache 服務較廣的 access，device DRAM 則儲存大型 tensor。即使 arithmetic 很快，tensor 反覆在 CPU 與 GPU 之間搬移，仍可能主導短運算的時間。

選讀：深入學習

深入研習 9：Training 與 inference

Parameter storage 為 parameter_count * bytes_per_parameter。Training 也可能儲存 gradient、optimizer moment、master weight 和 activation。示範用 mixed-precision Adam 配置中，2 bytes model weight + 2 bytes gradient + 4 bytes master weight + 兩個 moment 共 8 bytes，合共每 parameter 16 bytes，未計 activation 和 overhead。這是例子配置，不是通則；framework 和 precision 選擇可以不同。

五億個 parameter，以上示範 state 是十進制 8 GB。單獨一份 two-byte inference weight 是十進制 1 GB。所以能放得下 inference 的 model，training 仍可能失敗。LoRA 減少 trainable parameter state，但 activation 和 frozen base weight 仍佔 memory。

選讀：深入學習

深入研習 9：KV cache 計算例子

Autoregressive inference 期間，cache key 和 value 可避免重算較早 projection。KV-cache size 約為 2 * layers * batch * tokens * kv_heads * head_dim * bytes。對 24 layers、batch 1、2,048 tokens、8 個 KV head、dimension 64 和 two-byte value，cache 是 100,663,296 bytes，即 96 MiB。增加 batch 或 context 會成倍增加它。Grouped-query attention 可以使用少於 query head 的 KV head。

如果明確建立完整 attention score tensor，其大小亦會隨 sequence length 呈 quadratic 增長。Memory-efficient attention implementation 避免把全部 intermediate score 存進 device DRAM，同時保留 operation 的數學意義，但容許 numerical precision 差異。

選讀：深入學習

深入研習 9：實驗

Notebook 23 量度 device，而非假設其能力。先在紙上計算 weight、optimizer 和 KV-cache estimate，再與 allocated 和 peak memory 比較。計入 warmup 和 allocator reservation。遇到 out-of-memory error 時，先減 sequence length 和 microbatch，再考慮轉 framework。Gradient accumulation 改變 effective batch，但不會縮小單一 microbatch 所需 memory。

完成標準： 解釋為甚麼 model 放得下 inference，卻放不下 training，並估算隨 context 改變的 cache。 閱讀材料： R01 的 resource-accounting 主題；R16 的 memory hierarchy。 Tutorial： 22.
