A complete transformer walkthrough and first semester review

Tutorial 16Test your understanding
Lecture slides · Week 16

Learn one step at a time.

Read each explanation, pause to predict the result, then continue. Use the arrow keys while the presentation is focused. The complete lecture reader is below.

Start with an example

The semester returns to one sentence

We began with “I go to school by ___.” We can now trace a causal transformer that predicts a continuation. The goal of this lecture is to connect the components you have already studied, rather than introducing an application framework.

Use a small vocabulary and a two-block teaching model. Keep token IDs, representation width, head count, and sequence length visible in your diagram.

This model is intentionally small enough to inspect. The architecture shares important ideas with much larger systems, while its performance and resources remain very different.

Start with an example

Stage one text becomes representations

Tokenize the prefix into [I,go,to,school,by] and convert it to IDs. Select one vector per ID from the embedding table.

Add the position vector for each location. With five tokens and width D=8, the representation matrix is [5,8].

An ID does not itself encode order or semantic distance. The embedding lookup and position representation supply separate information that later transformations can use.

Build the mechanism

Stage two each block mixes and transforms

Normalize each row, form Q/K/V, split the appropriate head axes, calculate scaled pairwise scores, apply causal visibility, and softmax over keys. Multiply by values, merge heads, and project back to width 8.

Add that sublayer output through the residual path. Normalize again, apply the position-wise MLP, and perform the second residual addition.

Repeat for the next block. The output retains one contextual row per position. At no causal query may the computation use an unavailable future input.

Build the mechanism

Stage three vocabulary predictions

The final output head transforms each contextual row into V vocabulary logits. The last prefix position, by, supplies the logits used to choose the next token.

Suppose bus=2, train=1, bicycle=0 and all other candidates are excluded for this small arithmetic example. Softmax gives approximately [0.665,0.245,0.090].

A real vocabulary includes many other candidates, so the denominator would include their scores too. Restricting the arithmetic example must be stated; it is not the full output distribution of a real model.

Build the mechanism

Stage four training and generation use the result differently

During training on the complete sentence, the expected target bus supplies a cross-entropy loss. Its gradient changes the parameters through the computation you traced.

During inference, there is no given bus target to backpropagate. A decoding rule selects a next token, appends it, updates or reuses cached states as appropriate, and continues until a stopping condition.

This distinction explains why the same network can produce logits during both training and use, while the surrounding procedure differs.

Build the mechanism

Diagnosing mistakes at the correct boundary

If IDs decode to the wrong words, inspect the tokenizer/vocabulary pairing. If future perturbations change earlier outputs, inspect visibility. If output width differs from the vocabulary size, inspect the output head.

If training loss falls but the held-out task remains weak, inspect data, capacity, optimization, and evaluation before concluding that the block is implemented incorrectly.

A systematic debugging explanation names the boundary, a concrete observation, and a test that distinguishes possible causes. “The AI is confused” does not provide that information.

Go deeper and check understanding

Reading the original architecture with preparation

Open the original transformer paper's model diagram and attention equation. Identify which components you have implemented and which belong to the encoder-decoder translation architecture rather than our decoder-only exercise.

Write tensor shapes beside one equation. Locate the residual connections and the MLP. Note that our pre-norm teaching block differs from the original architecture's normalization arrangement.

This is a useful point to read a paper: you now have operations and examples with which to interpret the compact presentation.

First semester assessment and the next step

Take the first semester exam. It asks about tokenization, probabilities, attention, masks, block shapes, architecture visibility, shifted training, and generation. It does not require a vector database, RAG service, or agent implementation.

Complete the tiny-model experiment and keep an honest account of its limitations. Your first semester artifact is an explained and tested model mechanism, not a prematurely assembled application.

Semester two will introduce search and external evidence using the representations and evaluation ideas you now understand. Before moving on, explain the complete school sentence trace aloud without skipping from token IDs directly to “the model answers.”

A final shape ledger

For B=2,T=5,D=8,H=2 and vocabulary size V=20, token IDs have [2,5], starting rows have [2,5,8], per-head queries have [2,2,5,4], and attention scores have [2,2,5,5]. Merged contextual output returns [2,5,8], and vocabulary logits have [2,5,20].

The last input position of each sequence contributes a twenty-way next-token distribution during ordinary continuation. During training, all valid positions can contribute losses against shifted targets. In both cases, the causal constraint limits each query's visible keys.

Explain each axis in words before writing a reshape. Then construct a small tensor with deliberately distinct numbers for batch, head, position, and feature indices. A mistaken transpose becomes visible. This small experiment turns a shape ledger into an implementation check rather than decorative notation.
