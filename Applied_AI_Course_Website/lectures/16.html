Semester 1 / Week 16

Deliver and defend RAG v1

Tutorial 08Test your understanding

Intuition

A semester project is ready when another person can run it, understand its evidence, and observe its limitations. A chatbot screenshot alone does not demonstrate that ingestion, retrieval or evaluation are reproducible. Freeze an identifiable version and defend the engineering decisions.

Your v1 includes a source manifest, ingestion procedure, lexical baseline, semantic retriever, persisted index, generator adapter, citation contract and evaluation harness. The starter's invented fixture is replaced with public documentation. Save selected pages with source URLs, versions, hashes and license notes. Use a focused documentation area rather than attempting to ingest the whole internet.

A release contract

Define a run manifest containing corpus hash, index identity, embedding model revision, generator revision, prompt hash, decoding settings and software environment. A single release version points to this set. If the embedding model changes, the index compatibility check should fail unless the correct index was rebuilt. If a source page disappears, ingestion should produce an explicit error or deletion record.

Failure behavior is part of the product. Unsupported questions receive a useful insufficiency message. Timeouts produce a controlled error. Citations lead to the matching version. Logs contain enough diagnostic data while avoiding unnecessary sensitive content. Your local demonstration can remain simple; its interfaces must make behavior inspectable.

Worked release decision

Suppose the new retriever improves lookup correctness from 72% to 81%, but wrong-version answers rise from 0 to 4. If the release gate forbids cross-version evidence, do not release merely because the average improved. Diagnose filtering and fix the regression. Numerical quality targets can be tuned to your use case; an authorization invariant remains a hard requirement.

Submission and examination

Run the held-out set once for the planned report, then freeze its raw outputs. Write the result, uncertainty, slice breakdown and top five failures. Include an ablation that changes one component, a reproducibility command and an architecture description. Present a three-minute demo: correct lookup, unsupported query and a deliberately difficult case. If you revise after seeing held-out failures, label the revision exploratory and create a future untouched test set before making fresh generalization claims.

Take semester exam 1 in assessments/EXAMS.md for two hours, then use the separate solution guide. The examination checks mechanisms and debugging judgment as well as definitions. A score below 60% means repeat the failed topics with smaller experiments before proceeding.

Exit criterion: reproduce RAG v1 from its manifest and explain one case where retrieval helps, one where it fails, and one where a simpler method is enough. Reading: R02 system lifecycle overview. Lab: 08. Assessment: semester exam 1.
