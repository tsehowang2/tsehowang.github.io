CUDA programming and honest profiling

Where GPU memory goes

Intuition

PyTorch operations eventually execute kernels. A CUDA kernel specifies work for many threads. Writing one small kernel makes launch overhead, indexing, memory access and synchronization concrete, even if most application work should continue using optimized libraries.

For a one-dimensional array, thread index i = blockIdx.x * blockDim.x + threadIdx.x. A vector-add kernel computes c[i]=a[i]+b[i] when i<n. The bounds check matters when n is not divisible by the block size. Blocks are scheduled independently; code must not assume a general grid-wide barrier inside an ordinary kernel.

Memory and performance

Adjacent threads reading adjacent elements often produce more efficient memory transactions than scattered accesses. Shared memory can reuse data within a block, but reuse must justify its loading and synchronization overhead. A barrier must be reached consistently by participating threads. Occupancy is one diagnostic, not an objective that guarantees maximum speed.

Arithmetic intensity is approximate operations divided by bytes moved. Vector addition performs roughly one addition for two input reads and one output write: about 1/12 operations per byte for float32, ignoring caching. This is low intensity, so increasing theoretical arithmetic throughput may help little compared with memory bandwidth. A matrix multiplication can reuse tiles and attain much higher intensity.

Timing worked example

GPU work is asynchronous relative to the host. Timing a launch without synchronizing may mostly measure dispatch. Use CUDA events or synchronization around the defined measurement interval. Warm up first, repeat the operation, and report a median and spread. Include data transfers only if your stated question is end-to-end latency; separately report kernel-only time when studying the device operation.

Suppose end-to-end time is 20 ms, of which 3 ms is the kernel. Making the kernel twice as fast yields 18.5 ms total, a speedup of only 1.081. This is Amdahl-style reasoning: optimize what dominates the real task.

Experiment

Notebook 05 compiles the bundled vector-add example if nvcc and a GPU are present. Run n=1, n=257 and a large n to exercise indexing and overhead. Compare against a CPU reference with a numerical tolerance. Then profile a PyTorch matrix multiplication or a short transformer forward pass. Save the trace and explain one bottleneck. FlashAttention is a deeper example of redesigning memory traffic rather than changing the attention objective [R26].

Failure to recognize: comparing a cold first call with a warmed library call measures setup differences. A benchmark that produces wrong values is not a performance result. Reading: R17 indexing example, R19 profiling; optional R26. Lab: 05.
