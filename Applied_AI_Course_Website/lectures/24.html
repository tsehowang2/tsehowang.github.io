A repeated behavior problem

Suppose an assistant knows the supplied school facts but often ignores “Answer with one transport word.” It returns a paragraph instead of bus.

Prompt changes and output constraints are inexpensive first interventions. If a repeatable behavior gap remains, supervised fine-tuning may be a reasonable experiment.

If the problem is that the bus timetable never reached the prompt, adapting weights may be the wrong intervention. Diagnose the failure before choosing a training method.

Inputs and desired outputs

An SFT example contains the instruction/context and a target response. A simple record asks “Complete: I go to school by ___; answer with one word” and targets bus.

Another asks a handbook question with no supporting fact and targets an insufficiency response. Including such examples prevents the dataset from implying that every question should receive a confident factual answer.

The target must match the actual supplied evidence and requested format. A fluent synthetic target can still be wrong.

Constructing the model sequence

Use the model's chat template to serialize prompt and assistant response. During answer-only training, prompt tokens remain context but receive ignored loss labels.

Check the actual token boundaries. String length is not token length. A prefix assumption that fails under the template can mask the wrong positions.

If truncation removes every answer token, the record has no intended supervised targets. Detect that before training instead of treating the resulting failure as a tuning problem.

A worked label mask

For a toy ID sequence with prompt [10,11,12] and answer [20,21], the full input is [10,11,12,20,21]. An answer-only label construction can mark prompt positions ignored and answer positions supervised under the model's shifted-loss convention.

Be explicit about which library performs the next-token shift internally. Do not apply a manual shift twice.

Our tutorial checks prepared records and the later training notebook uses the chosen model's convention. Printed token IDs and labels are valuable debugging artifacts.

Data splits before paraphrases

If ten rewordings of the same question cross train and test, apparent generalization can mostly reflect duplicate task structure. Split by meaningful question/source families before generating paraphrases.

Keep final evaluation records separate from adaptation and configuration selection. The real project's train set may be 100–300 reviewed narrow examples if feasible; a smaller pilot must make narrower claims.

Manual review and executable checks are complementary. A validator can check citation IDs or a calculation, while a reviewer can inspect whether a target actually answers the question.

Choosing the adaptation objective

SFT teaches imitation of targets. Continued pretraining uses a language-model objective on additional text. Preference training compares alternatives. These objectives do not solve identical problems.

For a narrow output-format behavior, well-labeled SFT can be appropriate. For changing factual information, keeping evidence fresh through retrieval may be easier to maintain.

The methods can combine, but the experiment must isolate what changed. Improving the prompt, retrieval, and weights at once prevents a clean conclusion about the adapter.

An experiment proposal before training

Write the failure distribution, planned dataset, baseline, expected improvement, and possible regression. For example: improve valid tool-call format while monitoring argument correctness and inappropriate answering.

Choose metrics on independent examples and define the release gate before seeing the result. Training loss is a diagnostic, not the final application criterion.

Next week we reduce trainable parameter state with LoRA. That optimization still depends on the dataset and objective you design now.

Worked practice and a readiness check

Create correct-format, wrong-format, insufficient-evidence, and wrong-version examples. Inspect their serialized tokens and loss masks.

Propose a grouped split and audit ten records. Identify one failure that SFT is unlikely to repair because the relevant evidence is absent.

You are ready when “fine-tune the model” means a specific dataset, objective, trainable configuration, baseline comparison, and evaluation plan.

Reference details and checks

Review A: Intuition

When an assistant fails, changing model weights is only one possible intervention. Missing source material suggests ingestion. Missing relevant passages suggests retrieval. An answer that ignores available evidence suggests context, prompting or model capability. Consistently wrong output format may be a candidate for supervised fine-tuning. Diagnose the failed boundary before paying a training cost.

Prompting changes instructions and demonstrations at inference time. RAG changes the information supplied. Supervised fine-tuning changes parameters to imitate desired outputs. Continued pretraining changes parameters through a language-model objective on new text. Preference optimization changes relative preferences among possible responses. These methods can coexist, but they solve different immediate problems and have different update costs.

Review A: SFT dataset design

An SFT example contains inputs and a target response. For our assistant, teach a narrow behavior such as selecting a valid tool or producing an evidence-referencing JSON answer. Include answerable tasks, insufficiency cases, version-specific evidence and tool failures. If every example is answerable, the model may learn that producing an answer is always rewarded.

The target must be correct under the supplied context. A synthetic generator can create plausible but wrong examples; manually audit a sample and use executable or source checks where possible. Save provenance and generation settings. Split by task family or documentation group before making paraphrases. Otherwise stylistic near-duplicates can leak into evaluation.

Review A: Worked intervention decision

Imagine 50 development failures: 25 have missing evidence, 10 contain the right evidence but invalid JSON, 10 require an unavailable calculation tool, and 5 are genuinely ambiguous. Training on all 50 would mix four causes. Fix ingestion/retrieval first, add a typed calculation interface, and clarify ambiguous tasks. Fine-tune format adherence only if prompt/schema constraints still leave a measured gap.

For an answer-only loss, mask prompt tokens with an ignored label and supervise answer tokens. Keep the evidence in the input. Do not train on the final held-out labels or use the hidden test set to choose the number of epochs. Record truncation rates; an example whose target is cut away provides no intended supervision.

Review A: Experiment

Tutorial 24: Fine tuning starts with a teaching dataset builds training records, checks source IDs and splits grouped tasks. Its tiny synthetic examples teach the data pipeline, not a useful production behavior. Build a larger, reviewed development dataset for your real project. Before training, write a prediction: which metric should improve and which might regress? Keep the frozen RAG baseline for comparison.

Exit criterion: justify SFT with an error taxonomy and construct a leakage-aware dataset. Reading: Stanford CS336 Language Modeling from Scratch (R01) post-training topic; Hugging Face PEFT LoRA guide (R14) configuration overview. Tutorial: 24.
