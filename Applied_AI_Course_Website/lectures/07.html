Notation in this lesson

B: batch · T: tokens · d_model: model width · H: query heads · H_kv: key/value heads · d_head: query/key width per head · d_value: value width per head

Row and column conventions describe the same map

Attention chapters store token vectors as rows: y_row=x_row*W_row. Week 25 uses column vectors to match the common LoRA formula: y_col=W_col*x_col. They are transposes of the same calculation: x_col=x_row transpose and W_col=W_row transpose. A [d_in,d_out] row-convention matrix therefore becomes [d_out,d_in] in column convention. H_kv is reserved for the later grouped-query/cache discussion; ordinary attention here has one K/V set per query head.

One token can have several computational roles

Last week we chose attention weights by hand. A transformer needs to compute them from representations. Take the six rows for “I go to school by bus.” Each row begins as a token representation, with position information added later in our full model.

For attention, learned linear transformations create a query vector, a key vector, and a value vector from each row. They are different views of the same starting representation, optimized for different roles in the computation.

Query, key, and value are names for roles. They do not mean a human-written question, a word's dictionary definition, and a factual answer. Keeping the names separate from literal natural-language meanings makes the mechanism easier to reason about.

Linear projection with visible numbers

Let one input row be x=[1,2]. Let Wq be the identity matrix, Wk=[[1,0],[0,0.5]], and Wv=[[2,0],[0,1]]. Using row-vector notation, q=xWq=[1,2], k=xWk=[1,1], and v=xWv=[2,2].

The input row is the same, but the projected vectors differ. In a trained model, these projection matrices are parameters changed by the loss. We chose simple matrices only to make every multiplication easy to inspect.

Changing Wk changes how the position participates in comparisons. Changing Wv changes the information contributed after the weights have been computed. These effects can be studied separately.

A shared notation for attention dimensions

We use d_model for the token-representation width, d_head for one query/key head width, and d_value for one value-vector width. T counts positions, B counts batch examples, and H counts heads. In ordinary equal-width multi-head attention, d_head=d_value=d_model/H; the single-head shape exercise below deliberately allows a different value width. These symbols name dimensions, not different kinds of vectors.

Applying projections to the whole sentence

If X has shape [T,d_model], Wq has shape [d_model,d_head], and Wk has shape [d_model,d_head], then Q and K both have shape [T,d_head]. Wv can have shape [d_model,d_value], producing V with shape [T,d_value].

The same projection matrix applies at every token position. We do not train one Wq for the first word and another for the sixth word in ordinary self-attention. Sharing parameters lets the operation work over different sequences.

The number of positions T and the number of features d_model describe different things. Multiplying X by a projection changes feature coordinates; it does not by itself mix token positions.

Comparing all query key pairs

For one query q_i, dot it with every key k_j. Arranging the results for all i and j gives QKᵀ, a [T,T] score matrix.

Suppose T=6. Entry [4,1] describes query position 4 compared with key position 1 under zero-based indexing. It is not a vocabulary score for word ID 1.

This is the first operation in this attention block that explicitly compares positions with one another. The later weight-times-value multiplication then moves information across positions.

A complete two-position example

Let Q=[[1,0],[0,1]], K=[[1,0],[0,1]], and V=[[2,0],[0,4]]. The unscaled score matrix is the identity matrix. For the first query, scores [1,0] become softmax weights approximately [0.731,0.269].

Its output is approximately [1.462,1.076]. The second query has the opposite score pattern and output approximately [0.538,2.924].

Both outputs can include both values. The operation does not force each query to choose its matching position exclusively. In week 8, scaling by sqrt(d_head) will change these numbers, and masking may remove some contributions.

Self attention and cross attention use different sources

In self-attention, Q, K, and V derive from representations of the same sequence. In cross-attention, queries derive from one sequence while keys and values derive from another.

For translation, target-side decoder representations can query source-side encoder representations. If the target has length U and the source has length T, the score matrix has shape [U,T], which need not be square.

The rectangular case is a useful check that you understand the axes. Attention fundamentally relates query positions to key/value positions. It does not require their counts to match.

What training can change

Gradients can change the input embeddings and each projection matrix. If a comparison repeatedly helps predict appropriate next tokens, training can reinforce the corresponding computation.

The learned coordinates need not line up with a simple story about “the transport head” or “the school key.” Such interpretations require evidence. The small examples in these lectures explain valid computations, not the discovered internals of a pretrained model.

We can still test the implementation precisely: projection shapes, row sums after softmax, output dimensions, and sensitivity to changing a key or a value.

Worked practice and a readiness check

For X shaped [6,4] and d_head=2,d_value=3, write projection shapes [4,2],[4,2],[4,3], then Q/K/V shapes [6,2],[6,2],[6,3]. The score matrix is [6,6], and the output is [6,3].

For cross-attention with four queries and seven key/value positions, write scores [4,7]. Explain why softmax still runs across the seven keys for each query.

Before continuing, you should be able to say which operations change feature coordinates, which compare positions, and which mix value information. Scaling and masking will now refine this computation without changing that overall structure.

Changing a key versus changing a value

Keep Q and K fixed in the two-position example, but replace the second value [0,4] with [0,8]. The attention weights stay the same because their computation did not use V. The second coordinate of each mixed output doubles.

Now restore V and change a key instead. The dot-product scores change, so softmax can redistribute the mixture across both value vectors. This distinguishes the comparison role from the information role without requiring any interpretation of natural-language meaning.

For a third experiment, change only one query row. That changes that row's comparisons while leaving other query rows' scores unchanged before later processing. These controlled perturbations are excellent small tests. They explain which tensor participates in which stage more clearly than memorizing the letters Q, K, and V.
