Decoding and the chat contract

Intuition

The model produces a distribution, but a decoder decides how to turn it into text. Greedy decoding takes the highest-scoring next token. Temperature rescales logits before sampling. Top-k restricts to k candidates; top-p restricts to a probability-mass subset. These choices alter behavior, latency and reproducibility. Lower temperature does not make facts true.

Suppose two logits are (2,0). With temperature 1 the first-token probability is about 0.881. With temperature 2 it is about 0.731; with temperature 0.5 it is about 0.982. Greedy decoding is a separate argmax procedure; do not implement it by dividing by temperature zero.

Messages are serialized input

A chat model still receives tokens. Its tokenizer's chat template encodes role separators, message delimiters and the beginning of the assistant response. A hand-written string saying “system:” is not necessarily equivalent. Use the model's own apply_chat_template, inspect a rendered example, and avoid adding special tokens twice. In notebook 04, generation uses only newly produced tokens, not the prompt echoed back as an answer.

Instruction hierarchy and context construction influence behavior, but a prompt is not a security boundary. Retrieved pages can contain imperative text. Treat them as evidence whose authority is bounded by application policy. The model can suggest an action; only code with explicit authorization may execute it.

Output contracts

For our assistant, require an answer or an explicit insufficiency message, source IDs, and the requested version. Structured output helps downstream parsing, but JSON syntax alone does not establish truth. Validate fields, types, allowed IDs and evidence relationships. A citation to an existing page can still be irrelevant to the claim.

Generation needs termination rules: maximum new tokens, stop sequences where appropriate, request timeout and cancellation. A model can spend the entire output budget repeating itself. Include truncation and parse failure in evaluation, rather than dropping those examples from the denominator.

Experiment

Notebook 04 loads a small instruction model, serializes messages with its chat template, and answers a versioned documentation question using supplied evidence. Compare greedy decoding and sampling across repeated runs with fixed inputs. Record model revision and the actual prompt token count. A seed improves reproducibility but does not promise identical outputs across different kernels, hardware or software versions.

Common failure: the question asks about version 2 while the context includes both versions with no labels. More eloquent wording will not reliably repair ambiguous evidence. Filter and label the context first. Reading: R09 and R23. Lab: 04.
