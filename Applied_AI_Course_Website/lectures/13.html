Semester 1 / Week 13

Generation decoding and the KV cache

Tutorial 13Test your understanding
Lecture slides · Week 13

Learn one step at a time.

Read each explanation, pause to predict the result, then continue. Use the arrow keys while the presentation is focused. The complete lecture reader is below.

Start with an example

The model gives options before it gives a sentence

Return to “I go to school by.” A trained model produces a score for each vocabulary token. A decoding rule turns those scores into the next selected token.

Greedy decoding takes the largest score. Sampling chooses according to a distribution, possibly modified by temperature or filtering. These can generate different continuations from the same model.

The decoder is a decision procedure over predictions. It does not check whether the selected sentence is a true report of someone's commute.

Start with an example

A small sampling distribution

Suppose bus, train, bicycle, and boat have probabilities [0.5,0.3,0.15,0.05]. Greedy selects bus. Repeated sampling may choose all four with frequencies approaching these probabilities under ideal repeated independent draws.

With top-k=2, retain bus and train and renormalize to [0.625,0.375]. With top-p=0.8 under a convention including the token that reaches the threshold, the same two tokens remain.

Boundary and tie conventions depend on the implementation. State them when comparing a hand calculation with a library.

Build the mechanism

Generation changes the next input

After choosing bus, the next prefix includes bus. The model may predict a period. After choosing train, subsequent words may differ.

Generation is therefore not a list of independent classifications. Earlier selections change later conditions. A locally most probable token need not form the globally most probable complete sequence.

Beam search keeps several partial sequences according to a scoring rule, but its usefulness depends on the task and decoding objectives. It is not a universal replacement for sampling in open-ended generation.

Build the mechanism

Reusing keys and values

In a causal transformer, earlier positions do not depend on future tokens. Their computed key/value states can be retained when appending a new token.

Without caching, a naive generation loop repeatedly processes the entire prefix. With a KV cache, the new token can query cached keys/values plus its own new states, subject to the model's architecture.

The cache stores intermediate representations, not a list of answers. It speeds repeated computation but does not improve the underlying evidence or factual reliability.

Build the mechanism

A three-token cache trace

Imagine the prefix I go to. For each layer, cached keys and values exist for these three positions. To append school, compute the new position's representations and let its query attend to the four available key positions.

The old cached tensors remain associated with the exact earlier prefix. Change I to You, alter model weights, or change earlier role tokens, and reusing the old cache would generally be incorrect.

We will calculate cache memory in week 22. The important idea now is the validity condition that permits reuse.

Build the mechanism

Text models and chat formatting

A conversational model still receives a serialized token sequence. Its tokenizer may include a chat template that marks roles and message boundaries.

Writing the visible text “system:” is not automatically equivalent to the template's special tokens. Inspect a short rendered example and count tokens with the actual tokenizer.

We introduce this interface after the basic generation loop so role formatting is another input construction choice you can explain. It should not hide the next-token mechanism underneath.

Go deeper and check understanding

Stopping and evaluating a continuation

Generation needs a stopping condition: an end token, a specified maximum number of new tokens, or another explicit rule. Maximum length prevents an unbounded continuation but can also truncate a response.

Distinguish input tokens from newly generated tokens when decoding an output tensor. Returning the complete prompt as if it were generated text creates a misleading evaluation.

For our simple examples, inspect whether the continuation is grammatical and consistent with the supplied context. Later tasks will require independent factual and task checks.

Go deeper and check understanding

Worked practice and a readiness check

Apply top-k=3 to [0.5,0.3,0.15,0.05] and renormalize by 0.95. Then explain the difference between temperature adjustment and deleting candidates outside top-k.

Draw cache contents before and after appending one token. Explain why changing an earlier token invalidates reuse, even if the length stays the same.

You are ready when you can trace a complete generation step from prefix IDs through logits, token selection, append, cache update, and termination.

Go deeper and check understanding

The cached computation and a changed prefix

Consider generating after “I go.” Cached keys and values represent those exact two input positions under the chosen model. Appending to can reuse those earlier states in a causal model because future inputs do not change their past computation.

Replace the prefix with “You go.” Its length is still two, but the first token embedding and all dependent earlier states can differ. A cache indexed only by prefix length would return the wrong computation.

Now change the system instruction of a chat prompt while leaving the visible user sentence identical. The full token prefix has changed again. Cache identity must reflect the actual preceding tokens and relevant model configuration, not just the human-visible last question.

This example connects a numerical optimization to correctness. Saving computation is useful only when the reused state belongs to the computation you intend to perform.
