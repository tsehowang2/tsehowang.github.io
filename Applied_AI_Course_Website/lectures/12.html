Start with an example

One sentence supplies several supervised predictions

Take the tokens [I,go,to,school,by,bus]. Build inputs [I,go,to,school,by] and targets [go,to,school,by,bus]. At each input position, the model predicts the next token.

This shift is easy to state and easy to implement incorrectly. If the target equals the token at the same position, a model may learn a different, much easier copying task. Low loss would then answer the wrong question.

Use a printed example of IDs and decoded tokens before beginning a long training run. Check the first and last supervised positions explicitly.

Start with an example

The forward pass produces one vocabulary row per position

For batch size B, sequence length T, and vocabulary size V, logits have shape [B,T,V]. Targets have shape [B,T]. Cross entropy compares each valid row with the corresponding target ID.

The causal mask prevents future input leakage. The loss mask removes padding or other unsupervised target positions from the average. They work at different boundaries.

Flattening logits to [B×T,V] and targets to [B×T] is one implementation convenience. It should preserve the original pairing between each row and target.

Build the mechanism

A training step is a sequence of operations

Choose a batch, run the model, calculate loss, clear old gradients, backpropagate, optionally clip gradients, and update parameters using the optimizer. Repeat with more data.

An optimizer such as AdamW maintains additional state and follows a specific update rule. You do not need to derive it again to inspect whether gradients reach the embedding table and attention projections.

Save a small record at intervals: step, number of valid tokens, training loss, validation loss, learning rate, and any numerical errors. A single final loss hides the path that produced it.

Debugging before judging quality

A one-batch overfit experiment asks whether the model and training loop can fit a tiny fixed batch. It is a useful implementation diagnostic, not a generalization result.

Then restore a separate validation set. Disable dropout and gradient tracking for validation, and return to training mode afterward. Accidentally leaving a model in the wrong mode can change subsequent behavior.

Check finite losses and nonzero gradients. A plotting library cannot repair unshifted targets or an attention mask that exposes the answer.

Build the mechanism

Learning patterns versus memorizing sentences

A tiny collection of school/travel sentences makes every example understandable, but repeated strings make memorization easy. Split complete examples before generating overlapping training windows.

Include a few held-out sentence patterns and report exactly what they test. A tiny model producing “I go to school by bus” does not establish broad reasoning or documentation expertise.

More data, model capacity, and training steps can change results, but changing all of them at once makes diagnosis difficult. Start with a controlled small configuration.

Build the mechanism

Loss and generation tell different stories

A model can reduce average next-token loss while still generating a weak continuation under a particular decoding choice. Generation compounds decisions and can visit prefixes unlike those seen during training.

Conversely, one attractive generated sentence can come from a model with poor average performance. Evaluate several inputs and save raw outputs rather than selecting only the best demonstration.

For matched tokenization, perplexity is the exponential of average negative log probability. Keep the tokenizer and valid-token counting consistent when comparing runs.

Build the mechanism

Batch size and accumulated gradients

If microbatch size is 2 and you accumulate across 4 equally sized microbatches, the effective example batch is 8 on one device. Divide each microbatch loss by 4 before backward if you want the average of those means, and update only after the accumulation group.

Different sequence lengths complicate exact token-weighted equivalence. Four means over different valid-token counts do not automatically equal a single global token mean.

We will study GPU memory and scaling later. For this week, a small float32 CPU run can establish correctness without requiring a large accelerator.

Worked practice and a readiness check

Write the shifted targets for [3,8,2,5]. Then calculate average loss if valid target probabilities are [0.5,0.25,0.25]. Identify which positions should be excluded if one target is padding.

Train the tiny teaching model, save the configuration and loss history, and inspect at least three generated prefixes. Explain one failure using data, capacity, or implementation evidence.

You are ready when you can reproduce a run, show the actual input-target pairing, and distinguish a debugging overfit test from a held-out evaluation.

Optional deeper study

Further study 6 From prediction to loss

Given token IDs x[0:T+1], the input is x[0:T] and the target is x[1:T+1]. For logits z at a position, cross entropy is -log softmax(z)[target]. The language-model loss averages over valid target positions. If the model assigns probability 0.25 to each correct token, loss is -log(0.25)=1.3863 nats and perplexity is 4. Perplexity is comparable only under appropriate matching tokenization and evaluation conditions.

Padding targets should be ignored. In SFT later, prompt positions may also be ignored while answer positions receive loss. Confusing an attention mask with a loss mask is a common bug: one controls information access, the other controls which predictions are supervised.

Optional deeper study

Further study 6 Data quality is an engineering problem

Pretraining data pipelines filter, deduplicate, segment and tokenize. Duplicated or near-duplicated documents crossing train/test boundaries can create inflated evaluations. Split at a meaningful group boundary before producing overlapping chunks. For documentation, a page family or API topic may be a stronger group than an arbitrary text span. Keep version, license, origin, time and transformation metadata.

Gradient descent reduces training loss but does not guarantee the desired application behavior. Use training and validation curves to separate underfitting, overfitting and implementation bugs. Validate with dropout disabled and gradients off, without accidentally leaving the model in evaluation mode for the next training batch.

Optional deeper study

Further study 6 Worked optimization example

If the microbatch size is 2 and you accumulate gradients across 8 microbatches on one device, the effective example batch is 16, provided each microbatch is equally sized. Divide each microbatch's loss by 8 before backpropagation, step the optimizer once, and clear gradients afterward. If sequence lengths vary, equal averaging of microbatch means may not equal a global valid-token average. Account for token counts when exact equivalence matters.

Adam-style optimizers maintain moment estimates, adding substantial memory. Learning-rate warmup and clipping can stabilize some settings, but first verify labels, masks and data. A scheduler cannot repair training on the wrong target. Save optimizer state, random states, tokenizer identity and current step if you want faithful resume behavior.

Optional deeper study

Further study 6 Experiment

In notebook 12, compare train/dev losses for one fixed configuration over time. Intentionally train with unshifted labels once and explain why the task changes. Try a one-batch overfit test, then an actual grouped split. The starter's tiny corpus is too small for strong statistical conclusions; your report should say so.

Exit criterion: implement shifted labels, explain perplexity and list the artifacts needed to resume a training run. Reading: R01 data and optimization lecture headings. Tutorial: 12.
