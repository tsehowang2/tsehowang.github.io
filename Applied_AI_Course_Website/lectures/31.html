The project now has understood components

You have learned the model before using it in retrieval and tool systems. The project combines a focused public documentation corpus, semantic search, source-labeled answers, bounded executable tools, evaluation, and a reproducible API release.

Begin integration by stating the user tasks. Exact lookup, paraphrase, version comparison, troubleshooting, calculation, and insufficient-evidence requests need different success checks.

The architecture should make evidence and action boundaries visible rather than hiding every component behind one framework invocation.

A documentation question from end to end

A user asks how retry waiting changes across two versions. Preserve comparison scope, retrieve both relevant rules, select coherent context, calculate if needed with a validated tool, and form a source-supported answer.

If one rule is absent, the full comparison is unresolved. If a model proposes an invalid call, the controller rejects it. If generation adds an unsupported caveat, the answer rubric catches a different failure.

This trace connects the ordinary school examples with a harder but structurally similar technical task.

Baselines make integration claims defensible

Compare lexical and dense retrieval, a basic and improved context pipeline, base and adapted models for the narrow task, and a fixed workflow against adaptive planning.

Keep the relevant controls fixed and report all calls, failures, and costs. The default release may omit the agent or adapter if neither shows useful improvement.

A negative experiment can demonstrate competent reasoning when its data, configuration, raw outputs, and limitations are available.

Data and final evaluation

Use reviewed task records with expected sources, required facts, allowed tools, group labels, and success predicates. Keep final evaluation separate from adaptation and configuration choices.

Aim for a manageable focused collection rather than an indiscriminate crawl. Preserve source revisions and redistribution terms.

Report task slices, counts, uncertainty, new failures, and resource measurements. A small project cannot justify claims about every documentation domain or high-scale production usage.

Tables images and lost structure

Technical pages contain tables, diagrams, code, and screenshots. A text parser may preserve values while losing their row/column association.

If a table's product-tier labels disappear, retrieval can find the correct page while the answer assigns a number to the wrong tier. Evaluate extraction separately from reasoning over extracted evidence.

A multimodal extension should preserve coordinates/provenance and use an independent small test set. Adding a vision model does not automatically recover every detail.

Scaling as an optional engineering decision

If a real bottleneck appears, identify the resource before choosing parallelism. Data parallelism replicates a model over different batches. Tensor parallelism partitions layer computation. Pipeline parallelism partitions layers and schedules microbatches.

State sharding can reduce replicated optimizer/gradient/parameter state with communication costs. Activation checkpointing addresses a different memory component.

With 70% perfectly scalable work and 30% serial, ideal four-way speedup is 1/(0.3+0.7/4)≈2.105 before communication. A theoretical memo is acceptable when multiple GPUs were not actually measured.

An ethics and governance check before release

A correct-looking assistant can still serve groups unequally. Compare performance on English and Hong Kong Chinese questions, different phrasing, missing answers, and accessibility needs. Report slice sizes and errors. A bilingual interface is not evidence of equal answer quality. Tell users when an answer is generated, preserve a way to challenge a consequential error, and keep human responsibility clear for decisions affecting people.

Maintain separate license records for model weights, source code, training data, retrieved documents, and redistributed outputs. “Open weights” does not mean every use is unrestricted. A page being publicly readable does not by itself establish permission to redistribute its full contents or use it in every training context. Check license terms, permitted use, attribution, and the applicable copyright rules; document unclear permissions instead of inventing a blanket research or AI exception.

Energy is another measurable resource. A hypothetical device averaging 100 watts for 2 hours uses 0.2 kWh of device energy. Account for CPU, GPU, utilization, duration, and the system boundary; carbon emissions additionally depend on electricity carbon intensity and other assumptions. Reuse compatible cached computation and stop unhelpful experiments. Record estimates as estimates, not as a universal emissions-per-token value.

Regulation depends on the place, activity, and role of the organization. Hong Kong personal-data obligations, model and data licenses, consumer-facing representations, and rules in a destination market can apply to different parts of one system. The EU AI Act, for example, distinguishes roles and risk categories and has phased obligations. Keep a dated applicability record using official regulator guidance. The purpose here is to recognize questions requiring review, not to memorize a worldwide legal checklist.

Before the final release, answer five concrete questions: which user groups were tested; which personal data are necessary; which licenses permit the intended use; which person owns incident response; and which resource and regulatory assumptions were recorded. Attach the answers to the existing release checklist rather than treating ethics as an unrelated essay.

The final release candidate

Identify all artifacts, run invariant and integration checks, execute the planned task evaluation, and inspect representative traces. Record quality and latency gates before deciding.

Reproduce in a clean directory using the documented downloads and environment. Cached notebook variables should not be an undocumented dependency.

Prepare a demo that includes a correct lookup, a comparison, a tool task, a genuine absence, and a controlled failure.

Worked practice and a readiness check

Use the capstone rubric to identify the weakest evidence in your project. Run one focused improvement experiment or document why the simpler qualifying system remains preferable.

Write a capacity/extension memo only if it addresses an observed need. Distinguish actual implementation, measured results, and future proposals.

You are ready when the integrated system's claims can be traced to artifacts, examples, and tests you understand.

Reference details and checks

Review A: Intuition

One GPU may run out of memory or take too long. Distributed techniques divide data, parameters or computation, but communication becomes part of the cost. This week develops the decision framework; it does not require access to multiple GPUs.

Data parallelism replicates the model, processes different batches and synchronizes gradients. It improves throughput when enough work amortizes communication, but each replica still needs the model state. Sharding optimizer state, gradients or parameters reduces per-device memory with additional communication. Tensor parallelism partitions operations within layers. Pipeline parallelism partitions layers and schedules microbatches, introducing bubbles and coordination.

Review A: Efficiency mechanisms

Activation checkpointing recomputes selected forward work during backward to save activation memory. Gradient accumulation reduces the required microbatch for an effective batch, but does not reduce all optimizer/model state. Mixed precision changes storage and arithmetic where supported; float16 may need gradient scaling and bfloat16 availability is hardware-dependent. Quantization and adapters address different parts of the resource budget.

Review A: Worked scaling estimate

For the same global batch, a step taking 100 ms on one device and 60 ms on two has speedup 100/60 approximately 1.67 and two-device scaling efficiency about 83%. If the global batch changes, report examples or tokens per second and the changed optimization conditions. Comparing step times alone would mix different amounts of work.

For another example, if 70% of time can scale perfectly and 30% cannot, four-way ideal speedup is 1/(0.3+0.7/4) ≈ 2.11 . Real communication can reduce it further. These estimates are planning aids, not measured predictions.

Review A: Experiment

Use the memory estimates in Tutorial 22: Cpu gpu memory and model resource accounting and the profiling measurements in Tutorial 23: Cuda kernels and profiling to write a capacity memo: what bottleneck would a second GPU address, what remains replicated, what communication is introduced, and what experiment would validate the plan? Distinguish inference model parallelism from training-state sharding. Exit criterion: choose a plausible technique for a named memory/throughput bottleneck and state its costs. Reading: Stanford CS336 Language Modeling from Scratch (R01) parallelism topics; PyTorch automatic mixed precision recipe (R18) . Tutorial: 31.

Review B: Intuition

Technical documentation contains tables, diagrams, screenshots and code. A text-only parser may discard the information needed for an answer. Multimodal support begins with preserving evidence and evaluating extraction, not merely swapping in a vision-language model.

OCR extracts text from images but can misread symbols, units and indentation. Table extraction must preserve row/column relationships. A vision-language model can combine visual and textual inputs, but small screenshots or dense diagrams can still be difficult. Store page/image coordinates and source references so citations point to the right region. Evaluate extraction separately from reasoning over the extracted material.

Review B: Generative families revisited

For diffusion, a forward step can be written xt = sqrt(alpha_bar_t)*x0 + sqrt(1-alpha_bar_t)*epsilon with standard Gaussian epsilon. Training often teaches a network to predict noise or a related target; sampling repeatedly denoises from noise under a schedule. This differs from next-token autoregression, though real systems may combine architectures and representations.

A VAE learns a latent variable model with a reconstruction/regularization objective. GANs use adversarial learning. Flow matching learns a vector field connecting distributions. These survey concepts help read image/audio generation documentation; implementing a high-quality image generator is outside the core capstone.

Review B: Other adjacent topics

Mixture-of-experts architectures route tokens to subsets of expert networks, affecting active compute, total parameters and communication. Longer-context models can accept more evidence but still need retrieval selection, latency control and evaluation. Model-context and agent communication protocols standardize interfaces; they do not automatically provide authorization, correct tool semantics or reliable planning. Treat new frameworks as replaceable implementations of contracts you already understand.

Review B: Worked evidence problem

A screenshot table lists timeout defaults by product tier. Flattened OCR returns the numbers but loses the tier labels. Retrieval finds the page, yet the generator associates the wrong number with the requested tier. The error belongs to extraction/structure before language generation. A page-level citation does not repair the false association.
