LoRA and QLoRA from a small matrix

Tutorial 25Test your understanding
Lecture slides · Week 25

Learn one step at a time.

Read each explanation, pause to predict the result, then continue. Use the arrow keys while the presentation is focused. The complete lecture reader is below.

Start with an example

Training fewer parameters

A full model can contain many weight matrices. Fine-tuning every entry requires trainable state for all those parameters. LoRA instead keeps a base matrix fixed and learns a structured update using two smaller matrices.

Begin with one layer y=Wx using column-vector notation. The base W still processes the input. An additional path contributes a learned change.

This changes how we parameterize adaptation. It does not supply missing evidence, review training labels, or guarantee an application improvement.

Start with an example

A two by two update by hand

Let A=[0.1,0.2] have shape [1,2], and B=[[1],[2]] have shape [2,1]. Their product BA is [[0.1,0.2],[0.2,0.4]].

The two rows are proportional, so this update has rank at most one. Multiplying BA by x=[1,1] gives [0.3,0.6]. Add that contribution to the base layer's Wx output.

The tiny case makes the computation visible but does not yet save parameters: A and B have four entries, the same count as a 2×2 dense matrix. Savings depend on dimensions and a sufficiently small rank.

Build the mechanism

General shapes and the savings condition

For W shaped [Dout,Din], choose A shaped [r,Din] and B shaped [Dout,r]. Adapter parameters total r(Din+Dout), compared with Din×Dout for W.

At Din=Dout=1000 and r=4, the adapter has 8000 parameters compared with one million in the dense matrix. The update is restricted to a low-rank factorization.

Increasing r increases capacity and trainable state. It does not guarantee monotonically better held-out quality. Compare ranks under a defined dataset and training budget.

Build the mechanism

Scaling and zero update initialization

A common expression is y=Wx+(α/r)BAx. The factor α/r controls the scale of the update under this parameterization.

An initialization with one factor zero and the other nonzero starts with BA=0 while allowing a trainable gradient path. Initializing both factors to zero can make both initial factor gradients zero.

This is worth checking in code: the adapted model should start close to the base computation under comparable modes, and trainable adapter parameters should receive the expected gradients.

Build the mechanism

What stays in memory

The frozen base still occupies memory and participates in forward computation. Activations needed to learn the adapters can also be substantial.

LoRA reduces the trainable parameter and optimizer-state portion. It does not turn a large model into a tiny activation footprint or remove all backward computation.

Use the week-22 resource accounting to identify which state changed. A small adapter file is only one part of the full model/runtime requirements.

Build the mechanism

QLoRA adds a quantized frozen base

QLoRA combines low-rank adaptation with a quantized base representation. Some tensors, computations, and trainable states remain in higher precision.

Four-bit base weights do not imply four-bit activations, gradients, optimizer states, or a universal speedup. Hardware and kernel support matter, especially on an older local GPU.

The required experiment uses a small ordinary LoRA model. A quantized comparison is an optional extension if the runtime supports the chosen backend and the experiment fits the available time.

Build the mechanism

Saving and using an adapter

Save adapter weights and configuration together with the exact base model and tokenizer identities. Applying a checkpoint to an incompatible base can change behavior or fail.

Some adapter updates can be merged into a compatible base for inference. Quantized merging and numerical behavior require validation rather than an assumption.

Test a saved/reloaded artifact, not only the in-memory object that just trained. The next week performs this complete experiment.

Worked practice and a readiness check

Calculate adapter shapes and count for a 4096×4096 matrix at rank 8. The result is 65536 adapter parameters, or about 0.390625% of the dense matrix.

Explain why a rank-one update cannot represent every possible 2×2 change. Then describe one memory cost LoRA reduces and one that remains.

You are ready when the factorization, scaling, initialization, memory implications, and checkpoint dependencies are concrete numerical statements.

Optional deeper study

Further study 18 Mechanism

A dense layer computes y = W x. LoRA freezes W and learns delta_W = (alpha/r) B A, so y = W x + (alpha/r) B A x. For W shaped [d_out,d_in], A has [r,d_in] and B [d_out,r]. Only r*(d_in+d_out) adapter parameters are trained for that layer. The choice of target layers is part of the experiment.

For a 4096×4096 matrix and r=8, the dense matrix has 16,777,216 parameters while A and B total 65,536, about 0.39%. This reduces trainable optimizer state substantially. It does not eliminate frozen model storage, activations or forward/backward computation through the model. LoRA can be applied to attention projections and other layers; examine actual module names rather than copying a configuration blindly.

Optional deeper study

Further study 18 Initialization and scaling

A common initialization makes one factor zero so the initial update is zero while the other factor is random. Then the adapted model initially reproduces the base computation, apart from training-mode effects such as dropout. If both factors are zero, both factor gradients can initially be zero. Rank controls update capacity, not a guaranteed quality ordering. Increasing rank also changes parameters and potentially tuning behavior, so compare under a defined budget.

Optional deeper study

Further study 18 QLoRA

QLoRA combines a quantized frozen base with low-rank trainable adapters [R13]. Four-bit base weights do not imply every tensor or calculation is four-bit. Quantization scales, compute dtype, adapters, gradients, optimizer states and activations remain relevant. Specialized backend support depends on hardware and software. The course requires a small ordinary LoRA run; a QLoRA comparison is optional if the available runtime supports it.

Optional deeper study

Further study 18 Deployment considerations

Save the adapter with base model/tokenizer identity and target modules. An adapter checkpoint alone is insufficient if the base revision is unknown. Merging low-rank weights into a compatible unquantized base can remove the separate adapter path, but numerical behavior and quantized merge support require checking. Test the saved/reloaded artifact, not just the in-memory training object.

Optional deeper study

Further study 18 Experiment

notebook 24 calculates trainable parameter counts and inspects a planned model. notebook 26 creates actual adapters and confirms which parameters receive gradients. Compare your analytical count with the model's count and explain biases or excluded modules. Estimate memory before loading, then measure after the first training step.
