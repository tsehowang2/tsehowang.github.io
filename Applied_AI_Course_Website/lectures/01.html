Unseen continuations and smoothing

Exact counting assigns zero probability to a vocabulary item with no observations. If a prefix has no matching examples at all, the empirical conditional distribution is undefined, rather than every next word having probability zero. One simple fallback is add-alpha smoothing: p(w|prefix)=(count(w)+alpha)/(total+alpha*V), for a fixed vocabulary of size V and alpha>0. With no matches and three allowed words, alpha=1 gives 1/3 each. This shares probability mass, but it does not learn that school and work are related.

An ordinary sentence with one missing word

Start with “I go to school by ___.” Before thinking about a neural network, write three possible completions. Bus, train, and bicycle are all reasonable. Banana is grammatically possible after “by” in some strange invented story, but it is an unlikely completion of this ordinary sentence. The task is to assign different probabilities to possible next pieces of text using the words already available.

Now shorten the prompt to “I go to ___.” School is possible, but work, sleep, and the park become plausible too. The plausible next word changed because the available context changed. Context means the text on which a prediction depends. During the first part of this course, context is simply a prefix of an ordinary sentence.

The model does not need to know your actual commute to assign a high probability to bus. It might have learned that people often describe travel to school this way. This distinction matters. A likely continuation can sound sensible while being false about a particular person. Prediction is the starting task; truthful question answering requires additional decisions we will study much later.

A tiny collection that we can inspect

Imagine five training sentences: “I go to school by bus” appears three times, “I go to school by train” appears once, and “I go to school by bicycle” appears once. Among examples with exactly the prefix “I go to school by,” the observed next-word proportions are 3/5, 1/5, and 1/5. Our first language model can therefore predict bus with probability 0.6, train with 0.2, and bicycle with 0.2.

These numbers describe our tiny collection, not transportation in the real world. Change the collection and the estimates change. If the collection contains no sentence about boats, a count-based model has no direct evidence about boat for this prefix. A later neural model can share information across related contexts, but it still learns from the examples and objective we give it.

We have already identified the essential ingredients of a learning problem: examples, an input, possible outputs, predictions, and a way to judge them. We will add numerical representations and trainable functions gradually rather than introducing a complete transformer all at once.

A prediction becomes a sequence

Suppose the model selects bus. The available text is now “I go to school by bus.” To continue, it makes another next-token prediction using this longer prefix. It might choose a period. If an end marker follows, generation stops. Generating a paragraph repeats this operation many times.

This is autoregressive generation: each new prediction depends on earlier elements of the sequence. The model need not choose the whole paragraph in one decision. During generation, a mistake becomes part of the prefix for later predictions, which helps explain why a continuation can drift. Choosing an unlikely word once changes the situation the model sees next.

For now, imagine tokens are words. Week 2 will replace that simplifying assumption with a precise description of token IDs, punctuation, and subwords. A useful first explanation can make a simplifying assumption, provided we state it and later remove it.

Conditional probability in familiar notation

Write p(bus | I go to school by). The vertical bar reads “given.” It asks for the probability of bus given that prefix. The probabilities across all allowed next tokens add to one. A language model is a function that produces such a distribution for each prefix.

The probability of a whole sequence can be written as a product of conditional probabilities. For a short example, p(I, go, home) equals p(I) multiplied by p(go | I) multiplied by p(home | I go). This chain-rule decomposition is a probability identity. A particular language model supplies estimates of those terms.

If those three probabilities are 0.5, 0.4, and 0.25, the sequence probability is 0.05. A longer sequence accumulates more factors, so raw probabilities of sentences with different lengths require care when comparing them. Later we will average negative log probabilities over prediction positions.

Training and using a model are different activities

During training, we use examples to adjust a model. During inference, we use the resulting model to make predictions. Our count-based model “trains” by counting. A neural language model trains by changing numerical parameters so that appropriate next tokens receive higher probability on the training examples.

The sentence “I go to school by bus” can provide several training situations. “I” predicts go. “I go” predicts to. “I go to” predicts school. We do not need a person to label each of these separately because the next token already appears in the text. This is the basic self-supervised signal behind next-token training.

Do not confuse a training example with a command to the model. A sentence is data from which we derive prediction tasks. Instruction following will enter the course after we understand how the underlying prediction model works.

A small model can be useful for understanding

Our five-sentence collection cannot support a general assistant. Its value is that every probability can be explained. If a later program gives bus probability 0.2 instead of 0.6, we can inspect counts and find the mistake.

A larger model introduces learned vectors and nonlinear functions, but the questions remain recognizable: What input did it receive? Which output did we expect? What probability did it assign? What changed during learning? Keep returning to these questions when the equations become more complex.

The first semester will develop a transformer as a solution to representing and combining context. We will postpone vector databases, RAG, agent frameworks, and deployment until the model itself is familiar.

Worked practice and a readiness check

Add “I go to school by train” twice more. There are now seven matching examples: bus three, train three, bicycle one. The probabilities become 3/7, 3/7, and 1/7. Bus and train tie under the count model. A tie does not mean the task is broken; the observed data simply do not distinguish them.

Explain why “I go to work by” might require a different distribution. Then explain what information a simple exact-prefix count model cannot share between school and work. That limitation will motivate learned representations.

Before continuing, you should be able to distinguish an example, a prefix, a next-token distribution, a generated token, training, and inference. You should also be able to say why a probable sentence need not be a true statement about the user. The tutorial builds this tiny count model without a neural-network library.
