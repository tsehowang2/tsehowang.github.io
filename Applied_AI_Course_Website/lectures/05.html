Semester 1 / Week 05

Why language needs context and order

Tutorial 05Test your understanding
Lecture slides · Week 05

Learn one step at a time.

Read each explanation, pause to predict the result, then continue. Use the arrow keys while the presentation is focused. The complete lecture reader is below.

Start with an example

The same word can appear in different situations

Read “I go to school by bus” and “The bus is late because it broke down.” The token bus participates in different relationships. In the second sentence, it refers back to the bus. A model that processes each token independently cannot use the sentence to resolve that relationship.

The word order also matters. “The boy follows the bus” and “The bus follows the boy” contain the same words but describe different events. A representation based only on which words are present loses this distinction.

We now need a mechanism that transforms starting token vectors into representations that depend on other positions. This is the problem attention will address. First, examine simpler ways of supplying context.

Start with an example

A fixed window sees only part of the sentence

A window model might predict the next token from the last two tokens. For “I go to school by,” it sees only school by. This can be useful, but information earlier in the sentence disappears when it falls outside the chosen window.

Increasing the window adds context but also changes the input size and parameters of some simple architectures. A sentence with a dependency farther away can still exceed the window.

This is not a proof that every fixed-window model performs poorly. It identifies a structural choice and its limitation. We want to understand what information an architecture makes available before debating benchmark results.

Build the mechanism

A recurrent model carries a state

A recurrent neural network processes one token at a time. A simplified recurrence is h_t=f(Wx_t+Uh_(t-1)+b). The new state combines the current token vector with the previous state.

Imagine reading I, then go, then to. The state after to can carry some information about all three words. The sequence has a natural processing order because the next state depends on the preceding one.

That state has finite width and must carry useful information through repeated updates. Learning long dependencies can be difficult, and training involves sequential dependencies across time. Gated recurrent architectures address some problems but do not remove every tradeoff. We introduce them to understand the problem, not to claim that recurrence is incapable of language modeling.

Build the mechanism

A simple state update illustrates information loss

Take a scalar recurrence h_t=0.5h_(t-1)+x_t, starting at zero. If the input values are [1,0,0,0], the states are [1,0.5,0.25,0.125]. The effect of the first input decays.

This is a designed arithmetic example, not a claim that a trained RNN always uses a decay of 0.5. It shows how repeated transformations can change the influence of earlier information.

If the task needs the first word exactly after many steps, a compressed state must preserve that useful detail. Attention will offer another access pattern: compare the current representation directly with representations at available positions.

Build the mechanism

Reading a source and producing a target

Translation gives a concrete context problem. “I go to school by bus” can be an input sequence, while a translated sentence is a different output sequence. An encoder reads the source and constructs representations. A decoder produces the target under a generation rule.

A single fixed vector could summarize the whole source, but important details may be hard to preserve as sentences grow. An attention mechanism can let each target position consult different source positions.

This source-target example motivates cross-attention. Self-attention, which we study first, compares positions within the same sequence. The distinction concerns where the vectors come from, not whether the method is “thinking about itself.”

Build the mechanism

What the current position is allowed to see

For next-token generation, the prediction from “I go to school by” must not use the answer bus before it has generated it. If a training computation accidentally reads future tokens, it solves an easier problem than the inference task.

For a sentence encoder used to represent a fully observed input, reading words on both sides of a position can be appropriate. The task defines the allowed information. There is no universal rule that every language model must use the same mask.

We will separate architecture from visibility. A causal decoder uses a left-to-right visibility pattern; an encoder commonly uses a bidirectional pattern over valid input positions.

Go deeper and check understanding

The bridge to attention

Suppose you are filling the final word in a sentence. You might consult different earlier clues rather than relying on one compressed note. Attention turns that idea into a learned numerical mixture of value vectors.

The first explanation in week 6 will use visible weights that we choose by hand. Week 7 will show how learned projections produce the scores. Week 8 will add scaling and causal masks carefully.

This ordering lets us inspect the mixture before introducing every matrix in the final formula. A beginner should be able to calculate the output of a tiny attention example before memorizing its compact equation.

Go deeper and check understanding

Worked practice and a readiness check

For the recurrence h_t=0.5h_(t-1)+x_t, compute the states for [0,0,0,1]. Compare the final state with the previous example. Order changes the result because earlier inputs undergo more transformations.

Write an example where a two-token window loses useful context. Then identify whether a translation decoder is consulting the source sequence or its generated target prefix in each of two proposed attention operations.

You are ready when context, order, recurrence, encoder, decoder, self-attention, and cross-attention are recognizable ideas. You do not yet need to implement a translation system or use an orchestration framework.

Go deeper and check understanding

Context access as a diagram you can test

Write “I go to school by bus” as six boxes. For the representation at school, draw connections to the information permitted by each model. A two-token window, a recurrent state, and full valid-input attention offer different paths.

For an autoregressive prediction from school, cross out by and bus because they are future input positions. For an encoder of the complete sentence, those words may remain available. The same sentence can therefore support different legitimate computations under different tasks.

Avoid explaining the difference only by saying that one model “reads better.” The diagram identifies actual dependencies. A property test can then change an unavailable token and check that it has no effect where access is forbidden. This turns a verbal rule into a measurable implementation condition.
