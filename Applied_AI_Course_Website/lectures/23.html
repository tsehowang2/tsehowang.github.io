Planning and memory

The agent and its controller

Intuition

An agent's “memory” can mean its current prompt, a task scratch state, retrieved documents, or a persistent store of previous interactions. These have different retention and trust properties. More remembered text is not automatically more useful context.

Maintain a typed task state for facts such as requested version, selected source IDs and tool outcomes. Summaries can compress long histories, but they can omit an exception or turn an uncertain observation into a confident assertion. Preserve critical constraints in structured fields and retain source provenance.

Planning patterns

ReAct-style systems interleave action selection and observations. Plan-and-execute generates a plan and then performs it, potentially revising it when observations disagree. Routing chooses a specialized workflow. Multi-agent systems distribute roles but add coordination, duplicated context, cost and evaluation complexity. A single bounded controller is the core path here; multi-agent implementation is not required.

A fixed workflow for versioned lookup may be retrieve, pack, answer and validate. A troubleshooting task may benefit from conditional actions: inspect version, retrieve a rule, validate a config, then explain the first violated requirement. The latter supplies a concrete reason for adaptive planning.

Worked memory failure

A user first asks about v1, then says “now compare that with v2.” A summary storing only “user uses v1” can cause the next retrieval to filter out v2. Keep the task's allowed versions and comparison intent explicit. Authorization should come from authenticated application state, never from conversational memory or model-generated summaries.

Experiment

Notebook 12 converts a small model's JSON proposal into a controller action. Compare it with a fixed workflow on the same set of lookups, calculations and troubleshooting tasks. Count invalid proposals, unnecessary tool calls, missed required actions, completion, latency and total model tokens. A small model may fail often; use those traces to decide where a deterministic route is preferable.

Test a long irrelevant observation and a misleading instruction embedded in a retrieved page. Verify that policy fields stay outside the model's authority. A failed model proposal must produce a controlled result, not fall back to executing guessed arguments.

Exit criterion: justify adaptive planning for a specific task and identify which state belongs in structured memory. Reading: R11; R03 context engineering. Lab: 12.
