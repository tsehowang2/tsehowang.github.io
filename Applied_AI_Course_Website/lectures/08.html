Reasoning and chain of thought

Tutorial 04Test your understanding

Intuition

Some questions require intermediate computation: “If each retry doubles a 100 ms backoff, what is the delay before attempt four?” Asking for intermediate steps can help some models and tasks, but a polished explanation can accompany a wrong answer. Treat reasoning approaches as experimental interventions, with answer correctness and resource use measured separately.

Chain-of-thought prompting supplies or requests intermediate reasoning before an answer. Reasoning-trained models may use additional inference computation without exposing every internal step. A displayed rationale is generated text; it is not a reliable transcript of internal causality. For deployment, request a concise justification, evidence and verifiable results rather than storing unrestricted deliberation.

Mechanisms to compare

Direct answering minimizes tokens. Decomposition splits a task into explicit subproblems. Self-consistency samples multiple solutions and aggregates final answers; it can help when errors vary, but correlated errors remain. A verifier checks candidate results, often with executable tests or source evidence. Search explores alternative actions or solutions under a budget. More inference computation creates a cost/quality tradeoff, not a guarantee.

Worked example

Assume the first retry delay is 100 ms, then 200 ms, then 400 ms, with no jitter. The delay immediately before the fourth attempt is 400 ms; the cumulative waiting time before that attempt is 700 ms. If the wording does not distinguish these, both evaluation and generation become ambiguous. Define the task before comparing prompting methods.

For documentation, a stronger approach is often to retrieve the authoritative retry rule and pass numerical arguments to a calculator. The executable result can be independently checked. A long free-text calculation without the correct version of the retry rule remains unreliable.

Experiment

Prepare 20 development tasks: ten arithmetic or configuration tasks with executable answers, five source lookups, and five ambiguous/unsupported requests. Compare direct answers, concise decomposition and tool-assisted verification using the same model and task set. Record exact answer accuracy, unsupported-claim rate, token count, latency and parse failures. If you sample multiple candidates, report the total generation budget, not the cost of the winning candidate alone.

Use the checkpoint quiz before reading its solutions. Write down one hypothesis about where reasoning helps and another about where it adds unnecessary work. Your conclusion may be that a small model cannot perform the chosen tasks reliably; that is a valid measured result.

Exit criterion: distinguish CoT, reasoning training, verification and tool execution, and explain why rationale quality is not the same as answer correctness. Reading: R10; optional R03 reasoning/context-engineering videos. Lab: 04. Assessment: checkpoint B.
