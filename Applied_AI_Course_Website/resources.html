Setup and compute plan

CPU baseline

Use Python 3.10 or newer. From the extracted llm_course directory, run:

powershell
python -m unittest discover -s tests -v
python -m coursekit.demo
python -m coursekit.server

The baseline uses only the Python standard library. Open http://127.0.0.1:8000/health in a browser. Query it from a second terminal:

powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/ask -ContentType 'application/json' -Body '{"question":"What is the default request timeout?","version":"2"}'

Use curl or Python urllib.request on Linux. The server binds to loopback and is an instructional service; shared deployment requires authentication, rate limiting, a process manager, and infrastructure configuration you will implement in the capstone. No executable shell tool is exposed.

Colab

Upload a notebook and upload the ZIP. Extract the ZIP into /content using the Colab file browser or:

python
from zipfile import ZipFile
with ZipFile('/content/Applied_Generative_AI_Course.zip') as z:
    z.extractall('/content')

Notebooks locate llm_course in the current directory or its parent. For the GPU notebooks select Runtime → Change runtime type → GPU when available. Record nvidia-smi, Python, PyTorch, CUDA runtime and package versions, free VRAM, and random seed. Save checkpoints and reports before the session ends. If a GPU is unavailable, do the CPU experiments first and reschedule the measured GPU task. A CPU skip does not count as having completed a CUDA benchmark.

Optional model dependencies

Each model notebook includes its own installation cell. These are API-family constraints, not a verified binary lockfile:

text
torch>=2.4,<3
transformers>=4.45,<5
sentence-transformers>=3,<6
peft>=0.13,<1
qdrant-client>=1.12,<2

The examples deliberately use the Transformers 4.x interface rather than assuming that a future major version has identical behavior. After a successful run, save pip freeze with the run artifacts. If a dependency resolver reports a conflict, use a new runtime, install only that notebook's dependencies, restart, and rerun from the top. Record the resolved versions; do not silently replace the evaluation model halfway through an experiment.

Default demonstration models: sentence-transformers/all-MiniLM-L6-v2 for English retrieval and Qwen/Qwen2.5-0.5B-Instruct for generation/SFT. Read the model cards [R22, R23]; check licenses and model revision at download time. They are small instructional choices, not claims of current best quality. MiniLM truncates long input, so chunks must respect its actual tokenizer limit. A weak small-model answer is useful failure evidence.

Optional larger GPUMore useful model or longer training, QLoRA experimentNever required for baseline completion

The local GPU can run some small experiments if your driver/PyTorch build supports it. The course does not assume bfloat16, Tensor Core acceleration, a particular quantization backend, or that a multi-billion-parameter model fits. Prefer float32 for CPU correctness and select GPU precision only after checking support. Do not install a CUDA toolkit merely to use prebuilt PyTorch; the standalone CUDA C++ exercise additionally needs nvcc.

What to save after every experiment

Save config JSON; git revision if you use git; dataset and index hashes; model/tokenizer revision; package freeze; device details; raw per-example outputs; aggregate metrics; elapsed time; and your explanation of the result. Keep model caches outside the ZIP or source repository. A run with no saved output is difficult to reproduce after a Colab reset.

  • All 42 Python code cells across the 16 version-4 notebooks parsed successfully; notebook IDs and required structure checked.
  • CPU tutorial paths 01, 02, 07, 08, 09, 11, 13, 14, 15 and 16 executed successfully. Lab 07 real-model switch remained off.
  • All 23 deterministic retrieval, metric, arithmetic, schema, controller and manifest tests passed.
  • Lab 13 started the actual local HTTP API, checked health, made 20 successful scoped requests and recorded latency. This is an extraction-service smoke test, not an LLM throughput benchmark.
  • Numerical examples were checked through executed calculations or worked solution arithmetic.
  • The archive excludes test-generated runs, Python caches and model files. Notebook outputs are empty for clean student attempts.

Not executed in the authoring environment

This environment did not have PyTorch/model dependencies or a GPU. Model loading/inference, sentence-transformer embedding, Qdrant persistence with downloaded embeddings, tiny-LM training, LoRA training/reload, model-directed planning and CUDA compilation/profiling were not executed here. Their notebook code was syntax-checked and written against the cited official API families. End-to-end execution and package resolution must be confirmed in the chosen Colab/runtime.

Dependency ranges are not a verified lockfile. Resolve them in a fresh runtime, save successful versions/model revisions, and complete measured tasks before marking those labs complete. CUDA toolchain/precision support and free GPU availability vary.

Interpretation limits

Fixture data are invented and tiny. The lexical answerer is an extractor, not an LLM; deterministic planners test controller behavior, not model planning. Illustrative telemetry, rank lists and bootstrap arrays are labeled. Controller completion and source-ID existence do not prove correctness or semantic support.

The local API is instructional and unauthenticated. The controller enforces schemas, arithmetic bounds, request version and step count; it is not an arbitrary-code sandbox or blocking-call cancellation mechanism. Authentication, timeouts/cancellation, workload isolation, secrets, permissions and cache controls are deployment work where applicable.
