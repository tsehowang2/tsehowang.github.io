Setup and compute plan

Read first

The website uses static HTML, CSS and JavaScript. Reading, slides, search, worked solutions, diagrams and progress tracking require no Python installation or paid service. Code runs separately on your computer or Colab.

CPU foundation route

Use Python 3.10–3.12 in a virtual environment for broad package compatibility. Install NumPy for numerical lessons. Most early notebooks and controller/evaluation exercises need only the standard library and NumPy. Colab normally includes them.

Extract the full course ZIP. Its root contains coursekit, data, notebooks and tests. From that root run python -m unittest discover -s tests -v. In Colab, upload the ZIP, unzip it into /content/llm_course, and run the bootstrap cell. The cell also searches for an extracted llm_course_v2 folder. Do not upload a lone notebook without its support files.

Model downloads and free GPUs

Week 12 introduces a small PyTorch transformer. A short CPU run checks the training path; Colab allows longer experiments when a GPU is available. Later notebooks have explicit installation/download cells. Free GPU availability varies; inspect the assigned device. Save checkpoints and reports outside a temporary runtime before disconnecting.

Your GTX 1650 Super is optional. Inspect actual free VRAM with nvidia-smi. Use CPU for numerical lessons and Colab for larger model experiments. Do not assume BF16, large batches or QLoRA kernels work on every GPU. Start with float32 CPU correctness or supported float16 GPU execution.

Reproducible model work

Package ranges in notebooks are starting constraints, not immutable lockfiles. Record resolved Python, torch, transformers and accelerator versions, model/tokenizer commits, data hashes, seeds and configurations. Save a lockfile for a working environment. Check current official documentation if installation APIs differ.

Model labs download a small Qwen model and/or a sentence embedding model. QLoRA is explained but the guided LoRA pilot does not require a four-bit kernel. Week 23 CUDA compilation requires nvcc. If unavailable, inspect the kernel and record that limitation.

Outputs

The bootstrap creates a runs directory. Use run IDs and keep actual outputs. The fictional teaching fixtures are tiny and cannot establish production quality or broad model capability.

Readings by phase

Weeks 1–5: ordinary-sentence examples and mathematical prerequisites in the notes; external readings are optional. Weeks 6–11: R04 attention and transformer diagrams, and the official Stanford CS224N materials at https://web.stanford.edu/class/cs224n/. Weeks 12–16: R04 training/architecture, R09 instruction/reasoning examples, R10 controlled reasoning studies, R21 generative-model intuition. Weeks 17–21: R06 RAG, R07 embeddings, R08 vector database, R24 ANN, R25 lexical retrieval. Weeks 22–23: R16 CUDA thread hierarchy, R19 profiling, R26 memory-aware attention. Weeks 24–26: R12 LoRA, R13 QLoRA, R14 adapter configuration, R15 preferences. Weeks 27–32: R11 actions/observations, R20 tracking, R18 delivery recipe and the relevant model/runtime documentation. Readings extend the lectures; do not read research papers before the prerequisite example is clear.

About this course

Independent original self-study material. There is no Stanford or NTU affiliation or certificate. The teaching approach combines intuitive explanations, mechanisms, implementation and controlled experiments. Links to the instructors’ public materials are optional references, not copied lecture content.

Validation and limits

All 32 notebooks and companion scripts were syntax checked. Twenty-seven CPU-capable tutorial paths executed successfully with Python 3.13 and NumPy 2.5.4 where needed. Twenty-three support contract tests passed. Optional actual-model blocks were disabled for those CPU runs. The extraction API smoke test and controller fixtures were executed; these are not LLM inference benchmarks.

Actual tiny-transformer training (week 12), embedding/Qdrant execution (week 18), CUDA compilation/profiling (week 23), LoRA training (week 26) and actual model planning (week 28) were not executed in this revision environment. Optional model paths in weeks 13, 17 and 20 were not executed. Their code is syntax checked; package/device/model compatibility and model quality require your runtime. No fixture result is presented as a trained-model result. Distributed notebook outputs are empty. Verification runs and checkpoints are excluded.
