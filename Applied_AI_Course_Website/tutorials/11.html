What to do and what to submit

Tutorial: validate arithmetic/config schemas, run the deterministic lookup/calculator controller and inspect traces. Force unknown tool, wrong scope and endless loop failures.

Independent experiment: add at least ten contract cases covering extras, booleans, division by zero, bounds, malformed proposals, fabricated citations and repeated actions. Define controller terminal statuses and a real timeout plan for future blocking calls.

Expected: 700 ms fixture result, strict schema checks, unknown tools rejected, endless planner terminates with budget_exhausted. Structural citation checks do not verify the conclusion.

Debug: tool-call validity differs from tool result validity. A valid config-validator call can return valid=false without being a controller schema error.

Submit: contracts, tests, execution state diagram/description and traces. State clearly that this planner is deterministic; actual model planning follows in lab 12.

assert calculate('100+200+400')==700

for expression in ['1/0',"__import__('os')",'2**100']:
    try: calculate(expression)
    except ToolError as e: print('Rejected',expression,str(e))
def planner(state):
    if state['step']==0:
        return {'type':'tool','name':'lookup','arguments':{'query':'retry policy backoff','version':state['version']}}
    if state['step']==1:
        return {'type':'tool','name':'calculate','arguments':{'expression':'100+200+400'}}
    return {'type':'final','answer':'The fixture gives cumulative waiting time of 700 ms before attempt four.','citations':['retry-v2']}
result=run_agent('What is cumulative retry wait before attempt four?',planner,max_steps=4)
assert result['status']=='completed'
print(json.dumps(result,indent=2));(RUNS/'lab11_trace.json').write_text(json.dumps(result,indent=2))
loop=lambda state:{'type':'tool','name':'calculate','arguments':{'expression':'1+1'}}

This deterministic planner hard-codes arithmetic for one fixture. It tests the controller, not model intelligence. Add task predicates and different valid/invalid config cases. The synchronous controller does not interrupt blocking planners; deployment needs real timeout/cancellation enforcement.
