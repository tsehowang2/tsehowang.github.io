Regression and incident drill

Read the walkthrough, inspect the code, then run the notebook when you are ready.

Lecture 29Lecture 30Download notebookOpen in Colab ↗

When you run this notebook, also download and extract the full course pack for the support files and teaching data. You can read the support implementations here.

What to do and what to submit

Tutorial: run the contract suite, reject a mismatched candidate manifest and restore the previous manifest. Compute theoretical four-way speedups.

Independent experiment: rehearse actual artifact rollback on your project, not merely the starter metadata. Add one regression for a discovered error and write an incident report. Develop a capacity memo: present measured bottleneck, candidate scaling method, persistent-state/activation/communication budget and validating experiment.

Expected: incompatible candidate refused; ideal .7-scalable speedup≈2.105 and .8-scalable≈2.5, before overhead.

Debug: reverting only weights leaves index/prompt/corpus changes active. Data parallelism does not inherently shard all state.

Submit: release decision, recovery evidence, regression, incident and capacity memo. Proposed multi-GPU behavior must be identified as proposed unless actually measured.
